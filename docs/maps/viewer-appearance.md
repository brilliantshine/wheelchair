## Flow

An app page loads the shared dark palette and its own styles; its deferred background controller fetches saved metadata, loads the image and paints it behind the page. Settings' You section edits a page-local preview, then saves it to the hub; visible pages poll and fetch again on focus or return (`viewer/pages/settings.html:4-14`; `viewer/pages/app.css:12-29`; `viewer/pages/background.js:68-105`; `viewer/pages/settings.js:12,2242-2275,2315-2329`).

```text
page HTML -> shared CSS -> deferred background controller -> authenticated metadata -> image -> paint
Settings You -> local preview -> save with revision -> settings.json -> other pages refresh
```

- The app palette defines `--accent` as `#5b9dd9`, with separate ink, soft, line, text, highlight and chip values; surfaces, borders, status colors, fonts and a navigation height are also tokens. The body explicitly selects dark browser controls; spacing and radii remain literal throughout CSS (`viewer/pages/app.css:12-29,44,69-70`). No light-mode switch appears in these palette definitions. Thread cards, activity SVG, meters and popup buttons use the variables (`viewer/pages/thread.css:49-59`; `viewer/pages/views.css:233-249`; `viewer/pages/settings.css:202`; `viewer/pages/assistant-popup.css:3-16`).
- The CSS header's claim that every app color uses the variables is false: the popup human bubble hardcodes `#23303f`, and graph selection uses `rgba(91, 157, 217, .12)` (`viewer/pages/app.css:1-3`; `viewer/pages/assistant-popup.css:40`; `viewer/index.html:219`). The graph and standalone doc each define their own dark palette and blue accent (`viewer/index.html:7-10`; `viewer/doc.html:9-12`); the graph uses it for SVG nodes and edges (`viewer/index.html:111-120,157-158`). Sign-in is a separate page (`viewer/server.js:1784`). App file and doc pages load the shared app CSS (`viewer/pages/file.html:4-11`; `viewer/pages/doc.html:4-10`).
- The terminal constructs xterm without an explicit theme and changes only its cursor to the computed warning color while typing (`viewer/pages/term-view.js:73-86,165-171`). Agents activity colors include JS literals (`viewer/pages/agents.js:81`); picture export reads computed palette values with hardcoded fallbacks (`viewer/pages/picture-export.js:150-156`). Background CSS adds opaque token-colored surfaces when an image is active (`viewer/pages/background.css:1-12,20-21`).
- Background defaults are image ID/type null, opacity 35 and revision 0; normalization rejects invalid metadata (`viewer/app/settings.js:58,319`; `viewer/app/background.js:7-15`). The hub stores `settings.json` and serializes read-modify-write updates (`viewer/app/state.js:75,238-255`; `viewer/app/settings.js:420-434`). Background writes share that queue, check revision and return 409 for conflicts; image uploads are bounded to 25 MiB, validated and stored by hash (`viewer/app/background.js:63-97,124-155`).
- The editor validates and decodes the chosen file, previews via an exclusive token, and offers visibility, Save, Cancel and Remove; conflicting saves require Cancel to reload (`viewer/pages/settings.js:2282-2329,2339-2375`). Drafts are local to the page; the controller refreshes every 10 seconds while visible, on focus and pageshow, and keeps the last successfully loaded image on load failure (`viewer/pages/background.js:44-105`). It fetches after deferred script execution and then loads the image: there is no blocking pre-paint theme bootstrap or local settings cache in this controller (`viewer/pages/background.js:28-42,68-99`). It deliberately exits in iframes (`viewer/pages/background.js:5-6`). The standalone doc includes it, while the graph page has its own palette (`viewer/doc.html:4-5`; `viewer/index.html:7-10`).
- Assets are public; app pages use the remember-cookie boundary and browser writes require the matching origin (`viewer/server.js:7,1260-1264,1302-1319,1767-1780,2130`). Background routes dispatch separately (`viewer/app/routes.js:49`). Existing background node and browser suites cover behavior and rendering, and browser setup lists Firefox coverage (`viewer/test/background.test.js:1`; `viewer/test/background-editor.spec.js:1`; `viewer/test/background-rendering.spec.js:1`; `viewer/test/firefox-specs.js:1`); isolated server setup is in `viewer/test/helpers/server.js:66-74`.
