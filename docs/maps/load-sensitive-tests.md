## Flow

A clean full run starts the browser job, runs the other suites sequentially alongside it, then writes one summary and fails if any suite failed (`test-support/full-run.sh:26-33,47-58,60-73,84-107`). The node suite and machine suite invoke Node's test runner on file globs without a concurrency override (`test-support/full-run.sh:84-85`; `machine/test/run.sh:3`).

```text
clean commit -> browser workers ---------------------------> summary -> pass or fail
             -> viewer node -> machine -> other suites ----> summary
             -> TERM or HUP -> signal both process groups -> exit without summary
```

- The runner makes separate job-control process groups, TERM-signals both groups on TERM/HUP, waits for the job leaders and exits 1 (`test-support/full-run.sh:34-45`). The fixture appends `start` before installing its signal trap, and the test signals as soon as both starts appear, then immediately requires both `stopped` records after the runner closes (`test-support/test/full-run.test.js:17,25-36,50-56`). Thus a signal can arrive before a stub installs its trap; waiting for a group leader is also not an explicit wait for every descendant. These are possible races, not a demonstrated cause of the reported missing record. Normal completion writes browser's result to a temporary file, treats a missing/invalid result as failure, and writes the fixed-order commit and suite lines only at the end (`test-support/full-run.sh:52-58,91-107`).
- The picker compares commits, selects changed tests, direct imports/names and mapped targets, then applies shared-file and conservative fallbacks; it selects commands, not retries or a pass rule (`test-support/pick-tests.js:46-77,78-124`).

## Viewer node cases

- The pre-prefix holder is a spawned Node HTTP server standing in for an older viewer: it returns 401 on prefixed whoami, answers the old path with nonce HMAC and PID, and writes a request log; its parent records its token and PID for the CLI (`viewer/test/lifecycle.test.js:57-77`). The test checks open/show/service/rotation refuse, registration and URL warn, no token leaks, and stop ends the holder (`viewer/test/lifecycle.test.js:255-278`). `freePort` binds and closes before the child binds; another process can take the port in that gap (`viewer/test/helpers/server.js:15-22`; `viewer/test/lifecycle.test.js:255-258,68-73`). An unhandled listen error such as EADDRINUSE can cause exit 1; stderr is piped but not read in this helper, so the reported exit alone cannot prove that cause. A slow start has a separate 2 s timeout (`viewer/test/lifecycle.test.js:70-73`).
- Quiet test 6 ends the worker turn, posts its asking message, waits 220 ms and expects no submit (`viewer/test/app-quiet.test.js:16-18,41`). The fixture sets a 50 ms grace and 20 ms queue retry (`viewer/test/app-quiet.test.js:6-8`); the hub checks due quiet work on its retry timer and may enqueue a reminder after grace (`viewer/app/hub.js:52-55,93`; `viewer/app/quiet.js:7,12,32-48`). Delay between the turn-end and message acceptance can therefore cross the grace; actual failing ordering is not established. `until` polls every 20 ms for up to 8 s, while fixed sleeps assert absence over time (`viewer/test/app-quiet.test.js:7-8,37-41`).
- The upload integration creates real isolated machine/hub state and a Git project, modifies PATH for shims, then starts the real services (`viewer/test/app-uploads-archive.test.js:15-61`). Within a 30 s test it waits at most 3 s for a `.part`, stalls 5.2 s, requires archive to finish in under 5 s, races upload termination against 3 s, and asserts archive, cancellation and cleanup (`viewer/test/app-uploads-archive.test.js:65-109`). A slow setup or scheduling can consume these budgets; no failure trace was inspected here.
- Verifier retry forces submit failure, asserts the queued report and delivery error, then enables submit and polls 10 ms for at most 1 s; it requires exactly one delivered report, empty queue and cleared error (`viewer/test/app-hub.test.js:1327-1354`). The hub retry interval is set to 10 ms for this fixture; it still depends on the asynchronous timer and service work completing inside the deadline (`viewer/app/hub.js:52-53,93`).

## Browser and switching cases

- Browser config chooses workers, Chromium for every spec and Firefox for a named subset, with no configured timeout or retry override (`viewer/playwright.config.js:3-20`); Playwright defaults apply (30 s per test and no retries), with individual assertions/waits overriding where specified. `--workers` overrides the config; full runs choose at startup from half the CPUs capped at 8, divided by the number of live registered full runs plus one, with a floor of 2; non-full runs choose 2 (`test-support/browser-workers.js:7-12,15-34,48-60`). The registry is shared under the OS temp directory and tests liveness by PID (`test-support/browser-workers.js:15-34,54-59`).
- The phone approval case starts a per-test world, posts approval and offer, clicks Start building, waits for its request, then registers an offer request waiter and clicks the offer button (`viewer/test/app-threads.spec.js:21-34,573-587`). The reported 30 s wait at the second waiter says the matching request was not observed within the test budget; it does not by itself identify why. The deck spec mocks agents, opens a 390×844 phone viewport, scrolls a 40-round popover and page, waits up to 8 s for a subsequent agents response and two animation frames, then checks viewport geometry and retained scroll (`viewer/test/app-agents-decks.spec.js:7-21,240-277`). Poll timing, rendering and scroll geometry all matter; the failing assertion is not supplied.
- The switch HTTP fixture uses temporary HOME, service state, fake tmux/CLI and a real Git worktree (`machine/test/switch-http.test.js:18-40,63-75,89-102`). It runs Claude worker, Codex worker and Codex reviewer sequentially; after each accepted switch it polls up to 300 times at 10 ms for active or failed, checks transcript copy, resume command, no new worktree or first message, then switches back (`machine/test/switch-http.test.js:107,136-159`). This is an iteration limit rather than a strict 3 s deadline: scheduling can extend elapsed time. The report names the test but gives no failing assertion.

## Isolation and live state

- Shared viewer startup allocates temporary cache and state roots, probes and releases a port, spawns a child with explicit `--port`, `--cache-root` and `--state-dir`, waits 5 s for its URL, retries up to five times only for recognized port clashes and only when the port was not supplied, and escalates shutdown after 1.5 s (`viewer/test/helpers/server.js:15-27,41-58,69-106`). The app helper starts a fake machine and isolated hub; that fake machine also releases a probed port before binding (`viewer/test/helpers/app.js:9-30`; `viewer/test/helpers/app-machine.js:24-25`). Deck fixtures seed isolated state and two fake machines (`viewer/test/helpers/app-views-setup.js:68-82`).
- Installer cases run with temporary HOME, harness homes and command shims (`install/test/run.sh:1-2,97-98,182-210`). To detect leaks into the real home, the suite hashes `~/.wheelchair` before and after: sorted paths, file content hashes, directory markers and symlink targets; it excludes paths starting `accounts/` containing `/tmp` (`install/test/run.sh:25-49,229-234,700-705`). It does not compare timestamps or permissions. The assertion cannot attribute a change to the suite: other processes can modify the same tree between snapshots. Nondefault session accounts are under `~/.wheelchair/accounts`, passed to the CLI as `CLAUDE_CONFIG_DIR` or `CODEX_HOME`; the switch fixture explicitly copies session transcripts under such an account (`machine/service.js:110-116,837-842`; `connectors/claude/machine.js:5-6`; `connectors/codex/machine.js:5-6`; `machine/test/switch-http.test.js:100-102,144-146`). Hub and machine service default state instead lives under `~/.local/state/wheelchair` (`viewer/app/state.js:9`; `machine/service.js:48,283,290`).
- The named tests and helpers use separate local timeout values and targeted environment overrides; the inspected runner/config/helper paths expose no global timeout scaling knob (`viewer/test/app-quiet.test.js:6-8`; `viewer/test/helpers/server.js:41-45`; `viewer/playwright.config.js:12-20`; `test-support/full-run.sh:31-33`). This is not a repository-wide proof of absence.
