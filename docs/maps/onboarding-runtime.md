# Map: harness installation runtime

Checked against: `c9c6451819f00556a5d875d42f6a8e462f3eb22a` (origin/main; covered files match worktree HEAD).
Files covered: `machine/lib/harness-install.js`, `machine/lib/harness-recipes.js`, `machine/service.js`, `machine/API.md`, `viewer/app/routes.js`, `viewer/pages/settings.js`, `machine/test/harness-install.test.js`, `viewer/test/app-harnesses.test.js`, `viewer/test/app-harnesses.spec.js`, `viewer/playwright.config.js`, `viewer/package.json`, `machine/test/run.sh`.

```text
Settings selects machine -> POST install -> hub forwards -> machine starts detached job
  -> recipe -> setup and CLI check -> result file
  -> Settings polls GET -> running tail or failure tail or refreshed status
```

1. Settings loads harnesses for the selected machine and GETs each enabled provider's install state; Install or Try again POSTs to that machine. Running jobs poll every 2 seconds; fetches time out after 8 seconds where supported, and network errors or 5xx keep retrying. Switching machines, leaving the section, or switching off a provider stops its poll, not the job (`viewer/pages/settings.js:1605-1607,1619-1662,1665-1700,1716-1728,1742-1755,1810-1816`).
2. The hub validates provider and machine, forwards GET/POST and preserves the machine status/body; failures reaching it become 502. The machine authorizes the hub, validates provider and recipe, returns 202 on start, 409 if running, and GETs state (`viewer/app/routes.js:95-102`; `machine/service.js:2066-2073`; `machine/API.md:31`). Neither route accepts DELETE.
3. Start truncates the log, removes the previous result, spawns a detached Node job with log-backed stdout/stderr, writes its PID and start time, then unreferences it (`machine/lib/harness-install.js:23-34`). The job waits for its PID file, runs a PATH Node check for npm recipes, the shell recipe, Claude/GPT cleanup and sensitivity setup, then CLI resolution and version validation; it writes a result and removes the PID file (`machine/lib/harness-install.js:36-79`). Script recipes download using curl then bash; GPT and OpenRouter use npm with `$HOME/.local` prefix (`machine/lib/harness-recipes.js:3-20`). The detached job is the process-group leader; commands run synchronously inside it. There is no install deadline or cancellation in this runner (`machine/lib/harness-install.js:14-80`).
4. State reads `~/.wheelchair/installs/<provider>.pid`, `.result` and `.log`: live PID wins, otherwise result wins, otherwise a dead PID yields failed with a stopped message; the tail is the last 40 lines. These files and the detached job survive a machine-service restart; PID liveness is checked with signal 0, with no process identity check (`machine/lib/harness-install.js:11-21,23-32,76-77`; `machine/test/harness-install.test.js:26-39`). A live PID takes precedence even if a result exists. Killing the job before it writes a result currently gives the generic stopped message, not a cancellation or timeout reason.
5. Running and failed rows show the raw tail; failed rows offer Try again when a recipe is available. Success refreshes status and may retry version lookup; a poll's 409 POST response resumes GET (`viewer/pages/settings.js:1689-1713,1742-1767`). No structured failure explanation is currently returned or rendered (`machine/lib/harness-install.js:15-21,75-77`; `viewer/pages/settings.js:1692-1698,1756-1764`).
6. Machine tests use temporary homes, fake recipes and a real isolated service; they cover restart, duplicate starts, failures, cleanup and Node checks (`machine/test/harness-install.test.js:13-60`). Hub forwarding tests exercise POST/GET status and body plus outage (`viewer/test/app-harnesses.test.js:259-269`). Browser tests stub harness requests against an isolated server, covering running, success, retry, outage and machine selection at phone and desktop sizes (`viewer/test/app-harnesses.spec.js:3-19,50-64,100-119,178-253,399-410`). Run `node --test machine/test/harness-install.test.js`, `node --test viewer/test/app-harnesses.test.js`, and `npm --prefix viewer run test:browser -- app-harnesses.spec.js`; full suites are `bash machine/test/run.sh` and `npm --prefix viewer run test:browser` (both Chromium and Firefox: `machine/test/run.sh:1-3`; `viewer/package.json:8`; `viewer/playwright.config.js:11-18`).
