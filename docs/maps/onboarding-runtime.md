# Map: installation and onboarding runtime

Checked against: `b53f4f24313cc6e46ee58e24b18e02bcc9c5283d` (origin/main and worktree HEAD).
Files covered: `install.sh`, `install/guard.sh`, `install/unseen.py`, `install/test/run.sh`, `sensitivity/set.sh`, `machine/service.js`, `machine/adapters/`, `machine/lib/sudo.js`, `codex/preflight.sh`, `viewer/app/{providers,balancer,settings,state,sessions,ready,routes,diagram-sensitivity}.js`, `viewer/pages/settings.js`, `README.md`, `sudo-helper/{install.sh,helper.py}`.

```text
install prerequisites and one CLI -> install wheelchair -> start services and open token URL
  -> Settings accounts and models -> sign in on a machine -> choose provider and account
  -> check machine and CLI -> start CLI in tmux -> deliver role instructions
```

1. The README's first-time path asks for `./install.sh --serve`, Tailscale mappings, a token URL, then Settings account sign-ins and preferences (`README.md:18-40`). Dependencies include Node, tmux, git, authenticated gh, Tailscale and at least one of the five CLIs (`README.md:257-266`). The installer guards the canonical clone, detects Claude, Codex and `agy` on PATH, and Kimi and Pi on PATH or their respective home fallbacks; if all are absent it exits before any installation (`install.sh:6-9,38-56`; `install/guard.sh:12-31`). Thus a Settings button cannot currently be reached on a fresh CLI-free install through this path. The README's first-time Settings text lists only Claude and GPT, while Settings offers all five reviewer families (`README.md:31-37`; `viewer/pages/settings.js:601-602`).
2. For detected Claude/Codex, the installer removes recognized retired skill/prompt wrappers and passes only present harnesses to `unseen.py`, which removes matching old hooks and Claude permissions while preserving unrelated entries (`install.sh:86-114,136-139`; `install/unseen.py:23-91`). It initializes shared model pins for any detected CLI, installs npm dependencies and Chromium/Firefox, runs the sensitivity writer, and creates machine secret and config only if absent (`install.sh:116-145,158-180`). It does not install the harness CLIs. The sensitivity writer targets only detected Claude `CLAUDE.md` and Codex `AGENTS.md`, preserves other text, resolves the shared dial and refuses inconsistent or malformed blocks (`sensitivity/set.sh:10-26,125-130,173-187,203-234`). Installer fixtures use temporary state and cover detection, fallbacks and service setup (`install/test/run.sh:1-40,276-303`).
3. Serving needs Tailscale and either Linux systemd or macOS launchctl; Linux writes and starts user units and tries linger, while macOS writes GUI-domain launch agents and requires a logged-in user (`install.sh:217-242,321-361,364-435`). The installed service PATH is captured from the installer environment plus the executable directories it found; it is not dynamically rebuilt when a CLI is added later (`install.sh:373-390,408-426`). macOS looks inside the Tailscale app as a fallback and runs offered mappings without `sudo`; Linux uses `sudo` (`install.sh:24-33,281-303`). The separately installed root sudo helper is unavailable on macOS (`install.sh:80-83`; `sudo-helper/install.sh:4-6`). The helper checks a user's sudo authorization and executes an approved command as root with a minimal root environment, rather than as the logged-in user (`sudo-helper/helper.py:113,175-196`; `machine/lib/sudo.js:35-52`).
4. Settings loads hub preferences from `settings.json` and saves changes atomically; model cells are handled separately through `codex/model.sh` (`viewer/app/state.js:70,233-248`; `viewer/app/settings.js:261-264,299-307`; `viewer/app/routes.js:258-268`). The diagram dial is different: the hub fans out reads and writes to each known machine, collecting per-machine failures; the machine's files are the source of truth (`viewer/app/diagram-sensitivity.js:3-4,17-48`; `viewer/app/routes.js:201-206`). Account sign-in targets a selected machine through hub routes and its `/v1/logins`; the machine seeds non-default account homes, starts the adapter's login command in tmux and exposes state/pane/code operations (`viewer/app/routes.js:412-421`; `machine/service.js:1519-1541,2007-2010`; `viewer/pages/settings.js:1092,1119-1147`).
5. Providers map Claude to `claude`, GPT to `codex`, Gemini to Antigravity `agy`, Kimi Code to `kimi`, and OpenRouter to `pi` (`viewer/app/providers.js:3`). Login commands are `claude auth login`, `codex login --device-auth`, `agy`, `kimi login --region global`, and `pi auth login openrouter --api-key`; their login checks and prompts differ (`machine/adapters/claude.js:56-62,104`; `machine/adapters/codex.js:103,142`; `machine/adapters/agy.js:89-100`; `machine/adapters/kimi.js:52-59,162-164`; `machine/adapters/pi.js:16-22,49-51`). Kimi resolves its home fallback, whereas Pi's runtime resolver uses PATH even though install detection also checks `~/.local/bin/pi` (`machine/adapters/kimi.js:8-17`; `machine/adapters/pi.js:16`; `install.sh:49-50,379-389`). Adding a CLI after service setup therefore also needs attention to the running service and tmux PATH (`machine/service.js:698-709`; `install.sh:376-389`).
6. Hub placement filters by signed-in accounts, model slots, role order and review-family policy; a selected single review family falls back when unavailable, and no eligible account produces a wait (`viewer/app/balancer.js:19-21,27-50,56-62,79-95`). Defaults create accounts for every provider, not evidence that each is installed (`viewer/app/settings.js:38`). Ready checks the thread machine's reachability and version and **only the thread's own CLI**, including a non-paused signed-in account; it does not establish that every reviewer family is installed (`viewer/app/ready.js:29-72`). For GPT dispatch, the hub calls machine preflight for the selected account and retries placement on failure; the lock-protected script refreshes tokens as needed (`viewer/app/sessions.js:290-312`; `machine/service.js:1998`; `codex/preflight.sh:2-30,47-65`).
7. The machine selects the adapter, prepares its account, writes role instructions and creates a worktree, then builds the CLI command and per-session settings (`machine/service.js:684-687,768-790,796-815`). Claude uses per-session hooks; Codex supplies a notify option; Antigravity prepares its home hook; Pi writes a per-session extension; Kimi uses its own transcript handling (`machine/adapters/claude.js:63-74`; `machine/adapters/codex.js:124-126`; `machine/adapters/agy.js:10-21`; `machine/adapters/pi.js:53-59`; `machine/adapters/kimi.js:184`). Machine status reports installed/login state, with a Kimi version check and explicit missing-Pi/Kimi start failures (`machine/service.js:1589-1595,1601-1648,769-772,1520-1524`).
