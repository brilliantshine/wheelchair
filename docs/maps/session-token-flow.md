```text
start request -> select model and compose instructions -> machine launches CLI
  -> role reads files -> work and cards -> result queued -> starter reads and stops
```

The hub resolves model and role layers, sends those and the brief to the machine; the machine constructs the role-file pointer, writes provider settings, and launches tmux in the worktree with session environment variables (`viewer/app/sessions.js:268-275,305-330`; `machine/service.js:127-132,523-538`). `role_prompt`, when supplied, replaces both pointer and layers (`machine/service.js:127-132`). The normal layers contain a precedence sentence; optional project-specific or global template and switches, sub-lead escalation, lead writing style, and lead/sub-lead scout choices (`viewer/app/settings.js:121-123,142-164`).

Provider session commands, with optional arguments in brackets (the machine shell-quotes each argument; environment includes lane, token, state directory, machine origin and account-specific login environment):

- Claude: `claude --session-id <uuid> --settings <state>/settings/<name>.json --permission-mode <bypassPermissions|auto> [--model <model>] [--effort <effort>] --append-system-prompt <role prompt>`. Settings contain `cleanupPeriodDays: 30`, `promptSuggestionEnabled: false`, optional `skipDangerousModePermissionPrompt: true`, synchronous Stop/Notification/StopFailure hooks, asynchronous wildcard PreToolUse/PostToolUse/PostToolUseFailure hooks, and a statusLine command. The brief is the first typed message (`machine/adapters/claude.js:56-64`; `machine/service.js:529-534`).
- GPT: `codex <access> -c 'notify=[<hook>,"codex",<name>]' -c 'projects={<worktree>={trust_level="trusted"}}' [-m <model>] [-c model_reasoning_effort=<effort>]`. Reviewer access is `-s read-only -a never`; other sessions use `--dangerously-bypass-approvals-and-sandbox` if unrestricted, else `-s workspace-write -a never -c sandbox_workspace_write.network_access=true`. The first typed message is `[wc:role]` plus role prompt and brief (`machine/adapters/codex.js:50-51`).
- Gemini: `agy --settings <state>/settings/<name>.json <access> [--model <model>] [--effort <effort>]`, with `--dangerously-skip-permissions` for bypass or `--mode auto`; settings are `{ "trustedWorkspaces": [<worktree>] }`. Its first typed message contains `[wc:role]`, role prompt and brief; prepare also adds a wheelchair Stop hook to `~/.gemini/config/hooks.json` (`machine/adapters/agy.js:9-34`).

The session launch argv/settings above do not explicitly disable MCP servers, skills, or instruction files. Actual startup contents depend on CLI and account/project configuration; this code does not enumerate them. Custom Claude and Codex account directories are seeded with links to the usual `CLAUDE.md` or `AGENTS.md` if present, and Codex gets a minimal config only if absent; Gemini's seed is empty (`machine/service.js:501-509`; `machine/adapters/common.js:9-14`; `machine/adapters/claude.js:85`; `machine/adapters/codex.js:57`; `machine/adapters/agy.js:66`). Do not confuse the separate Claude usage probe and aside, or Codex aside, with ordinary sessions: those have explicit MCP restrictions (`machine/adapters/claude.js:47-48`; `machine/adapters/codex.js:28`).

The role pointer asks for the role file, not its contents (`machine/service.js:127-132`). Lead and sub-lead say read cards first; mapper and worker say read it for commands (`protocol/app/lead.md:3-8`; `protocol/app/sub-lead.md:3-8`; `protocol/app/mapper.md:3-6`; `protocol/app/worker.md:3-6`). Reviewer and verifier instead forbid card commands and report in their final message; neither opening directs a cards read (`protocol/app/reviewer.md:3-10`; `protocol/app/verifier.md:3-17`). This contradicts the router's description of cards as read by every role (`protocol/app/AGENTS.md:16-17`). Aside is a separate headless role whose copied lead instructions do not apply and which posts no cards (`protocol/app/aside.md:3-13`).

The lead uses the visible card kinds, title, resolve, retract and messages; sub-lead uses progress, message and result; mapper and worker use message and result, plus commands and markers. Reviewer/verifier need the final-report convention rather than card posting. The cards table and role instructions define these uses, not evidence that every section is read in a particular run (`protocol/app/cards.md:33-53,357-386,388-403,420-452`; `protocol/app/sub-lead.md:3-7`; `protocol/app/mapper.md:12-15`; `protocol/app/worker.md:11-14`). The whole cards file is 452 lines, 4,472 words and 24,421 bytes in this checkout (`protocol/app/cards.md:1-452`).

`wc.js` prints the entire raw successful response plus newline. List is `{sessions, review_families}` and `publicSession` excludes only token, brief, pending initial/start and unanswered start; it retains other fields such as command, queues and steps, so output grows with records and their contents. Start prints `{session, note?}` (or duplicate), also a waiting line on stdout and note on stderr when applicable; stop prints `{ok:true}` (12 bytes including newline). Errors go to stderr; session requests retry 503/network errors up to 90 seconds (`viewer/app/wc.js:101-111,115-145`; `viewer/app/sessions.js:144-146,587-605,627,657-672`). A live list during this mapping returned 10,694 bytes for two records (9,423 and 1,229 bytes of compact JSON respectively); this is a snapshot, not a bound. `card.js` prints nothing on success; errors appear on stderr (`viewer/app/card.js:245-270`).

The sub-lead reruns validation and reads the worker report. Added plus removed lines from `git diff --shortstat` determine review: under 200 scout, 200–800 bigger scout, over 800 or `tricky` the sub-lead; absent a band scout it goes up, and absent bigger scout it reads itself. It sends the scout diff, brief, Spec and report and asks for deviations, file-state checks and undictated choices (`protocol/app/sub-lead.md:142-167`).

A worker, mapper or sub-lead posts a result; the hub saves the full card but queues only `[wc:from <name>] result: <summary>` to `started_by`, so report and commit fields are not in that message unless the summary includes them (`viewer/app/cards.js:119-136,143-156`). Reviewer/verifier final assistant text becomes an automatically created result and the full text is queued (`viewer/app/sessions.js:370-393`). The queue waits for a live, ready, idle, unheld starter and submits through the machine (`viewer/app/sessions.js:411-432,435-457`). The lead stops the mapper and reads MAP.md before planning, stops reviewers on results, and stops the sub-lead when its build result arrives (`protocol/app/lead.md:65-70,153-158,231-236,305-311`). The sub-lead checks worker report/diff before merge and stop, and stops verifier on result (`protocol/app/sub-lead.md:142-170,225-227`).
