# Map: local project runtime

Checked against: `4cfa20cd5aafa0418afabb829c9a4c73430a435f` (origin/main and worktree HEAD).
Files covered: `machine/adapters/`, `machine/service.js`, `machine/lib/aside-turns.js`, `viewer/app/state.js`, `viewer/app/settings.js`, `viewer/app/sessions.js`, `viewer/app/routes.js`, `viewer/app/threads.js`, `viewer/pages/thread.js`, `install.sh`, `protocol/app/verifier.md`, `protocol/app/cards-lead.md`.

```text
machine and project choice -> hub settings and start payload -> worktree -> tmux CLI
  -> local tools and application -> image file -> lead image card -> thread
  -> verification -> push and PR
```

1. A new thread validates its project on the chosen machine (`viewer/app/threads.js:43-53`). The hub records project paths as strings in `projects.json` (`viewer/app/state.js:171-173,196-203`); Settings stores saved directories by machine and project-scoped behavior templates (`viewer/app/routes.js:133-138,170-178,340-348`; `viewer/app/settings.js:37,131`). The start body carries project path, account, role, permissions and prompt layers but no MCP setting (`viewer/app/sessions.js:304-330`). These are potential extension points, not a current per-project MCP registry.
2. The machine seeds a non-default account directory and supplies it through `CLAUDE_CONFIG_DIR` or `CODEX_HOME`; default accounts use the service environment and usual homes (`machine/service.js:580-588,611-616`; `machine/adapters/claude.js:5-6`; `machine/adapters/codex.js:5-6`). Seeding links the usual instruction file and creates a minimal Codex config only if absent; it does not copy the usual account's MCP configuration (`machine/adapters/common.js:9-17`). Antigravity uses the ordinary home and writes a wheelchair hook in `~/.gemini/config/hooks.json` (`machine/adapters/agy.js:9-29`).
3. **MCP update checked at `207c02f5e0b56cfbcc96046cca10a8df92002a9c`:** the machine now reads `.mcp.json` from the session worktree and supplies it to adapters (`machine/service.js:612-614`). Claude enables accepted project servers for tool roles, Codex creates command-line overrides, and Antigravity warns that it does not support them (`machine/adapters/claude.js:69-74`; `machine/adapters/codex.js:63-102`; `machine/adapters/agy.js:30-32`). See [project-tools.md](project-tools.md) for current validation, role and environment details. This recheck covers MCP only; the other items retain the earlier checked-against commit.
4. The machine starts tmux in the worktree with session token, state, origin and account variables, trying a Linux user systemd scope and falling back to tmux; macOS skips the scope (`machine/service.js:605-624`). The Linux unit explicitly sets PATH but does not set DISPLAY or WAYLAND_DISPLAY; macOS bootstraps launch agents in the logged-in GUI domain with HOME and PATH (`install.sh:312-352,367-405`). Neither start path explicitly forwards a display or guarantees GUI authorization; actual inherited systemd/launchd and existing tmux-server environments determine reachability, so a running desktop cannot be assumed accessible. Installer display checks at `install.sh:174-184` concern installer interaction, not session display forwarding.
5. A verifier checks a detached worktree and runs applicable validation commands (`machine/service.js:488-492,533-537`; `protocol/app/verifier.md:33-50`). A lead can post an existing absolute PNG/JPEG/GIF/WebP up to 25 MB; the machine copies it to thread uploads, and the thread renders it (`protocol/app/cards-lead.md:178-189`; `machine/service.js:328-345`; `viewer/pages/thread.js:846-849`). This transports an image; it is not a screenshot capture mechanism. Installer installs Playwright Chromium and Firefox unless dependencies are skipped (`install.sh:115-125`); that supplies browsers, not evidence of desktop capture.
6. New worktrees fetch origin and branch from its default branch under the machine state directory; workers branch from the thread branch and verifiers detach at it (`machine/service.js:471-492,529-541`; `viewer/app/sessions.js:625-630`). Normal finishing pushes and opens a PR (`protocol/app/lead.md:312-325`; `machine/service.js:1040-1063`). The agent git route operates in the session's recorded worktree, with no checkout/apply operation for the user's checkout (`machine/service.js:1040-1063`). Handoff has a guarded fast-forward of the recorded thread worktree (`machine/service.js:1274-1279,1348-1355`), not the user's checkout. Installer initializes a hostname entry with host, port and secret file only when `machines.json` is absent; the hub reads named entries and resolves `hub` to its local service (`install.sh:149-167`; `viewer/app/state.js:146-162`). The new-thread API lists those machines and machine-specific saved directories (`viewer/app/API.md:45`).

## What I did not look at

CLI vendor source or live MCP discovery, real GUI/display permissions or tmux environment, third-party screenshot tools, all checkout-related UI and handoff cases, real machine registration procedure beyond the installer and registry, or credentials and deployment configuration.
