```text
model settings -> provider and account -> machine session -> Pi log and hook
  -> transcript and report -> agent tree
  -> account spend totals -> usage screen
selected lead reply -> aside fork -> headless turns -> resume -> aside history
```

- Aside creation checks the selected assistant item, live lead, provider capability, parent ID and model; it stores the parent and queues a turn (`viewer/app/asides.js:34-47`). Claim persists a turn before dispatch and uses fork for the first turn, resume thereafter; a successful result saves its conversation ID (`viewer/app/asides.js:90-113,134-139`). OpenRouter is rejected, and the parent-ID mapping has no Pi entry (`viewer/app/providers.js:3`; `viewer/app/asides.js:40-42`). Machine validation permits only Claude/GPT and excludes slash in model IDs; its runner chooses only their adapters and parses their distinct outputs (`machine/lib/aside-turns.js:58-71,94-130`). Claude uses `--resume` plus `--fork-session`; Codex uses `exec fork` or `exec resume` (`machine/adapters/claude.js:55`; `machine/adapters/codex.js:102`).
- Installed Pi 1.5.2's help describes `--fork <path|id>`, `--session <path|id>`, `--session-id <id>`, `--print`, JSON mode and `--thinking` levels off/minimal/low/medium/high/xhigh/max (`/home/collin/.local/lib/node_modules/@earendil-works/pi-coding-agent/dist/cli/args.js:299-305,318`). This is local CLI evidence, not a test of fork output, identity, permissions or concurrent access.
- Settings and session starts gate effort by provider (`viewer/app/providers.js:3`; `viewer/app/routes.js:263-266`; `viewer/app/sessions.js:100-109,203-211,349-350,374`). The pin script rejects OpenRouter effort on read and write (`codex/model.sh:97-106,440-449`); machine startup explicitly clears Pi effort (`machine/service.js:779-780`), and Pi argv omits it (`machine/adapters/pi.js:53-59`). Claude and Antigravity pass `--effort`, Codex passes `model_reasoning_effort` (`machine/adapters/claude.js:74`; `machine/adapters/agy.js:67`; `machine/adapters/codex.js:128`). Existing app values are low through max, with GPT capped at xhigh (`viewer/app/sessions.js:203-211,667-672`).
- Kimi's startup/version check caches an asynchronous `--version` by executable and mtime, rejects failed/old versions, and blocks starts; Pi only checks installation (`machine/service.js:768-772,1601-1643`). Status includes Kimi's problem and marks its accounts signed out (`machine/service.js:1588-1599`); the usage hub collects the Kimi CLI problem and Settings renders account machine problem text (`viewer/app/usage.js:60-72,126`; `viewer/pages/settings.js:1232`). Pi readiness and login match screen text and its event parser expects specific hook fields (`machine/adapters/pi.js:22-23,62-84`).
- Each machine session gets a UUID and logs its account, thread and session ID (`machine/service.js:801-804,869`). Pi searches its account's session tree for a filename ending in that ID (`machine/adapters/pi.js:70-72`); the hub learns IDs through turn events or reconciliation (`viewer/app/sessions.js:611,817`). Account spend walks all JSONL files, accepts OpenRouter assistant cost records, and sums inclusive local-day windows; unreadable files are skipped (`machine/adapters/pi.js:24-46`). `/v1/spend` enumerates accounts and returns totals (`machine/service.js:1969-1979`); the hub sums all machines and flags failed requests incomplete (`viewer/app/usage.js:80-92,126`); Settings formats the result (`viewer/pages/settings.js:1038-1041,1391-1395`). This account-wide aggregate does not carry per-session attribution.
- The Agents API builds nodes from stored sessions, groups by starter and returns a thread tree; its page renders tree boxes and selected details (`viewer/app/agents.js:62-93,125-142`; `viewer/app/routes.js:101`; `viewer/pages/agents.js:151-195,246`). The returned structure currently contains no computed spend (`viewer/app/agents.js:77,125-127`). Older leads are excluded from visible nodes even though they remain in the thread's sessions (`viewer/app/agents.js:64-68`), a distinction for a thread total.
- Pi's extension event is translated to a turn event with an entry ID; the machine attempts to bind/copy its source before forwarding, but logs copy errors and continues (`machine/adapters/pi.js:74-86`; `machine/service.js:1403-1407`). Transcript reads copy complete lines and return an empty result when there is no source (`machine/service.js:1252-1255,1261-1275,1318-1321,1331-1341`). The hub catches read failures and returns a cached copy only for chat, otherwise tries a local path or returns empty (`viewer/app/chat.js:301-334`). A reviewer/verifier report uses inline text except for Pi, otherwise selects transcript text; no text returns without a result (`viewer/app/sessions.js:428-435`; `viewer/app/chat.js:268-271,343-350`). The event advances the turn watermark before report reading, ends the turn, then saves delivery IDs and state (`viewer/app/sessions.js:555-569,607-615,640-648`): a temporary read failure can therefore permanently lose the report on replay. Existing tests cover cached-chat versus report fallback and Pi report matching (`viewer/test/app-chat.test.js:362-375`; `viewer/test/app-openrouter-hub.test.js:1`; `machine/test/pi-turns.test.js:1`).

Not checked: live Pi fork/resume, JSON output or tool restrictions; model-specific thinking support and pricing semantics; performance on large session trees; every test case or all other providers' recovery paths.
