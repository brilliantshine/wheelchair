```text
chat poll -> discover slug -> list documents -> sidebar and phone panel
                                         -> document or picture page
lead file or image -> machine copies to uploads -> card -> hub streams file
archive -> machine deletes uploads -> hub marks thread archived
```

The chat response includes documents, cards and asides (`viewer/app/chat.js:335-341,368-373`). The shared files renderer lists existing documents, deduplicated diagram cards and aside graphs, then sent file and image cards; it fills the desktop and phone panels, and the poll signature includes their inputs (`viewer/pages/thread.js:381-465,1337`; `viewer/pages/thread.html:26-27,58-60`). Sent rows skip retracted and pre-import cards and are sorted newest first; archived rows suppress links (`viewer/pages/thread.js:405-445`). The file chat card also suppresses download on archive (`viewer/pages/thread.js:1139`).

Live document listing and reading check a fixed filename list, slug, regular final component, 2 MiB limit and realpath containment on the hub filesystem; archived listing runs local `git cat-file` and caches even a failed empty result by thread and branch (`viewer/app/documents.js:9-47`). The doc route reads live bytes or local Git `show`, sends JSON for rendering or Markdown attachment headers for download (`viewer/app/routes.js:572-582`; `viewer/app/threads.js:251-265`). The doc page fetches chat then the doc route and uses shared `renderMarkdown`; its link resolver permits the three plan files and external HTTP(S) (`viewer/pages/doc.js:15-16,25-66`).

Diagram source selection uses live worktree paths on the hub or archived thread routes; forms are DOM elements, HTML is a sandboxed iframe, and graphs use the graph viewer (`viewer/pages/diagram.js:12-24,28-80`; `viewer/pages/picture.js:31-52`). The graph viewer builds an SVG with pan/zoom and CSS-dependent graphics (`viewer/index.html:1888-1906,2040-2107`); graph reads validate and register local paths and return child and rollup data (`viewer/server.js:1488-1507`). Live forms and HTML are local reads with registered-plan and realpath checks; forms are limited to 2 MiB, HTML receives restrictive headers (`viewer/server.js:1673-1696`; `viewer/app/routes.js:18`). Archived graph and HTML reads use local Git and a 2 MiB buffer (`viewer/app/threads.js:270-290`). Aside pictures instead use their stored graph path directly, including on archived threads (`viewer/pages/picture.js:44-52`).

Slug discovery runs Git against the recorded worktree, comparing added files with the merge base and rejecting pre-existing plan directories; it skips an archived worktree that is gone (`viewer/app/views.js:66-104`). Thread-list polling calls discovery inside each `withThread`, and chat holds `withChatThread` while discovery and document listing run (`viewer/app/routes.js:441-451`; `viewer/app/hub.js:120-134,280-294`; `viewer/app/chat.js:335-341,368-371`). `withThread` chains operations per id, so re-entering it while holding it waits on itself; a machine call inside these sections holds the lock (`viewer/app/hub.js:120-130`). The existing handoff refresh illustrates a machine request outside the lock followed by locked comparison of snapshot fields (`viewer/app/hub.js:267-278`).

The hub streams user uploads and file GETs through the thread's machine; the machine authenticates the hub with a separate secret and validates numbered filenames (`viewer/app/routes.js:106-120,551-560`; `viewer/app/machine-client.js:139-149`; `machine/service.js:523-540,1968-1981`). Lead file and image cards copy into the same numbered upload directory as user attachments under a per-thread lock; file copies reject final symlinks, oversized files and most state-directory sources (`machine/service.js:300-305,319-328,353-396,2017-2037`). Non-images are served as attachments with `nosniff`; images are inline (`machine/service.js:1973-1981`). On completed archive the machine removes the whole uploads directory; the hub keeps the thread open if cleanup fails (`machine/service.js:1209-1217`; `viewer/app/threads.js:217-247`). Preserving only sent files therefore needs to distinguish them from attachments and account for the current archive retry contract.

The viewer package declares only font runtime dependencies and Playwright as a development dependency, and `viewer/vendor` contains xterm (`viewer/package.json:5-16`; `viewer/vendor/xterm/`). No ZIP or HTML-to-image export implementation was found in those files or viewer sources; the existing SVG renderer is not itself a download implementation (`viewer/index.html:1888-1906`).

Not checked: browser-specific image serialization and font embedding, every vendored xterm internal, handoff/import file preservation, other machines' deployed versions, or lifecycle cleanup beyond archive.
