# Map: thread files and document delivery

Checked against: `dbdc97c540f8c9226a3d0762bdd6fe9b548b9ecf` (origin/main); line numbers below refer to worktree `a5f9d5f61e2f23dd13ed996bb41b1b6c60ab9202`. The intervening changes add a separate checkout panel and route; the file and document flows described here are unchanged (`git diff a5f9d5f..dbdc97c -- viewer/pages/thread.js viewer/app/routes.js machine/service.js viewer/app/machine-client.js`).
Files covered: `viewer/pages/thread.html`, `viewer/pages/thread.js`, `viewer/pages/thread.css`, `viewer/pages/doc.js`, `viewer/doc.js`, `viewer/server.js`, `viewer/app/routes.js`, `viewer/app/threads.js`, `viewer/app/hub.js`, `viewer/app/sessions.js`, `viewer/app/machine-client.js`, `viewer/app/card.js`, `viewer/app/cards.js`, `machine/service.js`, `protocol/app/cards.md`, `protocol/app/cards-lead.md`.

```text
thread poll -> plan and picture links -> document or picture page
user attachment -> hub -> thread machine uploads -> authenticated file stream
lead image card -> machine copy and card spool -> hub card -> thread image
archive -> branch documents; machine removes uploads
```

The sidebar has an aside panel and hidden files section; phone links sit below the header (`viewer/pages/thread.html:23-26,58-60`; `viewer/pages/thread.css:16,204-216`). `renderFiles` always links MAP, IDEA and PLAN when a slug and worktree or archive exist, without checking file existence; diagram cards are deduplicated by file and aside graphs added. Both sidebar and phone link to pages, not downloads; the render signature watches diagram cards and aside graphs (`viewer/pages/thread.js:235-275,1115`).

The app document page allows only the three names, fetches thread chat, then reads live Markdown from `/wheelchair/doc?plan=<worktree>/docs/plans/<slug>` or archived content from the thread doc API, and renders it (`viewer/pages/doc.js:7,43-72`). The older plan viewer also uses `/plan` and `/doc` (`viewer/doc.js:16-25`). Live reads require a locally registered real plan directory, then a relative `.md` path with lexical and realpath containment and a regular file; the response is Markdown (`viewer/server.js:1510-1528,1551-1569,1659-1670`). Registration is attempted on the hub from the recorded worktree (`viewer/app/sessions.js:421-422`; `viewer/app/hub.js:71-73`). This route reads the hub filesystem directly, not through the thread machine, so a worktree existing only on another machine cannot be read through it. Archived docs use local `git -C thread.project show` with a three-name allowlist and 2 MiB buffer (`viewer/app/routes.js:522-524`; `viewer/app/threads.js:12,251-265`); remote-only project paths have the same local-filesystem limitation.

For user attachments the composer accepts files up to 25 MiB, streams each to the hub and inserts returned absolute paths as `[attached: ...]` in the message (`viewer/pages/thread.js:1192-1193,1201-1221`; `protocol/app/cards.md:152`). Hub upload checks length, frozen/archive state and a live lead, tracks in-flight uploads, then streams to `thread.machine` (`viewer/app/routes.js:104-134`). The machine sanitizes names, reserves numbered files under its state directory `uploads/<thread-id>`, streams with a 25 MiB limit and renames the temporary file (`machine/service.js:37-45,298-338`). The browser derives numbered basenames from attachment paths and displays image previews or download chips (`viewer/pages/thread.js:465-489`).

The agent CLI validates JSON and posts with a session token; allowed fields, kinds and roles are centralized in `card.js`, and the hub revalidates against the session role (`viewer/app/card.js:10-45,147-148,175-188,218,275-291`; `viewer/app/cards.js:56-67`). The image kind is lead-only; it requires an absolute path and title (`protocol/app/cards.md:48`; `protocol/app/cards-lead.md:209-220`). The machine copies a regular PNG/JPEG/GIF/WebP of at most 25 MiB into uploads before spooling the card; the hub stores its basename, and the thread displays it (`machine/service.js:351-368,1983-1985,1997,2006-2028`; `viewer/app/cards.js:133-134`; `viewer/pages/thread.js:916-919`). A new document kind needs a role/field contract and corresponding copy, delivery, presentation and listing behavior; existing image validation cannot send arbitrary documents.

Browser API reads require cookie or token; writes also require the matching origin (`viewer/server.js:1286-1298,2090-2110`). For `/files/<name>`, the hub accepts only numbered safe basenames and streams from the thread machine using its secret, forwarding only content type, disposition and nosniff (`viewer/app/routes.js:501-510`; `viewer/app/machine-client.js:126-147`). The machine independently validates thread ID and filename, serves only known image extensions inline, and sends all other extensions as `application/octet-stream` with `attachment` and `nosniff` (`machine/service.js:37-39,1945-1953`). A finished archive removes the machine uploads directory; failure prevents a completed archive and reports a needs card (`machine/service.js:1181-1189`; `viewer/app/threads.js:227-235`). Consequently attachments and image cards stop being downloadable on archive (`viewer/pages/thread.js:474-481,916-919`).

Not checked: handoff/import preservation of files, detailed diagram export formats, or unrelated portions of the older maps.
