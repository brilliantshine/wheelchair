Discovery reads immediate `.wheelchair/tools` directories, validates `tool.json` (32 KiB limit), gives project names precedence over shared names, and checks executables; malformed and missing programs become problem rows (`machine/lib/folder-tools.js:8`, `machine/lib/folder-tools.js:41`, `machine/lib/folder-tools.js:62`). Scripts declare typed inputs, `run`, and a 1–240 second timeout; servers require `start` argv, not a URL; both can declare key names (`machine/lib/folder-tools.js:15`). The service groups scripts into the `wheelchair-tools` bridge and constructs one launcher entry per server, subject to conflicts and connector policy (`machine/service.js:1002`, `machine/service.js:1035`; `machine/lib/folder-tools.js:77`). Scripts inherit the launch environment with the session token removed and project directory set (`machine/lib/tool-run.js:7`); bridge and launcher load declared keys from project or shared stores (`machine/lib/tool-bridge.js:8`; `machine/lib/tool-launch.js:28`).

The keyless launcher pipes stdin and stdout, inherits stderr, and waits for child `close` before exiting with its status (signal becomes 1); stdin end kills the detached process group and exits, as do termination signals, with a five-second SIGKILL reaper (`machine/lib/tool-launch.js:39`). `launcher drains output and propagates child exit` is now at `machine/test/folder-tools-run.test.js:46`, not line 26: it verifies one million stdout bytes and exit 7; a separate test simulates output arriving after `exit` and before `close` (`machine/test/folder-tools-run.test.js:69`). It does not test stderr draining or a descendant holding the server's stdout open. Keyed launch instead pipes both streams through the line-checking and redacting relay, respects backpressure and pending writes, and uses child `exit` plus stream ends, with a two-second post-exit limit and a 60-second hard limit after stdin closes (`machine/lib/server-relay.js:6`, `machine/lib/server-relay.js:21`, `machine/lib/server-relay.js:81`, `machine/lib/server-relay.js:104`).

`wc.js tool new` copies the selected template with name replacement and copies the stdio helper into server folders; the only server starter is Node's echo server (`viewer/app/tool-cli.js:56`; `machine/templates/tools/server/tool.json:1`; `machine/templates/tools/server/server.js:1`). `check` performs a time-limited MCP handshake without declared keys; `run` is scripts only and may use the machine route for keyed runs (`viewer/app/tool-cli.js:104`, `viewer/app/tool-cli.js:137`). The CLI test creates both starters and checks the echo server (`viewer/test/wc-tool.test.js:21`). The guide is `protocol/tools.md`.
