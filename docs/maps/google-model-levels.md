1. `show --json` calls `agy_models` for `agy_visible` (`codex/model.sh:472`, `codex/model.sh:483`). `agy_parse` splits tab-separated IDs and names, discards duplicate IDs, `none`, and IDs outside the provider format, and labels each remaining ID separately (`codex/model.sh:277`). The cache is `agy-models.json` beside the pins, normally `~/.wheelchair/agy-models.json`; fresh entries under 3600 seconds are reused, and an expired cache survives a failed, timed-out, or empty discovery (`codex/model.sh:45`, `codex/model.sh:272`, `codex/model.sh:290`). `agy_valid` validates cached shape and format but does not group levels (`codex/model.sh:330`). Thus a fresh cache delays new models; stale cache can persist beyond an hour on failure.
2. Registry-backed Gemini defaults are Flash `low`, `medium`, then `high` for heavy, critical and lead, all without a separate effort; sub-lead inherits lead unless explicitly pinned (`connectors/agy/manifest.js:73`, `codex/model.sh:20`, `codex/model.sh:126`). Pins are `provider.slot = model` with optional ` @effort`; `none` cannot have effort, and invalid or duplicate entries make the file malformed (`codex/model.sh:66`, `codex/model.sh:70`, `codex/model.sh:132`). Gemini permits lowercase model IDs up to 64 characters and efforts low through max (`connectors/agy/manifest.js:90`); max is allowed even though the supplied level examples do not establish a max ID. Installer `init` only creates a missing pin file (`install.sh:168`, `codex/model.sh:456`). Existing suffixed pins therefore need an explicit compatibility decision if storage changes.
3. `options()` combines discovered `{value,label}` entries with all current pins, deduplicating pins by exact ID only (`viewer/app/settings.js:440`, `connectors/agy/manifest.js:36`). The browser adds a missing current value, Not used where allowed, and Other; Other validates a typed model, and a separate selector saves effort or CLI default (`viewer/pages/settings.js:199`, `viewer/pages/settings.js:221`, `viewer/pages/settings.js:245`, `viewer/pages/settings.js:262`). PUT validates slot, provider format and effort membership, then delegates to `model.sh set` (`viewer/app/routes.js:345`). Grouping discovery alone will still append old level-suffixed pins and current values.
4. `slotFor` chooses the role/tier cell; `resolveModel` reads its model and effort separately (`viewer/app/balancer.js:12`, `viewer/app/sessions.js:104`). Worker requested effort overrides the pin; absent both becomes null, and the unchanged model and optional effort are sent to the machine (`viewer/app/sessions.js:390`, `viewer/app/sessions.js:417`). The agy connector sends these independently as `--model` and `--effort` (`connectors/agy/machine.js:74`). No level-ID mapping happens in this path: escalation of effort alone currently leaves the passed model ID unchanged. The code does not establish what the live CLI does with the two flags.
5. Settings generates escalation instructions: one failed try per step, effort-first or tier-first, CLI default counted as high, and configured ceilings (`viewer/app/settings.js:154`). A sub-lead rewrites the brief and starts a fresh worker with `--tier` and optional `--effort` (`protocol/app/sub-lead.md:121`, `protocol/app/sub-lead.md:202`).
