```text
Settings controls -> model cells -> model.sh pins
                  -> role tiers and escalation -> hub settings
session request -> role slot -> eligible provider and account -> model and effort -> machine start
```

1. Settings loads connector metadata and builds four tier columns, separate lead and sub-lead cells, escalation controls and six Other agents tier selectors (`viewer/pages/settings.html:10`, `viewer/pages/settings.js:15`, `viewer/pages/settings.js:26`, `viewer/pages/settings.js:618`, `viewer/pages/settings.js:640`, `viewer/pages/settings.js:647`, `viewer/pages/settings.js:662`). Tier rows show enabled harnesses, while lead cells iterate all providers; tier cells allow Not used and lead cells do not (`viewer/pages/settings.js:626`, `viewer/pages/settings.js:629`, `viewer/pages/settings.js:642`). CSS stacks the tier table at phone width (`viewer/pages/settings.css:156`). Model and effort changes save immediately, restore the control on refusal and refresh options (`viewer/pages/settings.js:251`).
2. `GET /settings` combines settings, `model.sh show --json`, options and heads-up (`viewer/app/settings.js:437`, `viewer/app/settings.js:487`, `viewer/app/settings.js:506`). `PUT /settings/models` validates provider, slot, model format and effort against manifests, normalizes known Antigravity levels, then calls `model.sh set`; omission of effort clears it (`viewer/app/routes.js:345`, `codex/model.sh:592`). Heads-up switch, skip and reset use a separate endpoint (`viewer/app/routes.js:364`). `PUT /settings/preferences` validates escalation and recognized role tiers, then serializes the settings update (`viewer/app/routes.js:381`, `viewer/app/routes.js:441`, `viewer/app/routes.js:457`, `viewer/app/settings.js:422`).
3. The two stores are distinct: hub settings hold `other_agents`, escalation and conversation on/off preferences, with defaults and normalization (`viewer/app/settings.js:56`, `viewer/app/settings.js:326`, `viewer/app/settings.js:416`); `model.sh` reads and atomically writes `~/.wheelchair/models` by default, using connector registry pins as defaults (`codex/model.sh:14`, `codex/model.sh:45`, `codex/model.sh:127`, `codex/model.sh:144`, `codex/model.sh:489`). An absent sub-lead pin falls back to the lead cell; malformed pins read as defaults and normal writes refuse them (`codex/model.sh:127`, `codex/model.sh:473`, `codex/model.sh:489`).
4. Placement maps lead and sub-lead to their own slots, reviewer/verifier/mapper/designer to saved role tiers, and worker requests to tiers (`viewer/app/balancer.js:12`). It excludes unused cells and ranks available accounts under provider order, family and reserve rules (`viewer/app/balancer.js:67`, `viewer/app/balancer.js:89`, `viewer/app/balancer.js:96`). Session startup checks worker tier and effort ceilings, resolves the selected cell, records the model and effort and sends them to the machine (`viewer/app/sessions.js:103`, `viewer/app/sessions.js:234`, `viewer/app/sessions.js:314`, `viewer/app/sessions.js:364`, `viewer/app/sessions.js:398`, `viewer/app/sessions.js:407`). Escalation instructions are also composed into sub-lead role layers; scout tiers resolve within the chosen provider and become instructions for built-in helpers, not separate placements (`viewer/app/settings.js:237`, `viewer/app/sessions.js:119`, `viewer/app/sessions.js:368`).
5. Assistant and project lead toggles are in the separate Conversations section, with no model picker there (`viewer/pages/settings.js:677`); both start as `lead` with `top`, so the lead slot applies (`viewer/app/assistant.js:32`, `viewer/app/project-lead.js:92`, `viewer/app/balancer.js:12`).

Connector manifests define provider IDs, model options, pins, formats and supported efforts; the registry supplies the script, and the hub derives capabilities from manifests (`connectors/README.md:5`, `connectors/claude/manifest.js:37`, `connectors/codex/manifest.js:36`, `connectors/kimi/manifest.js:95`, `connectors/pi/manifest.js:85`, `viewer/app/providers.js:4`, `codex/model.sh:14`). GPT options come from its cache, Kimi from its config and Antigravity from discovery; current pins remain options (`codex/model.sh:45`, `codex/model.sh:250`, `codex/model.sh:332`, `codex/model.sh:568`, `viewer/app/settings.js:487`).
