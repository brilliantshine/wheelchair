  -> choose provider and account -> resolve slot, model and effort

A session start checks the role and worker escalation ceiling, chooses an available provider/account, runs GPT preflight where applicable, resolves the model, builds role layers and sends these with permissions and brief to the machine (`viewer/app/sessions.js:119-128,141-170,198-218`). Claude, GPT and Gemini map to `claude`, `codex` and `agy`; all support configured effort (`viewer/app/providers.js:3-5`). The balancer pins a sub-lead to the thread provider, uses the lead slot for both leads and sub-leads, Other agents' tier for mapper/reviewer/verifier, and the requested tier for workers (`viewer/app/balancer.js:11-17,27-30,38-62`). A `none` cell is unavailable; placement also considers account status and reserve (`viewer/app/balancer.js:19-25,56-67`; `viewer/app/sessions.js:19-31`).

`settings.js` defines light, standard, heavy, critical and the luna/terra/sol/astra aliases; the balancer also accepts haiku/sonnet/opus as tier aliases and `top` as heavy (`viewer/app/settings.js:12-14,34-37`; `viewer/app/balancer.js:15-17`). `codex/model.sh` owns provider cells for those four slots plus `lead`, with model and optional effort, defaults, `none`, validation and JSON output (`codex/model.sh:15-35,54-59,75-95,124-132,314-329,361-385`). The Models page renders tier cells and one lead cell per provider shared by both roles, plus Other agents selectors for reviewer, verifier and mapper (`viewer/pages/settings.js:9-16,261-269,324-339,398-408,443-450`). Defaults for Other agents are heavy/heavy/standard (`viewer/app/settings.js:24-27`); API documents these settings and slot resolution (`viewer/app/API.md:37-40,100-104`).

The two role sets enumerate lead, sub-lead, mapper, worker, reviewer and verifier (`viewer/app/settings.js:12`; `viewer/app/sessions.js:35-47`). A lead may start mapper, reviewer, sub-lead or verifier; a sub-lead may start worker or verifier. An attempt ID is required, only one sub-lead may be live, and only a sub-lead starting a worker may override effort (`viewer/app/sessions.js:44-47,461-481`). Provider inclusion/exclusion is only accepted for worker/reviewer/verifier and is mutually exclusive; worker tiers are limited by escalation settings (`viewer/app/balancer.js:27-30`; `viewer/app/sessions.js:122-126,468-473`; `viewer/app/API.md:126,132-136`). The CLI also requires role, attempt and brief file (`viewer/app/wc.js:76-88`). Mapper/reviewer/sub-lead share the thread worktree; workers and verifiers have different branch handling (`viewer/app/sessions.js:492-498`).

`fullPrompt` previews a role-file pointer plus template, escalation or writing-style layers; the machine independently composes the same pointer with supplied layers unless `role_prompt` overrides it (`viewer/app/settings.js:141-160`; `machine/service.js:95-102`). Claude receives it as an appended system prompt; Codex and agy receive a `[wc:role]` first message (`machine/adapters/claude.js:55-62`; `machine/adapters/codex.js:50-51`; `machine/adapters/agy.js:30-34`). A new app role therefore needs a role file, both role sets, start authorization, slot/placement and worktree policy, settings/UI and card/result handling as appropriate; existing settings/hub and machine tests cover these contracts (`viewer/app/settings.js:12,157-160`; `viewer/app/sessions.js:35-47,461-498`; `viewer/app/balancer.js:11-17,27-30`; `machine/test/service.test.js:42-48,775-801`; `viewer/test/app-settings.test.js:28,203`; `viewer/test/app-hub.test.js:1094-1098`).

Harness subagents are separate from app sessions and their hub policy. Claude Code documents an Agent tool model alias override, and custom subagents can specify a model; configuration or organization restrictions can change the result ([Claude Code subagents](https://code.claude.com/docs/en/sub-agents)). The app's normal Claude launch supplies hooks, permission mode, model and prompt, but no explicit tool restriction or subagent model setting (`machine/adapters/claude.js:55-60`; `machine/service.js:494-498`). Codex documents subagent model/effort selection by prompt or agent configuration ([Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)); its normal app launch specifies sandbox, approval policy, notify, trust, model and effort, without an explicit multi-agent toggle (`machine/adapters/codex.js:50-51`). Antigravity documents custom subagent model tiers including flash_lite and flash ([Antigravity plugins](https://antigravity.google/docs/build-plugins/)); the app launches `agy` with trusted workspace, permission mode, model and effort, without an explicit subagent switch (`machine/adapters/agy.js:30-34`). These establish documented capability and launch arguments, not that a particular installed version, account, inherited configuration, policy or role instruction allows a given invocation. No live harness invocation was tested.

After a worker result the sub-lead must rerun validation and read the diff, then read the report and log choices before merging (`protocol/app/sub-lead.md:129-152`). A restarted sub-lead reads IDEA, all of PLAN, and MAP; if already implementing, it reconciles the tasks and reports with the tree and checks live sessions before dispatch (`protocol/app/sub-lead.md:25-36`). Fresh context between tasks is not part of this restart procedure.
