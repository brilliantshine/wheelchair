## Flow

The page loads shared navigation and the Settings scripts, resolves a hash to one of eight sections (unknown hashes fall back to Models), fetches `/settings`, and renders that panel. A `templates/lessons/<role>` hash opens the role's lesson editor. Changing hash rerenders and starts or stops section-specific work (`viewer/pages/settings.html:11`, `viewer/pages/settings.js:8`, `viewer/pages/settings.js:2224`, `viewer/pages/settings.js:2257`, `viewer/pages/settings.js:2273`).

```text
nav / section link -> hash selection -> GET settings -> panel
                                     -> edit -> hub route -> relevant store or machine
                                     -> section-specific refresh -> repaint
```

The hub validates and serializes changes in `settings.json`; model pins go through `codex/model.sh`, diagram sensitivity goes to each machine, project tools go through the selected machine, and background images have their own revision-checked route (`viewer/app/state.js:75`, `viewer/app/state.js:250`, `viewer/app/settings.js:416`, `viewer/app/routes.js:84`, `viewer/app/routes.js:237`, `viewer/app/routes.js:327`, `viewer/app/background.js:67`). The layout uses a 240px sidebar and a panel up to 1080px, with responsive rules in the stylesheet (`viewer/pages/settings.css:2`, `viewer/pages/settings.css:8`). Space below is an estimate from rendered groups, not a measured viewport.

## Inventory

Unless otherwise stated, settings are saved in hub `settings.json`, and initial data is fetched on page load rather than periodically. Section refresh does not necessarily reload all settings (`viewer/pages/settings.js:1366`, `viewer/pages/settings.js:2273`, `viewer/app/settings.js:416`).

- **Harnesses `#harnesses`**: machine picker; one row per provider with enabled/Use switch, install/try again/cancel, installation progress, and sign-in or Accounts link; warning when a machine is old. Several rows, expanding with provider count and job/sign-in status. Enabled flag is in hub settings; installation and login belong to the selected machine. Loads on entry/machine selection; active installs poll every 2 seconds and sign-in also polls (`viewer/pages/settings.js:1411`, `viewer/pages/settings.js:1502`, `viewer/pages/settings.js:1980`, `viewer/pages/settings.js:2016`, `viewer/pages/settings.js:2116`, `viewer/pages/settings.js:2182`, `viewer/app/routes.js:119`).
- **Accounts `#accounts`**: provider groups and account cards show plan/weight, pause status, active sessions, per-machine sign-in and 5-hour/week readings; actions sign in, pause/resume, rename, change plan/weight, remove, restore default, and add account. Variable, potentially multiple cards per provider; sign-in opens a separate card. Account metadata is hub settings, credentials/sign-in on machines, readings in usage storage. Usage refreshes every 30 seconds while Accounts is open, pausing repaint while editing; login polls every 2 seconds (`viewer/pages/settings.js:1366`, `viewer/pages/settings.js:1411`, `viewer/pages/settings.js:1502`, `viewer/pages/settings.js:1541`, `viewer/pages/settings.js:1597`, `viewer/pages/settings.js:1647`, `viewer/app/routes.js:275`, `viewer/app/routes.js:509`).
- **Usage `#usage`**: provider bars and expandable account tables report weekly usage; Balancing has worker provider order, account selection within provider, leave-for-user and warning percentages, reserve provider for leads, lead margin, and held-back role checkboxes, with Save. Variable provider bars plus roughly seven setting rows. Hub settings store balancing; usage readings come from `/usage`. Refreshes every 30 seconds when visible; opening marks warnings seen (`viewer/pages/settings.js:1366`, `viewer/pages/settings.js:1723`, `viewer/pages/settings.js:1746`, `viewer/pages/settings.js:1763`, `viewer/app/routes.js:323`).
- **Models and preferences `#models`**: a long multi-group page. **Tiers** is a provider-by-four-tier table, model and effort choices with heads-up actions; **Leads** has lead and sub-lead models per provider, lead provider order, and lead name list/upload. Pins use model script; lead order/names use hub settings (`viewer/pages/settings.js:175`, `viewer/pages/settings.js:242`, `viewer/pages/settings.js:315`, `viewer/pages/settings.js:572`, `viewer/pages/settings.js:1794`). **Escalation** has four choices: first step, highest effort, highest tier, when to ask (`viewer/pages/settings.js:584`). **Permission mode** has two provider-family session modes plus aside access (`viewer/pages/settings.js:594`). **Threads** has personal assistant, project leads, tool steps, auto-merge and conditional branch deletion, Enter-to-send, default project folder and your name; these are one row each, mostly hub settings, except Enter-to-send is browser localStorage (`viewer/pages/settings.js:401`, `viewer/pages/settings.js:425`, `viewer/pages/settings.js:453`, `viewer/pages/settings.js:558`, `viewer/pages/settings.js:605`). **Diagrams** is a three-choice group, read from and written to each machine's harness instruction files, read on visit and after save, no timer (`viewer/pages/settings.js:111`, `viewer/pages/settings.js:141`, `viewer/pages/settings.js:622`, `viewer/app/API.md:58`). **Other agents** has family choice and six tier rows for reviewer, checker, mapper, designer and two scouts (`viewer/pages/settings.js:625`). No general periodic refresh for these groups.
- **Behavior templates `#templates`**: role-grouped template and Lessons learned list; new/edit template opens a large editor with name, role, project scope, save-every-step, full tests, package policy, worker unsettled policy, file threshold, free text, composed prompt preview, in-use, save/duplicate/delete. Lessons editor lists editable lessons per role, history/restore, removed and waiting entries, keep, import/export. Variable long list and editor; saved templates and lessons/history are hub settings, composed prompt fetched on request; no periodic refresh (`viewer/pages/settings.js:648`, `viewer/pages/settings.js:673`, `viewer/pages/settings.js:751`, `viewer/pages/settings.js:831`, `viewer/pages/settings.js:1000`, `viewer/pages/settings.js:1022`, `viewer/pages/settings.js:1042`, `viewer/pages/settings.js:1090`, `viewer/pages/settings.js:1099`, `viewer/pages/settings.js:1144`, `viewer/app/routes.js:255`, `viewer/app/routes.js:448`).
- **Writing style `#writing`**: Basics (length, lists/headings, technical terms), Never say phrase chips, free text, before/after preview, save. Several rows plus two text/preview blocks; hub settings, preview is requested separately and does not save; no periodic refresh (`viewer/pages/settings.js:1189`, `viewer/pages/settings.js:1211`, `viewer/pages/settings.js:1236`, `viewer/pages/settings.js:1276`, `viewer/app/routes.js:493`).
- **Project tools `#tools`**: machine/project pickers, waiting PRs, tools list with add/edit/remove, Unity helper, Windows switch/status, form fields for name, command/arguments/environment or URL/headers and key references, save/start-over; keys on selected machine can be added, replaced or removed. Potentially large, variable list and form. Project tools changes open a PR against the default branch; key values stay on the selected machine. Picker/project loads on selection, Unity job polls while running and Windows connection checks are scheduled; not a general periodic refresh (`viewer/pages/project-tools.js:125`, `viewer/pages/project-tools.js:202`, `viewer/pages/project-tools.js:252`, `viewer/pages/project-tools.js:301`, `viewer/pages/project-tools.js:340`, `viewer/pages/project-tools.js:358`, `viewer/pages/project-tools.js:454`, `viewer/pages/project-tools.js:535`, `viewer/pages/project-tools.js:631`, `viewer/pages/project-tools.js:879`, `viewer/pages/project-tools.js:1009`, `viewer/app/routes.js:84`).
- **Background Customization `#background`**: image picker, visibility slider, save, cancel and remove; one compact box plus page preview. Background metadata is in settings and image is stored separately; local preview is validated using the shared image-format code and is not committed until save. Saved background refreshes every 10 seconds while visible and on focus/visibility/page show; image writes use revisions (`viewer/pages/settings.js:1844`, `viewer/pages/settings.js:1877`, `viewer/pages/settings.js:1901`, `viewer/pages/background-format.js:151`, `viewer/pages/background.js:70`, `viewer/app/background.js:67`).

Grouping observations: Models and preferences mixes model/agent selection with identity, project folder, thread UI, assistant, merging and diagram policy (`viewer/pages/settings.js:568`, `viewer/pages/settings.js:605`). Lead provider order sits in Models while worker order and other balancing sit in Usage (`viewer/pages/settings.js:1774`, `viewer/pages/settings.js:1794`).
