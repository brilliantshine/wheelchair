Checked against: `28d7471ce54f8e09154b345db4a9b066280aea34` (origin/main and worktree HEAD)
Files covered: `viewer/app/balancer.js`, `viewer/app/usage.js`, `viewer/app/usage-poll.js`, `viewer/app/sessions.js`, `viewer/app/quiet.js`, `viewer/app/routes.js`, `viewer/pages/settings.js`, `machine/service.js`, `machine/adapters/claude.js`, `machine/adapters/codex.js`, `machine/adapters/common.js`, `machine/lib/aside-turns.js`, `machine/lib/limits.js`, `codex/preflight.sh`.

```text
Settings and machine login status -> placement -> preflight -> tmux CLI
                                     | no room
                                     -> waiting start -> retry
CLI usage or failure -> machine event -> hub holds or reports -> reset -> Continue
CLI transcript -> machine copy -> chat and reports
```

1. Settings manages account records and per-machine sign-in; sign-in starts a machine login with the provider CLI and account directory (`viewer/pages/settings.js:1203`, `:1283-1285`, `:1355-1439`; `viewer/app/routes.js:240-273`, `:449-458`; `machine/service.js:1631-1645`, `:1654-1690`). Machine status enumerates default logins and metadata-bearing account directories and checks each CLI's login (`machine/service.js:1694-1711`; `machine/adapters/claude.js:103`; `machine/adapters/codex.js:152`). Model cells are edited in Models and read via the model script (`viewer/pages/settings.js:175-191`; `viewer/app/routes.js:290-301`).
2. Start chooses by role, provider constraints, configured model, harness, machine sign-in, usage, reserves and rank. Lead/sub-lead follow the thread provider; worker `provider` and `not_provider` are subject to fallback and notes, while review policy can constrain selection (`viewer/app/balancer.js:42-118`; `viewer/app/usage.js:78-97`). No eligible account creates a durable live waiting start; retries rerun selection in creation order (`viewer/app/sessions.js:264-290`, `:873-883`). GPT preflight failure marks the selected account unavailable in cached machine state and reselects once; a second preflight failure returns 409 (`viewer/app/sessions.js:292-314`). Preflight uses `CODEX_HOME`, locks the auth file refresh and atomically persists the rotated token (`codex/preflight.sh:15-33`, `:40-42`, `:63-75`, `:103-117`).
3. Machine validates and seeds non-default account directories, prepares worktree and session, then launches the adapter command in tmux with the session token and account environment (`machine/service.js:804-828`, `:830-832`, `:921-945`). Claude uses `CLAUDE_CONFIG_DIR`, Codex uses `CODEX_HOME`; defaults receive no override (`machine/adapters/claude.js:5-6`; `machine/adapters/codex.js:5-6`). Claude's ordinary launch uses a generated `--session-id`; Codex starts a new interactive CLI, neither launch passes resume (`machine/adapters/claude.js:57-73`; `machine/adapters/codex.js:133-147`).
4. Claude StopFailure classifies only `rate_limit` as limit-hit; other failures become turn-failed (`machine/adapters/claude.js:94-96`). Codex notify translates only agent-turn-complete; its transcript usage can report a reached limit on turn end (`machine/adapters/codex.js:114-131`, `:149-151`; `machine/service.js:1519-1533`). Machine calculates a reset from readings, otherwise one hour, for limit-hit (`machine/service.js:1536-1543`; `machine/lib/limits.js:2-7`). Hub records a future limit and holds delivery; expiry queues `Continue.` to the same live session, not another account (`viewer/app/sessions.js:506`, `:593-608`, `:886-893`). A turn-failed event instead tells the starter or creates a lead needs card (`viewer/app/sessions.js:610-619`). Startup stuck is a 30-second readiness event; quiet detection watches obligations after turns and is separate from quota classification (`machine/service.js:1141-1152`; `viewer/app/quiet.js:3-7`, `:32-56`).
5. Claude searches the selected account's `projects` for its session ID; Codex binds its thread ID on a matching role turn and searches that account's `sessions` (`machine/adapters/claude.js:86`; `machine/adapters/codex.js:114-125`, `:149`). Machine copies source transcripts to its own thread/session path (`machine/service.js:1376-1423`, `:1441-1451`). A separate headless aside supports Claude `--resume` and runs with a selected account environment; this does not establish that a transcript from one account is resumable in another account's directory (`machine/adapters/claude.js:49`; `machine/lib/aside-turns.js:58-71`, `:94-104`).

Not looked at: actual CLI internals, cross-account transcript portability or live behavior, every error format, browser styling, and full test coverage.
