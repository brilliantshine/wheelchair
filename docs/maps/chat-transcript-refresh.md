# Map: chat transcript refresh

Checked against: `6e89dfb4b0bf67e121b8ab4c3b720844ee4a74d7` (origin/main; covered files match this worktree).
Files covered: `viewer/app/chat.js`, `viewer/app/hub.js`, `viewer/app/state.js`, `viewer/app/machine-client.js`, `viewer/app/sessions.js`, `viewer/app/routes.js`, `viewer/app/views.js`, `viewer/app/agents.js`, `machine/service.js`, `viewer/test/app-chat.test.js`, `viewer/test/app-hub.test.js`, `machine/test/service.test.js`.

```text
chat request -> thread lock -> read each lead from machine -> parse or reuse -> assemble chat
                                  | failure or empty
                                  -> cached text -> local file -> empty
machine request -> serialized copy -> complete source lines -> dedupe -> append -> read kept file
```

`hub.chat` protects assembly with `withChatThread`; aside creation uses the same protection before its thread lock (`viewer/app/hub.js:132-142`, `viewer/app/hub.js:282-285`, `viewer/app/routes.js:599`). Each lead calls `sessionTranscript`; its cache is keyed by machine/session and stores raw `text`, `gen`, `end`, `parsed`, `parsedKey`, `lastRead`, and thread id. It sends `known=gen:end` when a generation is present; a matching `unchanged` returns the cached text, a mismatched response retries without `known`, and nonempty data replaces the entry, retaining the parse only when the raw text matches (`viewer/app/chat.js:329-348`). Errors or empty data use cached text, then the local transcript path. Chat reuses the parsed result only when text and the CLI/parent-title parse key match; otherwise it parses again (`viewer/app/chat.js:350-354`, `viewer/app/chat.js:423-445`). A minute timer removes entries unread for over ten minutes unless a chat operation is pending for that thread (`viewer/app/hub.js:95-96`, `viewer/app/hub.js:132-142`). Strict report reads bypass this cache and use a separate timed machine request, falling back to the local path on a 404 or empty data (`viewer/app/chat.js:313-328`, `viewer/app/sessions.js:448`).

For a managed session the machine finds the source if needed, serializes copy and read per session, and returns either `{unchanged:true, gen, end}` or `{offset, data, gen, end}`. Generation includes device, inode and birth time; it reads a full snapshot from the same handle. A forgotten archived session reads its kept file separately (`machine/service.js:1460-1467`, `machine/service.js:1526-1549`, `machine/service.js:2360`). The copier resets its source offset on path, inode or shrink changes, skips an unchanged source, and advances only through newline-terminated records; Pi records are redacted (`machine/service.js:1469-1484`).

With complete new lines, the copier checks its per-session hash set against the kept file's inode and size; on mismatch it reads the file, cuts a partial final line and rebuilds SHA-256 hashes. It appends unique lines, invalidates the set on append failure, and adds hashes only after success. Source state is saved when changed; a failed save sets `transcript_unsaved` so the next copy retries (`machine/service.js:1485-1524`, `machine/service.js:568`). Hash eviction after ten minutes occurs on a subsequent copy, not a timer; stop and fatal Kimi cleanup delete sets, and archive normally stops sessions first (`machine/service.js:194`, `machine/service.js:1470-1472`, `machine/service.js:1051-1053`, `machine/service.js:1309-1319`, `machine/service.js:1360-1376`). A copy already in flight can repopulate a set after stop because the final insertion has no stopped-session check (`machine/service.js:1492-1515`).

Each successful `hub.call` updates the in-memory machine seen time and awaits a serialized read/modify/atomic replacement of `machines.json`; the hub loads saved times at init (`viewer/app/hub.js:77-80`, `viewer/app/hub.js:107-113`, `viewer/app/hub.js:160-163`, `viewer/app/state.js:75-87`, `viewer/app/state.js:263-270`, `viewer/app/state.js:23-31`). Sessions and agent views expose the in-memory value (`viewer/app/views.js:160-165`, `viewer/app/agents.js:143-147`).

Tests cover cached parsing, context changes, old machines, fallback and idle pruning (`viewer/test/app-chat.test.js:371-431`); last-seen persistence (`viewer/test/app-hub.test.js:899-908`); source shrink, partial and overlapping copies, idle/failed-save retry, crash cuts, hash reuse/failure/stop, and stamps (`machine/test/service.test.js:265`, `machine/test/service.test.js:418-436`, `machine/test/service.test.js:1790-1850`). Commands: `node --test viewer/test/*.test.js` and `bash machine/test/run.sh`.
