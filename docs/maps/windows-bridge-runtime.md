# Map: Windows copy lifecycle and shutdown

Checked against: `c797033d53bcd9e4ddbf95cf2b52debba0d74de4` (origin/main; the covered handoff flow matches this worktree, with unrelated later changes in that file). Files covered: `machine/lib/win.js`, `machine/lib/win-env.js`, `machine/lib/win-sync.js`, `machine/lib/win-apps.js`, `machine/service.js`, `viewer/app/handoff-ops.js`, `machine/test/win.test.js`, `machine/test/win-tool-ready.test.js`, `machine/test/win-tool-sweep.test.js`.

```text
launch -> waiting file -> create copy -> reconcile -> ready file -> tool writes
stop / missing tmux -> app cleanup -> eligible final reconcile -> archive or retain copy
restart -> recover live sessions with existing copies -> mark used -> sweep
```

- A copy is keyed by worktree and registered with thread, worktree, copy and last session; create can seed from another successful copy (`machine/lib/win.js:56-73,90-103`; `machine/lib/win-env.js:49,184-187`). Reconcile snapshots both sides and merges changes, serializes by copy/worktree, and records success or failure (`machine/lib/win-sync.js:259-285,296-310,351-386`).
- Wrapped launch writes `waiting` with an in-memory per-session attempt token, attaches the copy key and shares in-memory readying per copy. A successful sync publishes `ready` with the Windows path; a failure publishes `failed`; launch waits at most 45 seconds (`machine/lib/win.js:28-31,113-153,155-177,180-194,204-254`). After launch, the copy is marked used, including after late readying (`machine/lib/win.js:196-202`).
- Startup recovers live tmux sessions, then bridge startup marks live tool-role sessions with existing copies as tool sessions and used, and sweeps (`machine/service.js:547-565`; `machine/lib/win.js:397-417`). It does not restore ready tokens or resume readying for waiting or failed files; the proposed durable `win-sessions.json` launch flags and recovery are absent from this path (`machine/lib/win.js:28-33,397-417`; `5950541c^:docs/plans/windows-bridge-solid/PLAN.md:194-211`). A later sync publishes only to current in-memory tokens (`machine/lib/win.js:149-164`).
- Normal stop kills tmux, marks the session stopped and starts `onStop` without awaiting it (`machine/service.js:1212-1227`). `onStop` removes the ready file, stops bridge-tracked apps, awaits readying, then removes a verifier copy or syncs an eligible unshared lead/sub-lead copy; it does not wait for proxy tools (`machine/lib/win.js:273-294`). Fatal stop calls `onStop` before killing tmux (`machine/service.js:967-977`). Tracked bridge apps are separate from proxy children (`machine/lib/win.js:39-40,273-275`; `machine/lib/win-tool-proxy.js:97-106`).
- Sweep runs every 60 seconds, cleans tracked apps for missing tmux sessions and syncs eligible idle thread copies; it checks running syncs but not `stopTasks` or proxy processes (`machine/service.js:450-453`; `machine/lib/win.js:361-370`). Handoff first tries managed stops then directly kills any remaining tmux sessions, without calling `onStop` in that kill action (`viewer/app/handoff-ops.js:83-96`; `machine/service.js:2020-2033`). A missing tmux session is observed by the sweep; unknown tmux status aborts it (`machine/service.js:471-478`; `machine/lib/win.js:361-365`).
- Archive stops sessions and asks `archiveCheck` before commit/removal; that check waits for known stop, readying and sync tasks and starts an eligible final sync, but has no copy-wide proxy gate (`machine/service.js:1251-1284,1299-1304`; `machine/lib/win.js:319-334`). Successful archive removes copies, while failed reconciles are retained (`machine/lib/win.js:336-347`).
- Tests cover restart with an existing copy, shared-copy stop and dead-session sweep, archive pending, ready-file attempt isolation, and stale-file cleanup (`machine/test/win.test.js:193-249,293-308,351-372,402`; `machine/test/win-tool-ready.test.js:38-88`; `machine/test/win-tool-sweep.test.js:10-27`).

Not checked: live WSL behavior, all crash modes, Git conflict mechanics beyond the cited reconciliation flow, and Windows app internals beyond their separation from proxy children.
