```text
user message or card press -> queue and timestamp -> thread JSON -> delivery -> sent JSON / JSONL
                                                             -> restart context and pages
sent records + imported history -> v1 export -> validate import -> stored history -> page / restart / export
```

New-thread text, a send route and an aside enqueue source `collin` (`viewer/app/threads.js:79`, `viewer/app/routes.js:534`, `viewer/app/asides.js:62`). Enqueue stamps `collin_at`, puts the message in `session.queue` and mirrors it at `thread.queues[name]` (`viewer/app/sessions.js:470`, `viewer/app/sessions.js:475`, `viewer/app/sessions.js:480`). Successful delivery copies the source into `thread.sent`, retaining 500 and appending overflow to JSONL (`viewer/app/sessions.js:517`, `viewer/app/sessions.js:528`). Thread JSON holds the queues, sent, cards, timestamp and imported history; saves serialize the full record, while `threads/<id>.sent.jsonl` is an append-only sibling under the state directory (`viewer/app/state.js:9`, `viewer/app/state.js:91`, `viewer/app/state.js:94`, `viewer/app/state.js:101`, `viewer/app/state.js:116`). Restart moves pending queues (`viewer/app/threads.js:165`, `viewer/app/threads.js:196`). Send-now and pending bubbles identify messages by that source (`viewer/app/sessions.js:539`, `viewer/pages/thread.js:436`, `viewer/pages/thread.js:504`).

Card presses and dismissal stamp the field; archive, keep, needs actions and dismissal resolve cards as `collin` (`viewer/app/threads.js:246`, `viewer/app/threads.js:327`, `viewer/app/threads.js:331`, `viewer/app/threads.js:404`, `viewer/app/threads.js:422`). `resolveCard` stores its caller's value (`viewer/app/cards.js:37`); the page tests it for the dismissal label (`viewer/pages/thread.js:580`) and the API exposes it (`viewer/app/API.md:22`, `viewer/app/API.md:23`, `viewer/app/API.md:62`). Thread and agent lists use the timestamp with created-at fallback (`viewer/pages/threads.js:38`, `viewer/pages/threads.js:74`, `viewer/pages/agents.js:139`, `viewer/app/agents.js:63`). Restart filters recent sent messages by old source and uses `asUser` to relabel source, card and pin `resolved_by`, and imported `who` in the context without changing stored data (`viewer/app/threads.js:138`, `viewer/app/threads.js:142`, `viewer/app/threads.js:146`, `viewer/app/threads.js:150`).

Export copies imported history, takes newer human and card messages from bounded `thread.sent`, emits `who: collin`, adds cards, and writes version 1 (`viewer/app/handoff.js:56`, `viewer/app/handoff.js:61`, `viewer/app/handoff.js:63`, `viewer/app/handoff.js:71`). Import validates before operations (`viewer/app/handoff-import.js:13`, `viewer/app/handoff-import.js:20`); imported history is displayed as You for `collin` (`viewer/pages/thread.js:231`) and copied into later exports. V1 has strict fields, a 10 MB limit, at most 2,000 history entries and an allowlist of `collin`, `lead`, `app` (`viewer/app/handoff.js:4`, `viewer/app/handoff.js:18`, `viewer/app/handoff.js:28`). An older install importing a new `who` under v1 rejects it with 422 `invalid history`; a new version is rejected as `unknown format or version` (`viewer/app/handoff.js:19`, `viewer/app/handoff.js:29`, `viewer/app/handoff-import.js:14`).

A migration must cover both queue copies, bounded sent, JSONL, timestamps, cards and imported history, or keep compatible readers; export can retain v1's old wire value while internal values change. Readers for old v1 exports remain necessary independently of local state migration. JSONL is appended here, but export and restart read `thread.sent`, not the spill (`viewer/app/state.js:101`, `viewer/app/handoff.js:60`, `viewer/app/threads.js:146`). Converting previously downloaded files cannot be accomplished by migrating local state alone.

Not checked: third-party consumers, arbitrary externally edited state, all handoff operation failure paths, or older releases beyond the validator shown here.
