# Map: project tools at session start

Checked against: `207c02f5e0b56cfbcc96046cca10a8df92002a9c` (origin/main).
Files covered: `machine/lib/project-mcp.js`, `machine/adapters/agy.js`, `machine/adapters/claude.js`, `machine/adapters/codex.js`, `machine/service.js`, `machine/lib/aside-turns.js`, `machine/test/project-mcp.test.js`, `machine/test/project-mcp-codex.test.js`, `machine/test/accounts.test.js`, `machine/test/aside-probe.sh`, `viewer/app/sessions.js`, `viewer/app/cards.js`, `viewer/app/card.js`, `viewer/app/threads.js`, `viewer/app/quiet.js`, `install.sh`.

```text
hub start -> machine worktree -> read .mcp.json -> adapter builds command and warnings
  -> warnings to machine log -> tmux launches CLI -> hub records start response
```

1. The machine prepares the adapter, creates or selects a worktree, reads `.mcp.json`, builds the adapter command, logs reader and adapter warnings only for lead, sub-lead, worker and verifier, writes settings, and launches tmux in that worktree (`machine/service.js:581-600,606-634`; `machine/lib/project-mcp.js:6`). The reader permits regular files up to 32 KiB, checks again after nonblocking open, and accepts only validated stdio and HTTP entries; it preserves all names for Claude's disabled list (`machine/lib/project-mcp.js:10-42`; `machine/adapters/claude.js:69-72`). Warnings are not attached to the returned session (`machine/service.js:608-617,628-634`).
2. Antigravity prepares `~/.gemini/config/hooks.json` using the machine process home, merges the hook atomically, has an empty login environment and seed, and starts with a per-session settings file containing only trusted workspaces (`machine/adapters/agy.js:9-32,54-66`). Its project-tools warning does not install servers (`machine/adapters/agy.js:30-32`). The existing settings argument therefore does not supply MCP. A separate session home or plugin configuration would need to preserve login and hook discovery; their feasibility is unverified here. The earlier plan records rejected `mcpServers` in `--settings` and suggests global or plugin config locations (`docs/plans/local-projects/PLAN.md`, Decision 7 and Deferred D1).
3. Codex restricts names, skips any entry with `headers`, rejects `${...}` except exact same-key stdio env pass-through, and generates `project_`-prefixed TOML overrides for stdio or HTTP, approval and enablement (`machine/adapters/codex.js:58-96`). The reader rejects other transports before the adapter (`machine/lib/project-mcp.js:34-39`). The service stores argv as `session.command`, so expanding secrets there would expose them in that record (`machine/service.js:616-617`). The override budget measures shell-quoted JavaScript string `.length`, i.e. UTF-16 units, not UTF-8 bytes; non-ASCII can exceed the intended byte budget. The entire project override set is dropped when this measure exceeds 64 KiB (`machine/adapters/codex.js:21-28,98-102`).
4. A hub start calls the machine and merges its response into the hub session; queued promotion calls `startSession` again, while an unanswered retry has a separate success path through `resumeUnanswered` (`viewer/app/sessions.js:167-210,304-365,766-775`). The machine returns an existing session for the same name, including retries (`machine/service.js:568-579`). A warning delivery design must account for both response paths and retained retry data; current warnings exist only in the log (`machine/service.js:612-617`).
5. Hub code opens system needs cards using `addCard`, which creates an unanswered record; needs cards are not singleton cards (`viewer/app/cards.js:9-34`; `viewer/app/sessions.js:560-568`). A matching ready or prompt-cleared event sets the stored card answered and persists the thread (`viewer/app/sessions.js:570-586`); other system cards close through their own conditions (`viewer/app/quiet.js:13-18`; `viewer/app/threads.js:166-189`). User presses on system needs are refused (`viewer/app/threads.js:360-362`). Per-CLI warning state and its closure are a proposed follow-up, not present behavior (prior plan Decision 16 and Deferred D4).
6. Codex asides run `codex mcp list --json` to enumerate and disable servers, not to check project server health (`machine/lib/aside-turns.js:109-120`; `machine/adapters/codex.js:36`). The live aside probe verifies Claude's list starts a test server and Codex's list reports its configured server (`machine/test/aside-probe.sh:53-73`); the prior plan reports Claude connection status and Codex/agy list limitations (Deferred D2). The service explicitly passes adapter login variables into the tmux command, but not PATH (`machine/service.js:616-625`); the Linux service unit sets its own PATH (`install.sh:392-399`). The only checked executable PATH lookup here is for Tailscale, against service `process.env.PATH`, not project MCP programs (`machine/service.js:157-164`). A search of machine and viewer app code found no `show-environment` use; the prior plan flags tmux global PATH and `update-environment` caveats (Deferred D4).
7. Reader and service tests cover invalid entries, files, role gating and log output (`machine/test/project-mcp.test.js:18-80`); Codex tests cover expansion, secrets, headers, escaping and an ASCII-heavy budget overflow (`machine/test/project-mcp-codex.test.js:30-90`). Antigravity tests cover argv, trusted settings and hook merging using a temporary HOME (`machine/test/accounts.test.js:104-119`).

Not looked at: Antigravity or Codex upstream source or live configuration behavior; real tmux environment inheritance on each supported OS; exhaustive card UI rendering and all test suites.
