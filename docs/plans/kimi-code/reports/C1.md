# C1 — Remediation 4 gap 3: named Kimi account with no home on a machine

Plan `kimi-code`, task C1. Fixes gap 3 in `docs/plans/kimi-code/REMEDIATION-4.md`: on a machine whose Kimi is below the 2.6.3 floor, a named Kimi account with no entry in that machine's `/v1/status` `accounts[]` showed `signed out` instead of the version problem.

## What changed

- **`viewer/app/usage.js:69-71`** (Spec bullet 1): the per-machine reader now records `cliProblems`. It is `{ kimi: <text> }` when `cliProblem('kimi')` is set, else `{}`. The unreachable branch returns `cliProblems: {}`. The returned shape is `{ reachable, accounts, problems, cliProblems }`.
- **`viewer/app/usage.js:110`** (Spec bullet 2): in the per-account machine value, a Kimi account whose machine is reachable, is not signed in there (`!m.accounts[a.id]`), and has `m.cliProblems?.kimi` now gets `{ state: 'problem', text: m.cliProblems.kimi }`. Otherwise the existing order applies: `signed_in`, then `m.problems[a.id]`, then `signed_out`. Other providers are untouched.
- **`viewer/app/usage.js`** placement and the boolean `accounts` map are unchanged (Spec bullet 3).
- **`viewer/test/app-kimi-settings.test.js:117`**: new test placed directly after the existing two-machine Kimi usage test. Machine `a` is below the floor and has only `default-kimi` in `accounts[]`; Settings has a named Kimi account `k-two`. Both accounts get `{ state: 'problem', text: <floor sentence> }` on `a`, and `signed_out` on `b` (no problem, no entry). The Claude account on `a` stays `signed_in`. It also asserts `machines.a.accounts['k-two']` is `undefined`, so the boolean map is confirmed unchanged.
