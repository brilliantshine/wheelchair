The implementation is incomplete and should not be accepted as finished.

- `machine/adapters/kimi.js:45`: candidate discovery, metadata and role-marker checks, shared binding and persisted log identity; missing executable login refusal at line 90.
- `machine/service.js:369`: one-second non-overlapping Kimi poller; binding, event mapping, offset/watermark and spool gate at line 646; fatal exact-target stop and input refusal at lines 650 and 839; pending archive at line 899; copier identity check and chat binding at lines 977 and 1012; Kimi agent hook ignore at line 1709; recovery classification at line 387.
- `machine/API.md:110`: event and pending-stop contract.
- `machine/test/kimi-turns.test.js:1`: focused unit coverage for binding, event mapping, protocol failure, spool gating, fatal input and copier identity; `machine/test/kimi.test.js:163` adjusts launch/login and adds configuration cases.

The machine suite failed twice in the same launch/login test. The first assertion did not account for shell quoting around `--auto`; the retry corrected that case but still did not account for nested shell quoting around `login`. The worker rules require stopping after the same gate fails twice. The test still fails and the requested machine tests are not complete: in particular restart and crash replay, actual outage and spool delivery, injected clock jumps, 30-second deletion, swap between stat/open, archive pending, HTTP hook ignore, and recovered Claude/Kimi pane cases need coverage. The recovery footer match is provisional and was not checked against a real Kimi pane. The failed error shape was not confirmed against Kimi's journal writer or a real failed turn. Carry-over sibling and stale kill/code cases and the launch `--yolo` assertion remain incomplete. Poller error handling and the remaining edge cases need review before accepting this implementation.
