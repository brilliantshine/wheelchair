# R1 — machine remediation

## Changes and coverage

1. Async version check: startup begins the path-and-mtime keyed check, status returns a checking problem without waiting, and Kimi launch awaits it (`machine/service.js:362`, `:587`, `:1289`, `:1310`; `machine/API.md:108`). Cache invalidation and floor are exercised at `machine/test/kimi.test.js:38`, `:139`; the slow HTTP status and launch test is at `:366`.
2. Approval detection pairs a recognized title with `Approve once` (`machine/adapters/kimi.js:97`; `machine/test/kimi.test.js:355`). Read-only `strings` of the installed Kimi 2.6.3 ELF exposes `headerFor` mapping Bash to `Run this command?`, Write to `Write this file?`, Edit to `Apply these edits?`, TaskStop to `Stop this task?`, and ExitPlanMode to `Ready to build with this plan?`. The shipped `adaptChoices` uses `DEFAULT_APPROVAL_CHOICES` (including `Approve once`) for TaskStop, but `adaptPlanReviewChoices` for ExitPlanMode, whose fallback is `Approve` and whose choices come from plan options plus reject/revise. Thus TaskStop remains recognized; the plan-review title was removed. This is inspection of shipped code, not a newly captured live prompt.
3. Recovery checks the anchored Kimi footer first and sets the lost-track reason (`machine/service.js:397`; tests `machine/test/kimi.test.js:105`, `:359`, `machine/test/kimi-turns.test.js:154`).
4. Machine forces Kimi effort to null before launch and storage (`machine/service.js:595`, `:614`; `machine/test/kimi.test.js:202`, `:235`, `:366`).
5. Same-batch duplicate or older turn IDs are skipped after advancing the handoff watermark (`machine/service.js:725`, `:726`, `:739`; `machine/test/kimi-turns.test.js:243`).
6. A 2.6.3 prerelease is below the floor; later prereleases and release build metadata are handled (`machine/service.js:1313`, `:1314`; `machine/test/kimi.test.js:139`).
7. `authenticated` is internal and omitted from every account on status (`machine/service.js:1285`; `machine/API.md:29`, `:108`; `machine/test/kimi.test.js:275`, `:291`).

Additional fixes: `machine/test/kimi.test.js:371` obtains a free port by probing port 0 and closing the probe, and `:381` asserts the actual HTTP 201; the service port handling is unchanged. `machine/service.js:1297` allows the `kimiVersionTimeoutMs` service option, default 5000 ms. `machine/test/kimi.test.js:155` uses an authenticated fake home and fake executables to prove a timeout with output and a nonzero exit with no output both give the floor problem and ineligible Kimi accounts. The draft approval test was changed only to reflect the shipped plan-review choices. Other draft tests are unchanged.

## Undone

None. The live permission prompt was not recaptured in this attempt; the shipped strings and existing real Bash prompt from verification provide the evidence above.

## Choices

- `machine/service.js`: retain the draft's lifetime cache keyed by executable path and mtime.
- `machine/adapters/kimi.js`: retain the generic `Approve <tool>?` title when paired with `Approve once`, as in the draft and shipped header mapping.
- `machine/test/kimi.test.js`: use a 100 ms injected timeout and emit a valid version before the sleep, proving a timed-out otherwise-valid version is rejected; use a silent nonzero exit to cover the `no output` fallback.
