# T1 — machine account switch

## Changes

- `machine/service.js`: failed resumes mark the switch failed and go through `stopFatal`, including MCP configuration cleanup and Windows stop handling.
- `machine/test/switch.test.js`: model tmux disappearing when testing the fatal-stop path.
- `machine/test/switch-http.test.js`: isolated HTTP route, both real launch preparations, retries, file copies and offset rebinding, failure rollback, hook suppression, readiness outcomes, and plain-start regression coverage. Uses fake CLI/tmux/hub and temporary HOME; the worktree comparison uses an isolated Git repository.
- `docs/plans/account-switchover/reports/T1.md`: this report.

## Results and baseline comparison

Both switch files pass. The final full machine run reports 604 passed, 18 failed: all 18 failures are in Windows tests, and none concerns switching. The 16 `win.test.js` failures are exactly the pre-existing tests identified in the brief. Two additional `win-tool-ready.test.js` failures both report `spawnSync wslpath ENOENT`; that test and its Windows bridge implementation have no diff from `f21cf9f2` (`git diff --exit-code f21cf9f2 -- machine/test/win-tool-ready.test.js machine/lib/win.js machine/lib/win-env.js machine/lib/win-sync.js machine/test/fixtures/win` exited 0). No separate baseline run was performed.

The initial full run also had a `win-tool-proxy.test.js` timeout: it left its test child open, so I terminated that child to let the run complete. The proxy file then passed 21/21 separately, and it passed in the second full run, which was limited to CPUs 0–3 to reduce concurrent load. The final run used the latest tests; the first full run preceded the last additions to the test assertions.
