# T4 report — blocked

The two first-attempt regressions are fixed. The machine Node suite and `machine/test/run.sh` both reported exactly the four baseline failures listed in the brief; the focused forwarding and replacement tests passed. The viewer Node suite reproduced the same two `app-slug.test.js` failures recorded in the first attempt, so I stopped at the second failure of that gate as required by the brief. The browser suite and live relay command were not run in this attempt; no new live-test output is available.

Files changed across the T4 implementation (including the two earlier commits):

- `machine/lib/win.js`: owns the forward instance and restores it during startup; tolerates service doubles without `liveTmux`.
- `machine/service.js`: forwards marked project tools, manages Claude configuration files, exposes Windows status and WSL state; tolerates an unset state directory and normalizes status timeout and exception reasons.
- `machine/test/win-forward-service.test.js`: exercises session starts, forwarding, restart, sweep, status and read integration.
- `machine/test/replace-entries.test.js`: covers replacement and withholding for `constructor` and `__proto__` with objects and Maps.
- `docs/plans/windows-localhost-tools/reports/T4.md`: this report.

|---|---|
