# Map: faster full runs

The build checks changed code with the picker while the sub-lead starts a full run on the verification commit; each remediation commit replacing that run starts another. A passing run gates handoff, and a later uncovered push needs its own run (`protocol/app/sub-lead.md:249-256`, `protocol/app/sub-lead.md:273-283`, `protocol/app/lead.md:119-133`). See `docs/maps/full-test-runs.md` for the implementation and `docs/maps/test-temp-dirs.md` for cleanup.

```text
build commit -> picker and full run alongside verifiers -> handoff -> push
                       | remediation                         | uncovered commit
                       -> new commit and full run             -> full run
```

- The previous plan deferred five items: transitive imports, map-entry validation, per-suite timing, the free-port race, and qualifying repair step 7's full-run phrase (`docs/plans/faster-verification/PLAN.md:327-333`). The picker scans direct relative imports in non-browser test files only; it does not walk their dependencies (`test-support/pick-tests.js:55-74`). Additive map entries preserve fallback, and missing target files are silently skipped (`test-support/pick-tests.js:33`, `test-support/pick-tests.js:76-80`). Its accepted risk also names `<dir>/index.json` and unseen non-import readers (`docs/plans/faster-verification/PLAN.md:349-350`).
- `full-run.sh` runs eight suite entries sequentially and stores only commit and exit codes in summary, with output in per-suite logs (`test-support/full-run.sh:31-71`). A lone full run uses up to six browser workers; other runs use two, to limit load (`test-support/browser-workers.js:7-9`, `viewer/AGENTS.md:57`). Its PID check and registration are separate, leaving the simultaneous-start race recorded as an accepted risk (`test-support/browser-workers.js:50-53`, `docs/plans/faster-verification/PLAN.md:344`).
- Config selects all matching specs for both Chromium and Firefox and sets no global timeout (`viewer/playwright.config.js:12-20`); individual tests can override timeouts (`viewer/test/app-files-followup.spec.js:107`). There are 52 `viewer/test/*.spec.js` files in this checkout. Likely browser-sensitive examples include graph rendering and geometry (`viewer/test/browser.spec.js:259`), touch gestures (`viewer/test/touch.spec.js:7-17`), and pixel sampling (`viewer/test/background-rendering.spec.js:61-70`); these are examples, not an exhaustive classification. Screenshot capture itself may be conditional on Chromium (`viewer/test/app-spot-comment.spec.js:243-244`).
- The probe closes before the viewer binds, allowing parallel starts to claim the same port (`viewer/test/helpers/server.js:15-23`, `viewer/test/helpers/server.js:73-76`). The viewer refuses an unknown holder after `EADDRINUSE` (`viewer/server.js:2287-2310`). Node tests also start servers: `app-new-thread.test.js:184` goes through `withContext` and `setup` to `startServer` (`viewer/test/app-new-thread.test.js:13-15`, `viewer/test/helpers/app.js:24`). The earlier plan reports this failure in both browser and node runs (`docs/plans/faster-verification/PLAN.md:332`).
- Workers do not run the full run; verifiers run Spec commands and picker-targeted checks, skipping picker-selected whole suites covered by the starter (`protocol/app/worker.md:38-40`, `protocol/app/verifier.md:44-54`). The root heading opts in (`AGENTS.md:76-84`); contributing guidance calls for targeted checks and full validation for cross-cutting handoff (`CONTRIBUTING.md:75-93`). Repair step 7 still says “start the full run alongside it unless the commit is covered” without explicitly qualifying that phrase by the opt-in heading (`protocol/app/lead.md:736-741`), as deferred (`docs/plans/faster-verification/PLAN.md:333`).
