## Changed

- `viewer/app/tool-cli.js`: `check` handshakes HTTP folder servers with `httpHandshake`, sending only headers without `${`; skips the live check for `windows: true` tools on WSL. `list` needed no change: `tool.transport` is already on each row.

Loosened the existing Python starter mode assertion (see Choices).
- `machine/lib/project-tools.js`: `folderRows` skips the program check for HTTP servers; new "uses keys" string. `transport` reaches the row through `row.tool`.
- `machine/test/project-tools.test.js`: new string; Git-tree HTTP folder tool test.
- `viewer/pages/project-tools.js`, `viewer/test/app-project-tools.spec.js`: new status strings (the spec file's key-status fixture string too).
- `protocol/tools.md`: HTTP servers section, `--lang`, sandboxed Codex behaviour, and removal of the old statements that HTTP servers stay in `.mcp.json` and sandboxed Codex cannot use keyed or server tools.

New tests were checked by breaking the code once each (placeholder headers sent, WSL skip removed, skip applied off WSL, early timeout removed, `folderRows` skip removed); the matching test failed and the code was restored.

## Not done, or true only after later tasks

- `protocol/tools.md` describes sandboxed Codex over MCP and the WSL Windows behaviour as the Spec states them. T6 and T7 build that behaviour; this branch does not have it yet.
- A stalled HTTP server's `check` prints `The operation was aborted`, not `Server handshake timed out`: `httpHandshake` in `machine/lib/mcp-http.js` (outside my files) sets `timedOut` from a second timer that runs after the abort. Sent to the lead as a message. Suggested fix: set `timedOut = true` in the first timer's callback before `controller.abort()` and drop the second timer.
- `protocol/tools.md` was reviewed as Markdown source and diff, not in a graphical renderer.
- The WSL skip was not run on a real WSL machine.
