# T2 — lead-order Save, sign-in handoff, one-line account usage

## What changed

`viewer/pages/settings.js`
- **Shared draft (S1).** `saveBalancing` (`:1765`) sends its box's keys and refreshes only those in the draft, takes `reserved_provider` from the response and repaints both boxes. The save route already returns it (`viewer/app/routes.js:324`). `reserveTexts` and `readReserved` (`:1786`, `:1797`) re-read the provider on opening Usage and balancing (`:1435`) and change only the words, in place. A Save outdates a read still on its way.
- **Sign in once (S2).** A Harnesses row's "Sign in" is a link (`signinLink`, `:2227`) that opens the sign-in card for the Harnesses machine inside that provider's account group (`:1710`) and scrolls there. `openSignin` (`:1463`) no longer mounts in a Harnesses row. `signinAccount` (`:2211`) only picks an account that has a card. "Open Accounts" / "Add an account" are as before.
- **Status reload (S2, Check Once Built #1).** `refreshStatus` (`:1421`) reads `/harnesses?fresh=1` first, which drops the hub's 15-second machine cache, then `/usage`. It runs when a sign-in card closes (`:1458`) and after every account change (`:1580`, `:1658`). No server change was needed. `refreshUsage` (`:1408`) ignores an answer older than its newest request.
- **One usage line (S2).** `usageLine` (`:1562`) replaces the account cards' two bars.
- **Harness switch (S5).** `setHarness` (`:2190`, `:2202`) repaints Accounts at once unless an account edit is open (`accountsBusy`, `:1402`).

`viewer/pages/settings.css`: bar styles for account cards removed; `.prov-signin`, `.acct-usage`, and a scroll margin so the sticky header does not cover the provider heading after the handoff.

Tests: new checks in `viewer/test/app-settings.spec.js:801`; `viewer/test/app-harnesses.spec.js` now expects the link and the card in the account group. `app-accounts.spec.js` needed no change.

Each new check was run once against a deliberately broken build and failed, then the code was restored: link ignores the machine; a bar added to the card; a Save resets the whole draft; a Save ignores `reserved_provider`; no re-read on entry; the switch leaves Accounts alone; the switch repaints over an open edit; closing sign-in reads only usage; harness and usage reads run in parallel; a late usage answer is kept; an account change skips the status reload; Add account skips it.

## Choices

- Following the Harnesses link opens the sign-in card straight away for the provider's first usable account, rather than only scrolling there (`settings.js` `signinLink`).
- A card opened by that link sits inside the provider's account group; a card opened by an account's own Sign in stays at the top of Accounts as before (`openSignin`, `renderAccounts`).
- Usage line wording: "5-hour 42% used · week 61% used · as of 14:00", without reset times; a window with no reading is left out, and "no reading yet" when neither exists (`usageLine`).
- Status is reloaded when a sign-in card closes (2 s after "Signed in.", or on Close), also when it was closed without signing in (`closeSignin`).
- Rename and plan changes reload the status too, since they share one path with pause and remove; the cards repaint first as before, then again with the fresh status (`mutate`).
- With an Add account form open, a harness switch repaints Accounts only when the form's chosen provider was switched off (the existing tested reset); otherwise it waits (`setHarness`).
- A usage answer older than the newest request is dropped, so a slow earlier reading cannot undo a sign-in (`refreshUsage`).
- Re-reading the reserved provider rewrites the three labels in place, so focus in a number field is not lost (`readReserved`).
- The existing rule that an open sign-in card stops the post-install version re-reads is kept; only its comment changed (`refreshAfterInstall`).
