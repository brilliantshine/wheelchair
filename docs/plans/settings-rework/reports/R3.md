## T3 — Refresh the background editor while You is visible

`viewer/pages/settings.js:1960` and `:2063` gate editor repaints on `youShown()`. The background controller still refreshes the saved page-wide image. `backgroundrestore` discards the visit, and the next visible sync rebinds its controls if needed. `viewer/pages/settings.js:2480` runs that sync after navigation, at the phone breakpoint, and at load. A valid editor visit refreshes only when the saved state differs from what it last rendered and it has no dirty or pending pick.

`viewer/test/app-settings.spec.js:832` saves an image at 35% in a 390px viewport, goes back through `.back`, and saves 42% through the hub. It verifies the new opacity on the page and the original node behind the list. It reopens with `.cat-link[data-category="you"]` and checks 42%. A second trip through the list checks node identity across `backgroundrestore`.

## Choices

- `viewer/pages/settings.js` uses the top of the visible card as the anchor for every earlier block. It uses the sticky navigation edge and viewport bottom to determine visibility.
- `viewer/pages/settings.js` shares one background sync between controller updates and navigation. Restore invalidates the visit, and the first visible sync rebinds it.
- `viewer/test/app-settings.spec.js` reproduces the second press after a 409 and disables native scroll anchoring so the check measures the page's scroll adjustment directly.
- `viewer/test/app-settings.spec.js` exercises refresh and restore on separate trips through the list so restore cannot mask a stale editor on the first reopening.
