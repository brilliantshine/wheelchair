# R1-R6 — settings-rework remediation 1

## What changed, per task

**R1 — bars in Usage and balancing.** `viewer/pages/settings.js:1861`: the "5-hour used" and "Week used" cells draw a 90px meter beside the percentage, labelled "N% of the 5-hour window used" / "N% of the week window used", 0 once the window has reset; a missing window stays "–" with no bar. Style: `viewer/pages/settings.css:209`. Account cards are unchanged. Check: `viewer/test/app-settings.spec.js:884`.

**R2 — Add account flake: a real cause, fixed.** Reproduced before any change: `--project=firefox -g "warns once|does not warn" --repeat-each=30 --workers=8` gave 3 failed, 117 passed (one lost "Save", two lost clicks further along the form flow). A temporary event log (not committed) showed the sequence:

```
860 pointerdown BUTTON#add-cancel "Cancel" @1185,832 sy=1136
866 paint harnesses h=472 sy=1136 addTop=1053        (was 707)
871 pointerup  DIV.models accounts @1185,832
871 click      DIV.models accounts @1185,832
```

Harnesses (above Accounts since the rework, and entirely off screen here) answered between mouse-down and mouse-up, grew by about 350px, and moved Cancel from under the press. Browser scroll anchoring did not compensate. No stale `adding` and no repaint of Accounts was involved. Fix: `holdPlace` (`viewer/pages/settings.js:2380`, used at `:2395`): when a block wholly above the screen repaints, the page scrolls by however far the next block moved. The same instrumented run after the fix, 60 repeats of the two desktop tests: 120 passed. No timeout or retry changed. Deterministic check: `viewer/test/app-settings.spec.js:907` (holds the Harnesses answer until the button is pressed, with browser anchoring off).

The separate `:262` "does not warn" failure has the same shape (a Save with no effect); it reproduced once in the first run and not after the fix.

**R3 — surfaces flake: the test was wrong.** The old check listed elements (`surfaces.all()`), then resolved and measured each in later round trips. A block repaint in between (Harnesses answering or an install poll) detaches the node, and a detached node's computed background is empty, so it reads as "no opaque ancestor". Evidence: with a temporary 60ms gap added between resolving and measuring, Chromium failed 1 of 10 with

```
Received: "detached <div class=\"box h-rows\"><div class=\"h-row\" data-provider=\"claude\"><div class=\"h-head\"><div class=\"h-name\"><strong>Claude"
```

On screen there is no such gap: `replaceChildren` swaps the old view for the new in one step. So the page was not changed for this; the check now finds and measures in one step inside the page (`viewer/test/background-settings-surfaces.spec.js:13`, `:57`). It still fails on a really bare surface (broken once by making `.harnesses > *` transparent). The original failure itself was not captured, so this is the mechanism that produces its exact message, not a replay of that run.

**R4 — Diagrams read when You is shown.** `viewer/pages/settings.js:171` `syncDiagrams` reads when You goes from hidden to shown (called on load, hash change and the 899px change, `:2469`-`:2483`); painting the block no longer reads. Only the newest read's answer is kept (`:159`). Check: `viewer/test/app-diagram-sensitivity.spec.js:55`.

**R5 — test name.** `viewer/test/app-settings.spec.js:637` is now "Models fits at 390px" (it opens `#models` only).

**R6 — preview panes and Visibility.** `viewer/pages/settings.css:127`-`:128`: panes have no fill or blue outline, 12px padding, 8px radius and gap, as the mockup. `:325`: Visibility is the browser's default short track on its own line (overrides the full width set in `background.css`, which is not in this task's files). Check: `viewer/test/app-settings.spec.js:623`.

Each new or rewritten check was run against a deliberately broken build and failed, then the code was restored: bar ignores a reset window; no bar; no hold on repaint; no re-read on hash change; read while hidden; no resize listener; filled "with" pane; full-width slider; transparent Harnesses surfaces.

## Choices

- The hold applies to any block repainted wholly above the screen, not only Harnesses; a block even partly visible still moves what is below, as before (`settings.js` `holdPlace`).
- Between 640px and about 900px the table columns are too narrow for bar and number side by side, so the number wraps under the bar (`settings.css` `.meter`).
- Diagrams shows "Reading each machine…" while re-reading, not the previous answer (`settings.js` `syncDiagrams`).
- Returning to the browser tab does not count as You becoming visible (`settings.js` `syncDiagrams`).
- Only the panes' box and the compare gap follow the mockup; pane text size and the two-column layout on wide screens are unchanged (`settings.css` `.pane`).
- The surfaces check is rewritten as one in-page measurement instead of one assertion per element (`background-settings-surfaces.spec.js`).
