# T1 — Settings page shell, categories, blocks and phone navigation

## What changed

`viewer/pages/settings.js`
- Eight categories with titles, phone-list lines, ledes and blocks (`:11`), old-key aliases (`:22`).
- Former sections and groups are separate blocks (`:499`-`:660` for You, Models, leads and Threads; `BLOCKS` `:2282`). `paint(...names)` (`:2296`) rebuilds only the named blocks in the open category; `renderCategory` (`:2308`) builds a category once per visit. Every former whole-panel rerender now paints its own block.
- Lead provider order is its own box above Balancing (`:1844`), Balancing is `:1818`. Either Save works as before (rebuilds both from saved values, `:1745`).
- Live work follows its controls: `syncSection` (`:1413`) runs Harnesses polling in AI providers, the 30-second readings in AI providers and Usage; `refreshUsage` (`:1399`) repaints Usage bars and Accounts separately, Accounts still waiting on an open edit. Diagrams read and draw happen when the You block paints; the background editor is tied to the You visit.
- Phone list and back link (`:2320`), hash parsing and visit changes (`:2341`, `:2350`). Harnesses links go to `#usage`; the Accounts links scroll to the Accounts block (`:2166`).

`viewer/pages/settings.css`
- 899px layout: side navigation hidden, category list, "‹ Settings", rows stack (`:134`-`:155`); the old 640px tab strip is gone.
- Mockup styling: Diagrams radio circles (`:235`), plain "Covers:" line, Never say box, narrow Lead names select, empty status lines take no room (`:326`); solid backdrops over a background image for the new headings (`:322`).

`viewer/pages/settings.html`: unchanged.

Tests: hashes and selectors moved to the new keys in the specs listed under Validation; new `categories` checks in `viewer/test/app-settings.spec.js:630`; the old section-list and tab-strip tests replaced by category order and no-sideways-scroll tests. Each new check was run against a deliberately broken build and failed (category title, block placement, alias, lesson address, phone list CSS, whole-category repaint, rebuild on resize), then the code was restored.

Not done here (T2): the lead-order save semantics, S2, and rebuilding Accounts on a harness switch. Until T2, switching a harness or acting on an account does not repaint the other block on AI providers at once (Accounts catches up on its 30-second refresh).

## Choices

- Old-key and unknown-key addresses are kept as typed, not rewritten (`settings.js` `parseHash`).
- Ledes without a mockup: AI providers "The agent programs wheelchair runs and the logins they use.", Usage and balancing "What is left this week, and how agents share it.", Models "Who runs what.", Agent behavior "How agents work, and what they have learned."; Project tools keeps its own heading and lede. Phone-list lines are the mockup's.
- Block headings: "Your name", "Writing style", "Diagrams", "Enter to send", "Background Customization" (mockup wording), "Conversations" (mockup), "Threads", "Permission mode", "Lead names", "Leads", "Lead order", "Harnesses", "Accounts", "Usage", "Behavior templates". Provider headings inside Accounts became `h3` at the same size.
- "Open Accounts" / "Add an account" use `#providers` and scroll to the Accounts block (`settings.js` `accountsLink`).
- On a phone with no hash, You is built behind the list (CSS shows one or the other), so crossing 899px rebuilds nothing; going from a category to the list counts as leaving it (discards a background preview, stops its polling).
- A hash change within the same category rebuilds nothing; two background tests that expected a rebuild now expect the same editor.
- "Saved" notes sit under the category lede (You, Models, leads, Threads); Lead order and Balancing each show their own Save's note (`boxNote`).
- Either Usage Save still discards the other box's unsaved edits, as one shared reset did before; both boxes repaint so the screen matches what the next Save sends. T2 replaces this.
- Diagrams choices, "Covers:", Never say and "In your own words" (count moved below the box) were restyled to match the You mockup, at every width.
- The Lead names section and the Your name section are not named regions, so their control's label stays unique.
- Test-only: `app-harnesses.spec.js` navigates by hash (a phone has no side navigation) and its switched-off-account test now stubs the switch in the harness status too, which the same page now reads; `app-send-now.spec.js` opens `#you` for the Enter-to-send switch.
