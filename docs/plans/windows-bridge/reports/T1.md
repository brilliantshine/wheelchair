# T1 — Windows bridge environment and sync

Implemented the standalone environment and copy/sync modules; no service wiring was changed.

- `machine/lib/win-env.js`: WSL detection and interop environment, PowerShell and Git runners, path conversion, version checks and copy paths, rewritten for readability.
- `machine/lib/win-sync.js`: copy initialization and seeding, raw-byte bridge indexes and snapshots, merge and conflict refs, unresolved-path masking, guarded application and retry, state, copy deletion and per-copy serialization.
- `machine/test/fixtures/win/`: PowerShell protocol and Windows Git fakes with path translation and fault injection.
- `machine/test/win-env.test.js` and `machine/test/win-sync.test.js`: environment, synchronization, conflict, failure, ignored and tracked file, bytes, seeding, deletion and serialization coverage.

The real WSL smoke created the copy under `t1-smoke`, edited the file through Windows PowerShell, verified the Linux result, and removed the copy and empty smoke directory. The focused suite passed. The machine suite has exactly the pre-existing Kimi login failure called out in the brief; its other 461 tests passed.

## Choices

- `win-sync.js` seeding: enumerate source ignored files with `git ls-files --others --ignored --exclude-standard -z`, then filter through the new worktree's `check-ignore`.
- `win-sync.js` deletion: remove the copy from Linux through the mount with `fs.rmSync`.
- `win-sync.js` application: use separate temporary trees for masked Linux and Windows paths while retaining the masked merge result as the common base; persist unresolved paths before applying, so an interrupted conflict checkout preserves masking.
- `win-sync.js` ignored paths: preserve paths tracked in the Linux real index during the Windows ignored-path removal step. The copy's ordinary index is empty, so treating those paths as untracked on that side causes a force-tracked ignored file to disappear on a later sync. Asked the lead to review this interpretation of D83.
- `win-sync.js` conflict classification: inspect the three versions' file modes and first 8,000 bytes for NULs to distinguish ordinary text conflicts; non-regular, absent, and binary entries take the Linux version.
- `win-sync.js` conflict refs: use an ISO UTC timestamp plus random suffix to avoid collisions.
