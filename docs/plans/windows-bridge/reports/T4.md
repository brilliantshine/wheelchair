# T4 — Windows bridge service wiring

## Changes

- `machine/service.js`: construct and start the bridge, run its sweep, route agent calls, prepare Windows MCP tools and environment, connect stop and worktree removal hooks, and wait for final reconciliation during archive.
- `machine/lib/project-mcp.js`: remove Windows-program entries from all returned adapter inputs on non-WSL while returning the names to disable Claude's implicit project-file loading; honor a configured WSL mount.
- `machine/lib/win.js`: coordinate asynchronous stop and removal; account for stop work during archive; skip non-WSL cleanup; keep launches available when Windows path discovery fails; bound preparation including path discovery.
- `machine/API.md`, `machine/AGENTS.md`: document the route and bridge files.
- `machine/test/win-service.test.js`: exercise route authorization, filtering, startup and environment, readying deadline, cleanup and archive using fake WSL roots and PowerShell/Git fixtures.

## Remaining work / blocker

The full machine run below was executed before the mock-instance compatibility fixes. Its Kimi mock failures were subsequently fixed and the targeted Kimi run shows only the known pre-existing login failure. The machine suite also exposes an additional failure in `machine/test/service.test.js` on this WSL host: its old default command assertion expects no Windows environment, and its fixture uses the real WSL/PowerShell environment. That file is outside T4's ownership boundary. I asked the lead to extend the boundary so its service helper can use fake non-WSL roots; the full suite has not been rerun because that assertion is known to fail again until the fixture is corrected. The viewer failures match the two known failures in the brief. The first focused test run failed because its test timeout was applied to normal readying; correcting the test setup made subsequent runs pass.

## Choices

- `machine/service.js`: use `options.win` for injected bridge options and fake roots.
- `machine/service.js` and `project-mcp.js`: parse the project file a second time on non-WSL to determine whether it contains Windows tools, and pass the detected mount to program detection.
- `project-mcp.js` and `service.js`: return filtered-out names separately and explicitly disable those entries in Claude settings, which otherwise reads the original `.mcp.json` itself.
- `win.js`: track asynchronous stop tasks so archive and worktree removal do not race copy cleanup; do not count a pending stop as an already-attempted archive reconcile.
- `win.js` and `service.js`: bound path discovery within the same launch time budget and proceed without Windows environment if discovery fails or times out.
- `service.js`: tolerate absent bridge on partial `MachineService` test doubles created without its constructor.
