# T5 — Windows live check: blocked

The non-Unity live check passed. The Unity gate failed twice, so I stopped without a third attempt. The first attempt passed the supplied Linux path directly to `win start`, which requires a Windows path; I changed the harness to translate it with `win path`. The second attempt launched Unity, but the initial batch import exited 198. Its project-relative Editor log was inside the temporary copy, which cleanup deleted; the remaining global Editor log confirms the intended executable and arguments but does not explain exit 198. No Unity tests or Editor screenshot were reached. The Unity section and final cleanup fallback have not passed a complete live run.

Changes:

- `machine/test/windows-live.sh` and `machine/test/windows-live.js`: isolated systemd service, hub session, real CLI calls, PNG pixel decoding, Windows and Unity scenarios, and cleanup. Screenshot files survive in `/tmp` for inspection.
- `machine/test/fixtures/unity-min/`: minimal Unity EditMode fixture, with no ProjectSettings.
- `protocol/app/worker.md`, `protocol/app/verifier.md`, `README.md`: Store-packaged app limitation.
- No bridge bug fix: the initial launch failure was a harness path error; the cause of Unity's exit is not established.

I opened all three WinForms screenshots. They show the uniquely titled window with a blue interior and normal window chrome:

- `/tmp/wheelchair-windows-live-59d28fb9645a-winforms.png`
- `/tmp/wheelchair-windows-live-c1c9dfd40351-winforms.png`
- `/tmp/wheelchair-windows-live-c52a0ed462ab-winforms.png`

All three Windows copy directories were empty after archive and were removed, and no `wc-win-live-*` units remained. The screenshot and other Unity checks could not run. The machine and viewer suite failures match the known base-branch failures in the brief.

## Choices

- `windows-live.js`: use a random per-run ID for the service unit, thread and window title, and retain screenshots under `/tmp`.
- `windows-live.js`: convert a `/mnt/` Unity executable path through `win path`; pass a Windows path through unchanged.
- `unity-min/Packages/manifest.json`: use test-framework version `1.4.5` for the minimal fixture.
