# R1 — Windows-side tools in Codex

- `machine/adapters/codex.js`: on WSL, add both bridge environment names to Windows stdio entries' existing passthrough names, without duplicates; normal override size accounting includes them.
- `machine/service.js`: pass detected WSL state and mount into the adapter context.
- `machine/test/project-mcp-codex.test.js`, `machine/test/win-service.test.js`: cover passthrough merging, deduplication, non-Windows and non-WSL cases, and the fake WSL service launch command.
- `README.md`: document automatic forwarding and `WSLENV` for hand-run tools.

Antigravity was not installed (`command -v agy` returned no path). Its adapter omits same-name passthrough entries because it expects stdio servers to inherit the CLI environment; the captured fixtures do not establish MCP inheritance, but `docs/plans/project-tools-solid/PLAN.md` decisions 16 and §4 record a live verification on agy 1.5.11 that stdio servers inherit the whole environment. No Antigravity change was made. Kimi remains unchanged.

The live Codex tool call succeeded twice and returned the requested path, but the scratch wrapper exited 1 twice: its first assertion expected unescaped backslashes in JSON-formatted output, and its revised assertion expected escaped backslashes when Codex emitted plain text. Per the two-failure rule no third run was made. Both temporary Windows PowerShell scripts were deleted. The two broad suites failed only in the pre-existing tests named in the brief.
