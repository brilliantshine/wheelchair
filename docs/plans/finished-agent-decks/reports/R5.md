# R5: keep the page scroll across the Agents refresh

Remediates verification attempt 4 (gap G5, Collin's Decision 17). The Agents page now restores its page scroll on every five-second refresh when the lead and the selected agent are unchanged, not only when an agent is selected. An open deck popover is placed again against the restored deck position.

## What changed, by file

- `viewer/pages/agents.js`
  - Line 6: `lastLead = null` appended to the module-level `let` list.
  - Line 246: the restore block is replaced. The side-panel scroll restore stays under the selected-agent check. The page scroll restore now runs when `lead.thread_id === lastLead && selected?.name === kept.agent`, including when no agent is selected. Then `lastLead = lead.thread_id;` and `placePopNow?.();` run.
- `viewer/test/app-agents-decks.spec.js`
  - New case, phone only (`test.skip(label !== 'phone')`): "page scroll and an open popover survive a refresh with no agent selected". It builds 12 live workers and a 40-reviewer deck, scrolls the deck to centre, records `scrollY` (asserted greater than 0) and the popover top, clicks the deck, waits 5500 ms, then asserts the popover is open, `scrollY` is within 2px, the popover is inside the viewport with 8px margins, and its top is within 2px.
- `docs/plans/finished-agent-decks/reports/R5.md`: this report.

## Choices

- `viewer/pages/agents.js` `lastLead`: initialised to `null` and set on every render, so the first render after load never restores a scroll it did not have.
- `viewer/pages/agents.js`: `placePopNow?.()` runs on every render, not only when an agent is selected, so an open popover is always re-placed after a refresh. This is what the brief's last sentence describes.
- `viewer/test/app-agents-decks.spec.js`: the new case is titled "page scroll and an open popover survive a refresh with no agent selected", and it asserts the popover is still open with `toHaveCount(1)`. The brief did not name a title or an assertion form.
