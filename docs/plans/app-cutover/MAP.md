## Install and existing homes

`install.sh` first refuses noncanonical worktrees, determines Claude and Codex presence from PATH or the test seam, and fails if neither is present (`install.sh:19-47`). For each present harness it removes `spine` only when the installed file contains this checkout's exact `protocol/spine.md` path; Claude removes the whole skill directory, Codex the prompt file. A foreign wrapper or one rendered from another checkout survives (`install.sh:77-86,98-99`; `install/test/run.sh:283-293`). The five retired commands need mappings from wrapper names to protocol names: plan/planning, adopt/adopt, plan-review/plan-review, implement/implementation, verify/verification (`skills/AGENTS.md:17-21`). The existing single-name `spine` test is not sufficient for those differing names or a moved canonical checkout.

The installer globs `skills/*/SKILL.md` and `codex/prompts/*.md`, substitutes the absolute checkout path for `{{WHEELCHAIR_ROOT}}`, clears old symlinks, and writes present homes; deleting source wrappers alone leaves installed copies (`install.sh:73-105`). It initializes Codex models, then calls `seen/set.sh` and `sensitivity/set.sh` in that order; each failure warns and installation continues (`install.sh:107-135`).

`seen/set.sh` installs one `UserPromptSubmit` command group in Claude `settings.json` and Codex `hooks.json`, with harness and `notice` arguments. It adds Claude's `Bash(<root>/seen/wording.sh:*)` permission and wording-directory `sandbox.filesystem.allowWrite`; Codex gets that directory in `[sandbox_workspace_write].writable_roots` in `config.toml` (`seen/set.sh:41-52,80-82,152-211,220-280,282-303`). Both currently use notice mode. The hook brings confirmed wording and a four-hour session gap notice to ordinary turns; it skips marked lanes and Claude subagents (`protocol/seen.md:143-175`). The separate append-only plan record template delegates its rules to the removed protocol (`protocol/templates/SEEN.md:1-12`).

Clean removal must filter each matching handler out of mixed groups, retaining unrelated handlers and dropping only empty groups; also filter the script permission and the wording-directory entries from both grants while preserving other JSON keys, hooks and TOML contents (`seen/set.sh:101-150,196-211,216-280`; `protocol/seen.md:189-210`). Ownership currently recognizes the current root, another checkout with `protocol/seen.md`, or a path under app worktrees (`seen/set.sh:84-99`): deleting that protocol before detection makes an older non-current checkout without the file unrecognizable. Directory grants carry no ownership marker and may predate installation: the installer appends only if absent, so their provenance cannot be inferred from the resulting config (`seen/set.sh:208-209,268-274`). The existing writer validates all input before writing, refuses malformed JSON/TOML and unsupported TOML shapes, and uses per-file temporary replacement (`seen/set.sh:66-78,110-132,220-280,305-328`; `protocol/seen.md:212-220`). Cleanup needs an explicit policy for these ambiguities and failures; simply dropping the call leaves dead commands and grants.

## Sensitivity and retained app rules

The dial reads the marked region from `protocol/sensitivity.md` and selects present Claude `CLAUDE.md` and Codex `AGENTS.md` (`sensitivity/set.sh:5-26`). It validates markers, refuses a nonempty Codex override or conflicting existing levels, resolves the requested or existing level (default otherwise), substitutes the root and level, then replaces only the region or appends it; it prepares backups and rolls back prior targets on a failed rename (`sensitivity/set.sh:153-193,210-263`). The rendered ask carve-out names `protocol/planning.md` (`protocol/sensitivity.md:32-35`); the test names it in a comment and a landed-region probe (`sensitivity/test/run.sh:225,264-266`). The source region is also rendered into root `AGENTS.md:1-20`; installed global files are external copies. D42 retains the dial and retargets it to app diagram rules (`docs/plans/app-shell/PLAN.md:85,656-662`); the app lead already follows the dial and uses graph rules plus the diagram card (`protocol/app/lead.md:393-407`; `protocol/app/cards.md:206-229`).

App roles do not directly reference any of the removed protocol files; their router says each role stands alone and app sessions use Settings style instead of the old wording hook (`protocol/app/AGENTS.md:3-6,23-27`; `protocol/app/lead.md:31`; `protocol/app/aside.md:20`). The mapper independently specifies flow, plain-text diagram and file:line evidence (`protocol/app/mapper.md:24-55`); sub-lead owns app worker briefs, tiers and verification (`protocol/app/sub-lead.md:45-49,96-101,186-201`). Thus removing old files does not break a direct app-role import, but it does discard the old universal human-writing guidance (`protocol/writing.md:1-5,18-25`) and headless lane invocation, credential and hook-marker rules (`protocol/lanes.md:3-20,33-44`); determine which, if any, are still intended beyond the app-specific replacements. `codex/preflight.sh` has no removed-file reference, and app role startup uses `wc.js` session management rather than that file (`protocol/app/cards.md:375-392`). Machine sessions and previews still set `WHEELCHAIR_LANE=1`, as do asides (`machine/service.js:490,956`; `machine/lib/aside-turns.js:73`); the marker currently suppresses the seen hook, so those are residual hook-related behavior, not a dependency on the removed file. Settings describes replacing the wording list (`viewer/pages/settings.js:726`).
