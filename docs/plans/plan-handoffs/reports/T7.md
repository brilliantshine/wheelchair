## Built

- `viewer/app/threads.js:123`: Imported lead restart builds context, removes stale context while transferring other queued messages, cleans up orphan lead sessions, saves a pending record before start and delivers as soon as the lead can accept it. It inspects a recorded checkout when `checkout_sha` exists and clears the path if the machine reports it missing. The merge watcher observes the imported PR cutoff.
- `viewer/app/sessions.js:277`: Starts the same pending record, forwards the checkout SHA and registers the plan after the worktree is recorded; registration failures are logged without failing a start.
- `viewer/app/hub.js:54`: Repairs partial imported lead starts and registers plans at startup, logging registration failures per thread. A machine result saves `first_message`; a live `starting` lead without it is marked ended.
- `viewer/app/handoff.js:105`: PR lookup limits imported done cards to after import and falls back to the carried URL, including export status and file construction.
- `viewer/app/chat.js:134`: Replaces the import marker in transcripts and applies the imported PR cutoff while preserving ordinary chat lookup behavior.
- `viewer/test/app-handoff-restart.test.js:1`: Covers the PR cutoff and merge watcher, startup repair and subsequent restart, registration failures, pending-save ordering, stale-context filtering, orphan queues and refusal, checkout inspection, first and later context markers, transcript replacement and immediate delivery.

## Remaining

None within this task's boundary. The page task owns the dead-lead panel condition: allow an imported thread with no live lead even if no lead was ever started.

## Choices

- `hub.js`: Recognise an unsaved start result by `status: starting` and absence of `first_message`; that field is added after the machine start returns.
- `threads.js`: A lead counts as started after import when it has `first_message` and `created_at` is strictly later than `imported.at`.
- `threads.js`: Discard queued messages with `source: context` when transferring queues; the fresh context replaces them, and other messages retain their order.
- `handoff.js`: Use `created_at`, falling back to `at`, as the done card creation timestamp; the import cutoff is strictly greater than `imported.at`.
- `sessions.js`: Register the plan on every lead start with a slug and recorded worktree, catching and logging registration failures.
