## Choices

- `viewer/app/routes.js`: upload content-length is checked before looking up the thread.
- `viewer/app/routes.js`: the upload counter is released after the response is piped and completes or closes.
- `viewer/app/handoff.js`: `GET /handoff` returns 404 when the thread is not handed off.
- `viewer/app/handoff.js`: history records use `who: "app"` for system cards and `"lead"` for other shown cards.
- `viewer/app/handoff.js`: a card's history time is `created_at || at`.
- `viewer/app/handoff.js`: accepted history kinds use a hard-coded KINDS list.
- `viewer/app/handoff.js`: a locally invalid file produces 500 `Could not build the handoff file` before push.
- `viewer/app/handoff.js`: open questions render `withdrawn` in carried history.
- `viewer/test/helpers/app-machine.js`: an unscripted handoff action returns a scripted failure.
- `viewer/app/handoff.js`: answer time comes from the thread's sent press, then `resolved_at`, then `card.at`.
- `viewer/app/handoff.js`: without an answered IDEA.md anchor or `imported.at`, any answered question blocks the idea-confirmed point.
- `viewer/app/handoff.js`: filenames strip a trailing separator after the 60-character cut; history uses newline-separated text.
- `viewer/app/hub.js`: status cache records the last attempted refresh time separately from its last successful value, preventing repeated calls after failures during the 60-second interval.

The revoke-list format is the sub-lead's settled JSON array of entries, with a missing or malformed list treated as empty.
