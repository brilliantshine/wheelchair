# T1 — machine handoffs

## Built

All eight milestones were implemented and committed with green machine gates. The subsequent review corrections are included in this branch.

- `machine/service.js:43` normalizes supported GitHub origins. `machine/service.js:1214` fetches exact remote branch refs into tracking refs; `machine/service.js:1226` validates handoff inputs and takes the archive lock before the repository queue; `machine/service.js:1506` exposes the hub-only route.
- `machine/service.js:1268` implements status, push, inspect, claim operations, local branch updates, known, running, kill and reopen. `known.checked_out` is an array containing all absolute checkout paths. Inspect accepts the machine checkout path after archive and falls back from missing or invalid worktrees to the local branch then the supplied head. Status validates GitHub pull request URLs and passes a separator to `gh`.
- `machine/service.js:217`, `machine/service.js:252`, `machine/service.js:342`, `machine/service.js:561` and `machine/service.js:778` implement cancelled starts and durable archiving/archived markers, including clearing the in-progress marker on archive failure.
- `machine/service.js:442` adds the ordered remote-branch worktree paths, upstream configuration and archive ownership.
- `machine/test/service.test.js:1393` covers normalization, handoff validation, fetch, status, push, inspect, claims, local branches, session cancellation, archive markers and imported worktrees. Tests include archived or missing checkouts, `gh` argument protection, moved claim dates, wrong-branch destination folders, starting sessions, and marker persistence before a forced stop failure. The fixture restores its environment if listen fails (`machine/test/service.test.js:59`).
- `machine/API.md:15` and `machine/API.md:36` document the handoff endpoint and all action request and response shapes, including the checkout array.

## Choices

- `machine/service.js`: Store ownership in `archive-markers.json` and serialize marker writes to avoid lost cross-thread updates.
- `machine/service.js`: Return a null current branch for detached HEAD in status, allowing the caller to reject it.
- `machine/service.js`: Identify orphaned checkout ownership by the machine's thread-branch or session-name directory conventions.
- `machine/service.js`: Use Git's NUL-delimited porcelain output to preserve unusual characters in checkout paths.
- `machine/service.js`: Derive the standard thread checkout path from the checked project directory's basename, matching the hub's project naming.
- `machine/test/service.test.js`: Restore the fake-command environment after a failed listener setup so a port collision cannot contaminate subsequent tests.
