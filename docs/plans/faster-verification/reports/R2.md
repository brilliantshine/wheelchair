# R2 — wording remediation

## Changes

- `protocol/app/verifier.md`: Spec validation commands may name whole suites; the prohibition now applies only to suites named by neither the picker nor a Spec validation command.
- `protocol/app/sub-lead.md`: Deferred-finish and resume paths require a passing full run for the reported commit in opted-in projects.
- `protocol/app/lead.md`: The after-done path requires a full run for an uncovered merge commit before pushing.

## Final changed passages

`protocol/app/verifier.md`:

> Spec validation commands as written, plus the commands the picker prints for the picker base
> (`--base <picker base> --head <the commit you check>`). Never run the full-run command, or a
> whole suite that neither the picker nor a Spec validation command names: a Spec command always
> runs as written, even when it is a whole suite. A whole suite the picker selects is skipped,
> because the starter's full run covers it on the same commit; say so in your report, name the
> picker base, the comparison commit and the picked commands.

`protocol/app/sub-lead.md`, resume rule:

> contains `Deferred and finished at the user's choice` (or the older form
> `Deferred and finished at Collin's choice`), send the done result described below and
> do nothing else. In an opted-in project, send that done result only once a full run has
> passed for that commit; run it first if the Log does not show one. If your brief carries
> that choice, save those rows with that
> Log line, commit and message the lead, then send that result without a new attempt.

`protocol/app/sub-lead.md`, step 4a:

> the rows with `Deferred and finished at the user's choice` in the same commit, messages
> the lead, and sends a build `result` with outcome `done`, that commit, and a summary
> saying the gaps were deferred at the user's choice, with no further verification. In an
> opted-in project (step 3), the full run must still have passed for that commit (step 4);
> if it has not, run it first and treat a failure as in step 4.

`protocol/app/lead.md`:

> updated the pull request branch), merge them with `wc.js git merge` and re-verify
> first (with a `Test picker and full run` heading, the merge commit also gets a full run
> unless it is covered, and the push waits for it to pass). Then push with `wc.js git push
> -u origin HEAD:wc/<thread-id>`.
