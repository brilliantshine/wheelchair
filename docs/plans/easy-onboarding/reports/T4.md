# T4 — Settings Harnesses section and home checklist (S4, S5)

## Files changed
- `viewer/pages/settings.js` — new first section **Harnesses** (`#harnesses`): machine picker, per-harness rows (state, Use switch, Install / Try again / vendor link / Sign in / Open Accounts), old-service line, "Agents can't start yet" notice with `#usage` / `#models` links, install polling (2 s, outage handling, 404 no recipe, 409), 5 s retry while the machine is unreachable, inline switch-off confirmation, 409 message under the row, sign-in card mounted under the row (`openSignin` takes an optional harness argument; closing it re-fetches `/harnesses?fresh=1`), fresh re-fetch on entering the section and after every order save. ## Choices
- Default section stays Models and preferences (Harnesses is first in the list, not the landing section); existing tests depend on that. `settings.js` `readHash`.
- Switch-off confirmation is inline buttons ("Leave it out" / "Keep"), not `window.confirm`, for phone use. `settings.js` `harnessRow`.
- Install button shown only when `recipe === true`; `recipe: null` or missing offers no Install or Try again. `settings.js` `harnessRow`.
- A sign-in card opened from a row is tied to that row's machine and provider; it hides if the picked machine changes. `settings.js`.
- Hidden (switched-off) providers stay in the saved order; editing an order appends them after the visible ones, before `any`. `settings.js` `orderEditor`.
- Checklist card also appears in the thread sidebar on the thread page (shared `threads.js`). `threads.js`.
- Edited existing `app-settings.spec.js` lines (see above). `viewer/test/app-settings.spec.js`.
- Added shared checklist styles to `app.css` since Threads loads only it. `app.css`.
