# T1 report

Implemented the `check` card schema, current-done acceptance and duplicate checks, press handling, handoff history, and card documentation.

Files changed:
- `viewer/app/card.js`: lead-only shown card schema and step validation.
- `viewer/app/cards.js`: shared current done lookup and acceptance checks under the thread lock.
- `viewer/app/threads.js`: check press validation and lead delivery.
- `viewer/app/handoff.js`: check history and handoff validation kind.
- `protocol/app/cards.md`, `protocol/app/cards-lead.md`: card and press contract.
- `viewer/test/protocol-rules.test.js`, `viewer/test/app-check-card.test.js`: protocol and behavior tests.
- `docs/plans/self-check-steps/reports/T1.md`: this report.

`machine/service.js` needs no change: only `done` is synchronous; other kinds use the generic spool and forwarding path.

The first focused run failed because the test fixture passed stored metadata to agent validation; correcting the fixture made the requested focused run pass. The first full run failed in `server.test.js` “the global write lock serializes concurrent writes and retry retains both changes” (`null !== 'left'`). A clean archive of the starting commit with Git metadata and dependencies passed the full suite, so that run does not establish the failure as pre-existing. The full retry passed. An initial baseline archive run was interrupted after it exposed missing Git metadata; it was not a valid baseline.
