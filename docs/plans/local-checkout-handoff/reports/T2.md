# T2 — Hub try routes

Implemented the GET and POST routes, local source-root refusal, active thread title lookup, and authenticated machine client forwarding. The focused test uses a fake machine and covers forwarding, archive, authentication, titles, errors, and the root check.

Files changed:
- `viewer/app/routes.js`
- `viewer/app/machine-client.js`
- `viewer/app/API.md`
- `viewer/test/app-try.test.js`
- `docs/plans/local-checkout-handoff/reports/T2.md`

The full viewer suite failed twice, so the required full-pass gate remains unmet. The first run failed quiet test 6 and the real-machine archive/upload test; the retry failed quiet tests 5 and 6, the same archive/upload test, and a port collision (`EADDRINUSE`) in a sudo test. Multiple concurrent viewer suites were running; the timing failures may reflect contention, but that is not proven. The worker rule requires stopping after two failures of the same gate.
