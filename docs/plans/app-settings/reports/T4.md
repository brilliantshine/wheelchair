## Choices

- `settings.js` (tier table, Claude and leads): changing a model keeps that cell's existing effort; the lead pickers carry no effort picker, so a lead's saved effort is preserved rather than wiped.
- `settings.js` (Other agents): the three rows are plain tier pickers (Light to Critical); "Two providers when both are installed" and "Not the provider that built it" sit under the row names as the explanatory lines.
- `settings.js` (Code mapping line): the design's "Same order as workers" belongs to a non-goal, so its line reads "Maps how the existing code works before planning".
- `settings.js` (Models section): a one-line hint under the table replaces the design's "Providers covering it" note and says what "Not used" and "CLI default" mean; the lede drops the design's "rules for a kind of work" sentence.
- `settings.js` (heads-up placement): `newer` and `available` items sit inside the GPT cell for their tier; `tierless` and `malformed` lines sit above the table.
- `settings.js` (templates, switches): a checked switch saves `true` and an unchecked one is left out of the template (never saved as `false`); Installing packages and "When the brief doesn't settle something" always show a value (new templates start at "Ask the lead first" and "Ask the lead").
- `settings.js` (templates, list): roles are listed one group each (Lead, Sub-lead, Worker, Reviewer, Checker, Mapper) instead of the design's combined "Checker and mapper"; empty groups are hidden; a project-scoped template in use shows "in use here".
- `settings.js` (templates, Mark in use): added a "Mark in use" / "Stop using" button in the footer, since the design has no control for it; it sends only `in_use`, so unsaved edits are neither saved nor lost.
- `settings.js` (templates, Duplicate): saves a copy named "<name> copy" at once (from the editor's current contents) and opens it.
- `settings.js` (templates, Delete): two-step inline "Delete" then "Really delete", not a browser dialog.
- `settings.js` (templates, layer stack): for non-worker roles layer 1 keeps the design's "can't be turned off" with a generic caption, and layer 3 reads "The brief / What it is asked to do each time it starts"; the worker wording is the design's.
- `settings.js` (See it in full): shows the saved composition from `GET /settings/prompt` for the template's role and project; it does not include unsaved edits.
- `settings.js` (project labels): a project shows as its folder name plus "only", or its full path when two share a folder name.
- `settings.js` (Writing style): the design's "Rewritten live as you change the settings above" became "Preview rewrites the message under the style above, saved or not. It saves nothing." The "With your style" panel starts with "Press Preview to see the same message under this style." A phrase typed in the never-say box but not yet added with Enter is included on Save and Preview.
- `settings.js` (notes): template Save shows "Saved. Changes apply to agents started after you save."; Writing style Save shows "Saved" beside the design's "Leads pick it up on their next message."
- `settings.css` (phone): the section tabs wrap their labels onto two lines rather than scrolling; the tier table turns into stacked cards with each tier's name above its pickers.
