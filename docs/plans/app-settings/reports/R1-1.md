# R1-1 — save both values of a boolean switch

## What changed

- `viewer/pages/settings.js`
  - `templateBody()`: `save_every_step` and `full_tests_before_done` are now sent whenever the draft holds a boolean for them (`true` or `false`), not only when `true`.
  - `blankDraft()`: a new template's draft now starts with both switches at `false`, so a new template with untouched checkboxes saves `false` for both.
- `viewer/test/app-settings.spec.js`: at the end of the existing "creating and saving a template…" test, a second template, `Plain`, is created with both switches unchecked and marked in use. The test then asserts:
  - `GET /wheelchair/api/settings` returns `save_every_step: false` and `full_tests_before_done: false` for `Plain`;
  - `GET /wheelchair/api/settings/prompt?role=worker` contains "Do not make an extra save after every step." and "Run the tests that fit the change before reporting done."

Nothing else changed. `viewer/app/settings.js` already accepted and rendered `false` values, so the server side needed no edit.

## Choices

- `viewer/pages/settings.js` `blankDraft()`: a new template now starts with `save_every_step: false` and `full_tests_before_done: false` in its draft. The brief asks that a new template's checkboxes "save false" without a toggle, which needs these defaults in the draft. Templates loaded from the server with no key still send no key until toggled.
- `viewer/test/app-settings.spec.js`: the new assertions are a second template block at the end of the existing template test, not a separate test.
- `viewer/test/app-settings.spec.js`: the prompt check fetches `role=worker` with no `project`, so `Plain` (scope `all`) is the in-use worker template it reads.
