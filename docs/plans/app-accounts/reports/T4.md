# T4 — machine login sessions

## Changes

- `machine/adapters/claude.js`, `codex.js`, `index.js`: login commands and screen parsers; optional `onTurnEnded(session, event)` owns Codex thread binding, transcript scanning and incremental readings, and `usageFrom` exposes the reached flag.
- `machine/service.js`: login routes and tmux lifecycle, account validation, status reuse, usage forwarding, and exclusion of login sessions from recovery, listing and archive.
- `machine/API.md`: documented the login routes and exclusion.
- `machine/test/accounts.test.js`, `service.test.js`, and `fixtures/login/`: sanitized real-screen fixtures and regression coverage for login, account seeding, preflight, default start compatibility and Codex usage.

Claude's captured screen went directly to the OAuth URL and paste-code prompt; no login-method or account-type question appeared, so the fallback answers Enter for a subscription option when detected, but that screen was not verified against a real capture. The observed Claude URL used `claude.com`; Codex printed the device URL and a five-character second code segment. The first Codex attempt exited before capture; the second retained the screen with a temporary sleep. No login was completed.

## Choices

- `machine/service.js`: retain the CLI's exit marker in tmux for 600 seconds and determine completion from account login status.
- `machine/service.js`: retain login metadata in memory; infer it from default IDs or the seeded account file when an existing tmux session survives a service restart.
- `machine/adapters/claude.js`: accept the observed `claude.com` host as well as the specified hosts; for a detected subscription menu, press Enter (the observed capture did not show that menu).
- `machine/service.js`: reserve the `wc-login-` prefix against thread session creation and filter any legacy managed records with that prefix from listing and archive.

## Validation

The first machine run failed because an existing direct `cliStatus` caller had no cached argument; the compatibility fix passed on the subsequent runs. The first viewer run overlapped the machine suite and had the documented lifecycle failure plus a port collision and a graph write assertion; the isolated rerun is recorded below. `git diff --check` produced no output.
