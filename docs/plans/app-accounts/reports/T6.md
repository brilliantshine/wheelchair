# T6 report: the accounts interface

## What changed, by file
- `viewer/pages/settings.js`: new `accounts` and `usage` sections (first and second). Accounts panel (grouped by provider, machine states, windows, Pause/Resume, Rename, Change plan + weight, Remove with an inline confirm, Add account with the once-per-add second-Claude warning, Sign in offered on each machine after an add). Sign-in card (Claude link + paste box, Codex link + large code + Copy, `Couldn't read the sign-in screen` fallback after `failed` or 30 s with no url, Open terminal link, green then closes after 2 s, polling every 2 s and stopped on close). Usage panel (bars, amber line, notify line, "All accounts paused", "no reading yet", account table with reasons, balancing form saved via `PUT /settings/balancing` with the 400 shown inline). `lead_order` editor under the lead model pickers on Models. `GET /usage` on opening Accounts/Usage and every 30 s while either is shown. `POST /usage/seen` on opening Usage.
- `viewer/pages/settings.css`, `app.css`, `thread.css`: styles for the above, the nav dot, the waiting line; phone layout.
- `viewer/pages/nav.js`: Settings dot from `GET /usage/alert` (page load + every 5 min); clears on a `wc-usage-seen` window event the Settings page fires.
- `viewer/pages/terminal.js`: `?login=<id>&machine=<m>` mode reads `/accounts/<id>/signin/<m>/pane` (`text`) and posts keys to `…/keys`.
- `viewer/pages/threads.html`, `thread.html`, `threads.js`: CLI picker removed; thread list shows the provider label.
- `viewer/pages/thread.js`, `thread.html`: lead waiting line (`#lead-wait`) above the pinned cards; head meta shows the provider label.
- Tests: new `viewer/test/app-accounts.spec.js` (27 tests per browser); `app-settings.spec.js` (five tabs) and `app-threads.spec.js` (no `#nt-cli`) updated.

## Could not do
- The fake machine service in `helpers/app-machine.js` has no `/v1/logins` routes, so the new spec answers the usage and sign-in routes with `page.route` instead. The pages, the real server and the thread world are real.

## Choices
- Default section stays Models (hash fallback unchanged) although Accounts is now first in the list; existing tests and links rely on it.
- `viewer/pages/settings.js`: Remove asks "Remove <name>? Remove / Keep" inline first (the brief did not say to confirm).
- `viewer/pages/settings.js`: the 30 s refresh skips a repaint while an edit/add form is open or an input in the panel has focus, so typing is never wiped.
- `viewer/pages/settings.js`: after an add, the Sign in buttons show on the new account's card, one per machine listed in `/usage`.
- `viewer/pages/settings.js`: balancing order editors keep both providers by default (up/down, leave one out, add back); `lead_order` has a "then whatever's left" checkbox for `any`. The Usage Save sends the worker/within/leave/notify/save-claude/margin keys; the Leads Save sends only `lead_order`.
- `viewer/pages/settings.js`: plan choices are hard-coded (Claude: not sure/Pro/Max 5x/Max 20x; GPT: not sure/Plus/Pro), matching `PLANS` in `viewer/app/settings.js`, since no route lists them.
- `viewer/pages/settings.js`: a window whose `resets_at` has passed shows 0% used with no reset time (as the hub's `effective()` does).
- `viewer/pages/settings.js`: `done` with `logged_in` false keeps polling; only `failed` or no url within 30 s shows the fallback.
- `viewer/pages/nav.js`: the dot is cleared through a `wc-usage-seen` window event, and on phones it sits at the corner of the gear.
- `viewer/pages/thread.js`: the waiting line's provider label comes from the lead session's `provider`, falling back to the thread's; the account name comes from `/settings` `accounts`, fetched once on load.
- `viewer/pages/thread.js`: the thread head meta line shows the provider label (not `cli`) when `provider` is set.
- `viewer/pages/settings.css`: five tabs share one row at phone width (smaller font), because the existing phone test requires a single row.
