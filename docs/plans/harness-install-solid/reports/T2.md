# T2 report: hub routes and Settings page

## Changed
- `viewer/app/routes.js`: install passthrough accepts DELETE; POST refused 409 `{error: "<display name> is switched off"}` when the Use switch is off (name from `DISPLAY_NAMES`, e.g. "Codex"); `PUT /settings/harnesses/<p>` with `enabled:false` fires DELETE to every machine in `hub.machines()` in parallel, not awaited, all errors swallowed.
- `viewer/pages/settings.js`: `cancelInstall`, Cancel / "Cancelling…" in the running row (only once a POST 202 or GET running arrived, hidden while offline), cancelled branch before `!st.installed`, `h-explain` line on failed, job record keeps `explanation`, POST 409 split by `body.error`.
- `viewer/pages/settings.css`: `.h-explain`.
- `viewer/test/app-harnesses.test.js`: two new tests (DELETE passthrough/502, POST refused while off; PUT false/true fan-out). The two existing fake hubs gained `state.settings`, which the POST check now reads.
- `viewer/test/app-harnesses.spec.js`: five new tests, each run at phone and desktop sizes (Cancel flow to "Install cancelled", failed Cancel messages, no Cancel while offline, stale-page "switched off" row error, explanation above tail).

## Choices
- After a Cancel answered with a non-409 4xx (e.g. 404), the "Cancelling…" state is undone so Cancel shows again beside the error line; the brief only said to keep the poll going. (settings.js `cancelInstall`)
- Cancel press and Install press clear that provider's row error first. (settings.js)
- A 202 or 409 to DELETE leaves "Cancelling…" showing until the poll reports the outcome. (settings.js)
- Provider name in the 409 uses `DISPLAY_NAMES` (same strings as the Settings page). (routes.js)
- A POST 409 with another error removes the optimistic job record as well as stopping the poll. (settings.js)
- Cancelled row shows Install whenever `!st.installed`, regardless of `st.recipe`. (settings.js)
