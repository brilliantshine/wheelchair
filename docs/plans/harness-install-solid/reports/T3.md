# T3: a failed Cancel after a poll tick shows its reason

## Changed files

- `viewer/pages/settings.js`, `cancelInstall` only. The identity check `now !== job` is replaced with `now.state !== 'running'`, and `job.cancelling = false` becomes `now.cancelling = false`. The poll replaces `hz.jobs[key]` every 2 s and copies `cancelling` across, so the old object reference was stale when a DELETE failed after a tick. The `hz.rowErr` line and `paintHarnesses()` are unchanged.
- `viewer/test/app-harnesses.spec.js`: one new test, `a Cancel that fails after a poll tick still says why`, placed after `a failed Cancel keeps the button and says why`. The DELETE answers 500 after 3 s, which is longer than one poll tick. It asserts the row shows `Cancelling…`, then the alert `Couldn't cancel: hub isn't reachable.` (timeout 8000), then that the Cancel button is visible.
