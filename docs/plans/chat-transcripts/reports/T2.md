# T2 — hub transcript caching

- `viewer/app/chat.js`: separated fresh report reads from versioned chat reads, retained parsed items and parse inputs only, and implemented version, fallback and unknown-reader handling. The parsers read no thread field beyond `parent_title`. Chat spreads parsed items into a new array and only filters that array; it does not mutate the cached array or its items.
- `viewer/app/hub.js`: added idle sweeping, an injectable clock and timer interval, a stop method for the sweep timer, and per-name synchronous last-seen write reservations.
- `viewer/test/helpers/app-machine.js`: added an optional versioned transcript protocol.
- `viewer/test/app-chat.test.js`: exercises protocol, cache, report, clock, lock, aside, timer and throttle behavior.
- `viewer/test/app-asides.test.js`, `viewer/test/app-handoff.test.js`: allow transcript query strings in route matchers.
- `viewer/test/app-hub.test.js`: checks the persisted last-seen time can lag the in-memory time.

Temporarily removing the sweep's thread-lock check made the aside-at-cutoff test fail with `message not found`; restoring it made the test pass. The hub stop method needs to be called by the server's shutdown path; `viewer/server.js` lies outside this task's ownership boundary, and the lead was asked to integrate it or authorize that edit.
