# T2 — hub transcript caching

- `viewer/app/chat.js`: separated fresh report reads from versioned chat reads, retained parsed items and parse inputs only, and implemented version, fallback and unknown-reader handling. The parsers read no thread field beyond `parent_title`. Chat spreads parsed items into a new array and only filters that array; it does not mutate the cached array or its items.
- `viewer/app/hub.js`: added idle sweeping, an injectable clock and timer interval, an exported sweep function, and per-name synchronous last-seen write reservations.
- `viewer/test/helpers/app-machine.js`: added an optional versioned transcript protocol.
- `viewer/test/app-chat.test.js`: exercises protocol, cache, report, clock, lock, aside, timer and throttle behavior.
- `viewer/test/app-asides.test.js`, `viewer/test/app-handoff.test.js`: allow transcript query strings in route matchers.
- `viewer/test/app-hub.test.js`: checks the persisted last-seen time can lag the in-memory time.

Temporarily removing the sweep's thread-lock check made the aside-at-cutoff test fail with `message not found`; restoring it made the test pass. The lead clarified that the unref'd timer follows the existing hub timer lifecycle and does not keep the process alive; no separate shutdown hook is needed.

## Choices

- `viewer/app/hub.js`: exposed an injectable clock and sweep interval on the constructor to exercise expiry and timer behavior without waiting ten minutes.
- `viewer/app/chat.js`: encoded the three parse-key values as a JSON array to avoid delimiter collisions; no additional thread field reaches the parsers.
- `viewer/app/chat.js`: shared a `localTranscript` helper between the independent report and chat paths.
- `viewer/app/chat.js`: exported `chatTranscript` for direct protocol tests.
- `viewer/test/helpers/app-machine.js`: named the optional versioned response switch `versionedTranscripts`.
- `viewer/app/hub.js`: retained the 60-second reservation after a failed `machines.json` write.
