## Choices
- `app-settings.spec.js` lines 48 and 299: updated the section list and tab count to include Project tools (the existing tests would otherwise fail); no other edit there.
- Project picker has a "Choose a project…" placeholder, so nothing is read until a project is picked.
- Tool Remove and key Remove use an inline "Yes, remove / Cancel" confirmation instead of `window.confirm`.
- Tool edits are applied to a working copy only on "Keep changes"/"Add to the list"; the single Save button sends them. Save is disabled with no changes and no pending key values.
- Reserved check: exact names compared case-insensitively, prefixes case-sensitively.
- Entry shapes: stdio = no `type` or `stdio` with string `command`; http = `type: "http"` with string `url`; anything else (incl. `sse`, extra `headers` on stdio) is "edit in the file". Empty-string args count as unrepresentable (would be lost as lines).
- A plain value containing `${` is refused in the form ("use a key"); a header text-before-key may not contain `${`.
- Key values typed in the tool form for a key not yet set are sent with the next tool Save only if the key is still referenced; values typed in the form but with no tool change send `tools: null`.
- Keys list repaints from `keys` on every key-carrying reply, and the tool list repaints too so "set"/"not set" updates; the open form and unsaved edits are untouched.
- 409 refusal reloads the section and shows the reason plus "make your change again".
- Header-warning note shows whenever a web-address form has at least one header.
