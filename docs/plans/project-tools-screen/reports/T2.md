# T2 report

## Changes

- `machine/lib/project-tools.js`: project identity, remote discovery, private-ref reads, key operations, validation, isolated commits, lease-protected push and PR creation.
- `machine/service.js`: authenticated routes and a per-project write lock.
- `machine/API.md` and `machine/AGENTS.md`: route and ownership pointers.
- `machine/test/project-tools.test.js`: real-git and fake-gh coverage of reads, writes, failures, stale baselines, key storage, Start over and dropped requests.

## Outstanding

Blocked on the question sent to the lead: `git remote get-url` itself expands `insteadOf`, so the required file-URL fixture makes a configured GitHub origin appear non-GitHub before the validation. The fixture disables the rewrite only for `get-url`; production currently follows the literal `get-url` check. A lead decision is needed on whether to inspect raw configured URLs instead.

The requested one-test-per-validation-item coverage is incomplete: several cases are combined, and the new tests do not individually exercise concurrent lock waiting, a changed default branch, an invalid key-store read, or all checkout alias / session-injection cases (the latter have T1 coverage). The test suite does cover command timeout and key-write cleanup in the existing T1 tests. No T1 module was changed.

## Choices

- `machine/lib/project-tools.js`: unchanged non-null tool submissions are compared against the baseline blob in the local object database to avoid a fetch for key-only saves.
- `machine/test/project-tools.test.js`: disable the test-only `insteadOf` configuration for `get-url` calls, while retaining it for network operations; the production interpretation remains a question for the lead.
- `machine/lib/project-tools.js`: compare existing conflict pairs by tool and field so editing unrelated properties does not create a new conflict.
