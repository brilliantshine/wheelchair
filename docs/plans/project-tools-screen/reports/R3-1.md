# R3-1 report

## Changed
- `viewer/pages/project-tools.js`: A) `state.loading` (counter-based, `startLoad`/`endLoad`/`applyLock`) around the picker load and every Read (including the reload in `handle()`); selects and all view controls disabled; Save, key Set/Add/Remove, Start over, tool Add/Edit/Remove and form submit are no-ops while loading; machine change clears the project options first. B) tool cards render machine `key_warnings` except "needs" ones, compute "needs NAME…" and "shared with" from `checks[*].keys`; editor hint uses the same; draft-based `toolsUsingKey` and `dataset.needs` removed. Gap 1) `apply()` duplicate check includes read-only row names. Gap 2) `argsRO` true for arguments containing `\r`.
- `viewer/test/app-project-tools.spec.js`: four new tests (A, B, 1, 2). Existing tests updated: those relying on "needs" lines now give `checks[*].keys`; the draft-based "shared with" test is rewritten to use checks; the stale-reply tests (late picker, late read, post-save reload) now force the change with `page.evaluate` because the selects are locked while loading.

## Validation
`npm --prefix viewer run test:browser -- app-project-tools.spec.js app-settings.spec.js` run twice:
- run 1: exit 0, `144 passed (57.5s)`
- run 2: exit 0, `144 passed (2.7m)`

## Choices
- Lock implemented as a load counter so a superseded request cannot leave the section unlocked or locked.
- Stale-guard tests force changes via `page.evaluate` since real users can no longer trigger them.
- "shared with" on a card lists other tools from `checks` (loaded baseline), even if a draft removed that tool.
