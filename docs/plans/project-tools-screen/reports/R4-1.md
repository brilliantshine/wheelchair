# R4-1 report

## Changed
- `viewer/pages/project-tools.js`: `state.baseName` map (draft name -> baseline name; set on read, carried across renames, dropped on removal, absent for added tools); `checksFor()` and `toolsUsingKey()` use it, so cards and the editor's "shared with" use baseline checks and current draft names, omitting removed tools. `buildEntry` keeps every unchanged field exactly as read (command, args, url, type, env, headers compared with the originally parsed form). `readProject` returns a result; new `reloadThenShow` shows the save's message plus "Couldn't reload the project: <reason>" and a Reload button when the reload fails (opened, pr_failed, 409).
- `viewer/test/app-project-tools.spec.js`: stub's `read` may return `[status, body]`; four tests appended (rename/removal baseline checks; untouched fields; 409 + failed read; opened + failed read).

## Choices
- The three "untouched fields" cases are in one test (separate tools in one project) rather than three tests (spec file).
- Kind change on an edited tool keeps the old rebuild-everything behaviour; the "as read" rule applies only when the kind is unchanged (`buildEntry`).
- The Reload button re-runs the read and re-shows the same message; on a second failure it shows the new reason (`reloadThenShow`).
- A key-mode row compares value/prefix/keyName as empty-string defaults, so absent and '' count as equal (`buildEntry`).
