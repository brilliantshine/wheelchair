# T1 report: the auto_merge setting

## What changed, by file

- `viewer/app/settings.js`: `defaults()` gets `auto_merge: 'off'` beside `aside_access`; `normalize()` keeps `'on'` and maps anything else to `'off'`; `describe()` returns `auto_merge` beside `aside_access`.
- `viewer/app/routes.js`: PUT `/settings/preferences` accepts `auto_merge`, refusing anything but `off` or `on` with 400 `auto_merge must be off or on`; the response carries `auto_merge`.
- `viewer/pages/settings.js`: a new `Merge pull requests when done` row in the Threads section, right after Tool steps, using `modeGroup('auto_merge', …)` with Off/On. The hint text is the constant `AUTO_MERGE_HINT`, defined beside `asideHint`, with the exact wording from the brief.
- `viewer/test/app-settings.test.js`: assertions after the `aside_access` ones: initial `'off'`, a bad value gives 400 with the detail, `'on'` is returned by the PUT and by GET `/settings`, and `'off'` is set back.
- `docs/plans/auto-merge/reports/T1.md`: this report.
