# T1 report — blocked

Implemented `machine/lib/win-tool-proxy.js`: stand-in, ready-file polling, direct child launch, handoff, list probing/cache, and shutdown. Added a configurable fake server in `machine/test/fixtures/win-tool/server.js` and focused tests in `machine/test/win-tool-proxy.test.js`.

Validation mapping: stand-in, ready at start, 3a/3b, remembered and empty lists, held timeout and cancellation, failed state, handoff failure, stdin close, own-list cache and pagination, environment, tool exit and signal status, exit during handoff, large response, and missing executable are covered. The signal tests exercise shutdown. Coverage remains incomplete for slow-reading and closed-read-end clients, child stdin EPIPE, forced escalation, command-only launch, and some detailed ordering and permissions cases. The full machine suite failed twice in unrelated tests, so the two-failure guardrail stopped further work.
