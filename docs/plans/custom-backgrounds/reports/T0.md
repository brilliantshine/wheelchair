# T0 — preparation and isolation

Before appearance code was enabled, `viewer/test/helpers/server.js` was changed to always allocate and pass a temporary `--state-dir`, independent of the temporary cache root. An explicit stateDir remains available for sequential restart tests only. The returned context exposes stateDir so isolation is testable.

Preserved and explicitly committed authorized bootstrap artifacts: root ROUTER.md, machine/ROUTER.md, protocol/ROUTER.md, viewer/ROUTER.md, viewer/app/ROUTER.md (18bb3257). Shared helper landed in 2845666d; first implementing status commit is 0e6adc49.

Validation:

```text
node --test viewer/test/server-isolation.test.js
1..1
# tests 1
# pass 1
# fail 0
```

The test starts two default servers on isolated ports and confirms independent state and cache roots and that writing a marker into one state directory cannot be observed in the other. Both servers are stopped in finally.

Baseline command (before background implementation):

```text
node --test viewer/test/*.test.js
# tests 699
# pass 697
# fail 2
# duration_ms 84814.212285
```

Both failures are existing app-slug.test.js expectations about committed plans on origin/main. Temporary git repositories default to master on this machine. A command-local Git configuration resolves the setup assumption without modifying repository/user configuration:

```text
GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=init.defaultBranch GIT_CONFIG_VALUE_0=main node --test viewer/test/app-slug.test.js
# tests 8
# pass 8
# fail 0
```

## Decisions

- Expose chosen stateDir in the test-server return context to check isolation and support sequential restart cases explicitly.
- Use command-local init.defaultBranch=main for final Node validation because the existing slug tests assume main; no production code or persistent Git configuration was changed.
