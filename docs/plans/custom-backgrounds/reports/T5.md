# T5 browser coverage — blocked

Changed `viewer/test/background-editor.spec.js`: added real-server checks for shared save/reset, clean and dirty editors, conflict/Cancel, draft invalidation, slider/image identity, pending file reads, delayed save ownership, stale metadata and Settings screenshots. Updated the Settings section expectations in `viewer/test/app-settings.spec.js` for the added section.

The delayed-save test failed, but worker-5 identified a test race: the test recorded the image before the second selection decoded. Worker-5 reports that waiting for the second filename and image in a scratch copy passed all ten tests. This commit adds that readiness wait; it has not been rerun here because of the gate guardrail. The earlier claim of a source failure is withdrawn. The two-failure gate guardrail stopped further iteration. This is partial coverage: finite-loop animation, ten-page integration, thread/agents/docs interactions, actual delayed metadata polling and bounded retry, replacement failure fallback, and pending decode invalidation remain to be completed. The same-section rebuild and stale poll cases currently exercise controller notifications directly rather than proving the full external trigger; the rapid selection test holds the file read rather than image decode. Firefox was not run as instructed. The Settings section suite was not independently run.

Screenshots retained: `/tmp/backgrounds-T5-artifacts/chromium-settings-1280.png`, `/tmp/backgrounds-T5-artifacts/chromium-settings-390.png`.
