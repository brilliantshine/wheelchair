# T4 — Background editor and shared appearance

## Changes

- `viewer/pages/background.js`: preserve the image captured by a dirty preview, maintain ordered shared metadata and reusable saved display, expose load errors and availability, cancel superseded saved image loads, and release resources on navigation and restoration.
- `viewer/pages/settings.js`: scope slider animation frames and pending image resources to each visit, preserve drafts and revisions across rebuilds, accept conflict metadata, and give useful errors without revealing implementation details.
- `viewer/pages/background.css`: use actual content surfaces and existing palette colors for Settings, Features, threads, documents, New thread, agents, and terminal; preserve Settings gutters and its selected section state.

The controller methods remain compatible. `current` and subscription state add `error` and `available`; `publishSaved` uses the image captured at acquire.

## Choices

- `viewer/pages/background.js` and `settings.js`: when a saved replacement fails to load, disable the clean slider until that image actually appears; file selection and Remove remain usable and normal refresh retries it. This preserves the requirement not to edit an unseen replacement.
- `viewer/pages/background.css`: use existing `--bg`, `--panel`, and `--panel-2` palette values on the content surfaces identified in the current pages; keep the Settings section wrappers transparent so gutters remain visible.
- `viewer/pages/settings.js`: show concise retry/format/size messages for failures instead of exposing parser or server details in the interface.
