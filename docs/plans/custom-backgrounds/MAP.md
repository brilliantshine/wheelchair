## Flow

A signed-in browser opens an allowlisted app page, loads public page scripts/styles, and Settings fetches `/settings` before rendering the hash-selected section (`viewer/server.js:1707`, `viewer/server.js:1718`, `viewer/server.js:1748`, `viewer/pages/settings.html:6`, `viewer/pages/settings.js:1406`, `viewer/pages/settings.js:1416`). App API reads require the remember cookie or token; writes additionally require the matching origin (`viewer/server.js:1286`, `viewer/server.js:1292`, `viewer/server.js:2104`). The route dispatcher reads most write bodies as JSON before routing to Settings, whose updates normalize, modify and validate the saved settings inside a per-file queue before atomic replacement (`viewer/app/routes.js:19`, `viewer/app/routes.js:63`, `viewer/app/routes.js:92`, `viewer/app/settings.js:256`, `viewer/app/state.js:57`, `viewer/app/state.js:222`).

```text
signed-in page -> public scripts -> Settings editor -> authenticated API
                                                   -> settings queue -> settings.json
```

- Normalization explicitly reconstructs known fields; a new background field must survive it or any ordinary Settings update can erase it (`viewer/app/settings.js:194`, `viewer/app/settings.js:211`, `viewer/app/settings.js:256`). `atomicWrite` currently renames before chmod, so chmod failure can report failure after publication (`viewer/app/state.js:23`). The generic JSON reader buffers without a limit; binary dispatch and bounded background reads must precede it (`viewer/app/routes.js:19`, `viewer/app/routes.js:38`).
- Settings keeps drafts in module state, rebuilds its panel with `replaceChildren`, and changes section on hash navigation; its JSON-only API helper serializes supplied bodies (`viewer/pages/settings.js:32`, `viewer/pages/settings.js:65`, `viewer/pages/settings.js:1395`, `viewer/pages/settings.js:1406`). The existing shared poller skips hidden ticks but does not wait for asynchronous callbacks, so it alone does not enforce one in-flight request (`viewer/pages/nav.js:6`).
- Page assets are restricted to JS/CSS paths; `PAGE_CSP` permits `data:` but not `blob:` images, and app pages add same-origin framing (`viewer/server.js:45`, `viewer/server.js:1709`, `viewer/server.js:1718`). Legacy docs use a separate HTML page and CSP (`viewer/server.js:1780`, `viewer/doc.html:87`). Standalone graphs have their own opaque page and canvas (`viewer/index.html:13`, `viewer/index.html:102`); thread diagrams and picture views can embed frames (`viewer/pages/diagram.js:70`, `viewer/pages/picture.js:20`, `viewer/pages/picture.css:9`). Shared app base and sticky navigation already paint backgrounds, while Settings panels and assistant bubbles include transparent regions (`viewer/pages/app.css:28`, `viewer/pages/app.css:39`, `viewer/pages/settings.css:4`, `viewer/pages/thread.css:76`).
- The isolated test helper always creates a cache root but passes `--state-dir` only when supplied; the server otherwise defaults to the user's Wheelchair state, so new appearance requests must not run against that default in tests (`viewer/test/helpers/server.js:66`, `viewer/server.js:2091`). Hub initialization runs before API dispatch and already performs a sweep (`viewer/server.js:2102`, `viewer/app/hub.js:58`).
