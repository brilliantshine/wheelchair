# T1 — Load harness

Implemented `test-support/under-load.sh` and `test-support/test/under-load.test.js`. There was no existing bounded load harness; CPU contention had to be confined to the caller's allowed CPUs. The harness selects a random subset, pins itself and descendants, runs busy helpers, counts command results, and terminates helpers and the command group on signals.

Test reasoning and mutation checks: the count and affinity test observes two runs and a failing run; replacing the pass count with zero made it fail on the count, and removing the affinity pin made it fail on the affinity assertion. The normal-exit and TERM tests record the actual children before exit; removing helper cleanup made both fail with `process survived normal exit` and `process survived TERM`. The TERM fixture records its child's signal receipt; changing group TERM to leader-only TERM (with a delayed KILL to end the experiment) made it fail with `command child did not receive TERM`. Each mutation was restored. No existing tests were changed.

## Choices

- `under-load.sh`: use `shuf` to randomly select CPUs and silence helper output, so helpers cannot hold the caller’s output pipes open.
- TERM test: require a child signal marker as well as process disappearance, so natural child exit cannot hide leader-only signalling.
