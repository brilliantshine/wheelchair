# R8 — sticky spot comment

- `viewer/pages/diagram.js`: removed the tap handler's scroll and scroll-position restoration.
- `viewer/pages/thread.css`: made the comment panel sticky above the composer with background, padding and stacking; changed the diagram-card overflow to `clip`. Checked `.image-pair`, `.image-halves`, `.image-half`, `.card`, `#chat`, and the intervening layout ancestors: no other overflow needed changing. `.mockup-box` clips the layer but is a sibling, not an ancestor, of the comment panel.
- `viewer/pages/picture.css`: added the picture pane's bottom offset while retaining its horizontal sticky behavior.
- `viewer/test/app-spot-comment.spec.js`: added tall thread and picture regression tests, retained the wide test, and moved an existing second coordinate tap away from the newly overlaid panel.

Screenshots at 390x844, captured after a tall-mockup tap and inspected:
- Thread: `/tmp/wheelchair-r8-w13/thread.png`
- Picture page: `/tmp/wheelchair-r8-w13/picture.png`

## Choices

- `app-spot-comment.spec.js`: the existing coordinate test's second tap uses 30% width and 50% height instead of 30% and 80%, so it exercises an unobscured part of the mockup.
- `app-spot-comment.spec.js`: scroll the thread mockup top to 190 px for the tall test; allow 1 px on bounding-box checks and use soft assertions to expose multiple geometry failures.
- `app-spot-comment.spec.js`: capture optional screenshots only in Chromium when `R8_SCREENSHOTS` is set, so ordinary suite runs do not write screenshots.
