# T1 report: chat updates in place (S1), mockup height up front, image links (S4 thread half)

## What changed
- `viewer/pages/thread.js`
  - `renderChat()` now builds a list of keyed entries (bubble, card, lead-name line, tool/peer/context rows, attachment rows, pending/queued rows), each with a signature, and `reconcile()` (new) keeps unchanged nodes, replaces changed ones in place, inserts new ones and removes gone ones. A kept node holding an iframe is never moved or removed. Returns whether anything changed (drives `changed` in `render()`, so asides re-decorate and "follow the bottom" only fire on real changes). A full clear happens only when the import/hand-off cutoff moves (`seenCutoffKey`).
  - `cardSig()` (new): card fields plus every outside state its drawing reads (pinned, archived, frozen, slug, worktree, branch, kept_files, import cutoff, card error, declining, archive-ask, pressing, idea/deferred open, check-card copy state and current done card).
  - `live(card)` (new) and its use in every press/dismiss/sudo handler and the answer box, so kept nodes act on the current card in `data`.
  - `chatPlace()` / `restorePlace()` (new): record near-bottom and key + viewport offset of every visible chat entry; restore the first surviving one. Used in `render()` (captured at its start, before banners/pins; restored after the chat update, unless following the bottom) and in `showError()` (so the poll error banner, set or cleared, is covered; no-op when it did not change). A comment in `render()` marks where S2's per-render pass over kept nodes goes.
  - `imageHref()` (new): `pictureHref(card) + '&view=image'`; used by the Built half's Open full size and the tap on every image card's picture (same tab, no longer `_blank` to the raw file).
- `viewer/pages/diagram.js`: `mockup()` sets `aspect-ratio: width / height` on the frame box at creation; `fit()` no longer sets the box height (only the scale transform).
- `viewer/test/app-chat-stability.spec.js` (new): 4 tests (x Chromium, Firefox, 390x844): reader stays put with identical iframes and no second `load`; bottom follows new card; mockup box height before iframe load (iframe HTML held back via route); image hrefs.
- `viewer/test/app-mockups.spec.js`: the Built half's link assertion now expects the `view=image` href instead of `target=_blank`.

## Break checks (each test failed when its behaviour was broken, then restored)
- `restorePlace` made a no-op (with the test turning off the browser's own scroll anchoring) -> stability test failed in both browsers.
- `reconcile` clearing the chat first -> stability and bottom tests failed.
- `aspect-ratio` line removed -> height test failed.
- `view=image` dropped -> href test failed.

## Choices
- Entry keys are type + id/time + first 60 chars of text, with a `#n` counter for duplicates (thread.js `renderChat`).
- The lead-name line is its own entry keyed to the entry it precedes, signature = lead name.
- `showError()` itself wraps the capture/restore (covers the poll path and every other banner change) instead of a poll-only wrapper.
- `view=image` links open in the same tab (dropped `target=_blank`).
- Cards pushed out of time order are not reordered (existing `cardsBefore` assumption); my test inserts the older card at the array start.
