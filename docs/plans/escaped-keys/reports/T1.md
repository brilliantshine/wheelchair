# T1 — Escaped key redaction

`machine/lib/key-spell.js:27` memoizes all local parses of up to three escape layers in position-tagged rings. The forward scan shares those parses across keys, starting keys by first character and carrying each live key's indices in bitsets (`machine/lib/key-spell.js:205`). The backward pass follows recorded edges to mark every byte on a complete path, including overlaps (`machine/lib/key-spell.js:148`). The cut-start search seeds the forward pass with suffixes. The cut-end search works backward from the real end with whole characters and partial prefixes (`machine/lib/key-spell.js:349`, `machine/lib/key-spell.js:411`).

`machine/lib/key-redact.js:53` keeps the original plain path for captures without escape bytes. For other keyed captures it combines K4's trims and the matched cut stretches, then renders the surviving marks. When the shared budget runs out, it uses plain matches and unchecked runs on the original capture. `machine/AGENTS.md` routes to the new matcher and `protocol/tools.md:70` documents the escape forms, cut edges and fallback. `machine/test/key-redact.test.js` covers the matcher, exact edge results, fallback and all three runner regressions. `machine/test/key-redact-speed.test.js` exercises the five timed captures.

The budget is **64,000,000 units per capture** (`machine/lib/key-redact.js:6`). A unit covers one capture byte counted once, one generated local parse pair, or one bitset word processed in a pass. The edge grammar also charges memoized prefix queries and suffix combinations. Raw byte pairs are shared constants. The most expensive required no-fallback fixture used 22,270,477 units, about 35% of the budget. Fixture (a) finishes unchanged as E1 allows. Forcing (a) into fallback using the same fixed budget would also force (c) and (d) into fallback. The lead received this difference between the brief's tuning note and E1.

## Timings

Redaction times are the slowest of three final runs on this machine with Node v22.23.5. The runner measurement is the slowest of three focused runs during the broader checks and includes process startup and pipe capture. The work tally used a temporary in-memory wrapper around the matcher.

| Fixture | Slowest | Work units | Result |
| --- | ---: | ---: | --- |
| (o) Ordinary JSON | 94.1 ms | 3,770,373 | All spellings replaced |
| (a) Noise | 447.5 ms | 7,485,675 | Original bytes |
| (b) Late failures | 475.9 ms | 64,000,048 | Fallback |
| (c) Many keys | 921.0 ms | 22,270,477 | All spellings replaced |
| (d) Both cut edges | 807.7 ms | 21,859,217 | Both edges dropped and all spellings replaced |
| 64 KiB stderr runner | 138.3 ms | 2,318,989 | `[output cut] tail` |

During the parallel machine suite, (o), (a), (b), (c) and (d) took 176.5 ms, 1196.2 ms, 1011.2 ms, 2579.5 ms and 1777.5 ms respectively. The stderr runner took 189.2 ms. All remained inside the Spec's limits.

## Choices

- `machine/lib/key-redact.js` uses a 64 million-unit budget based on the measured work.
- `machine/lib/key-spell.js` packs each character and relative end into one number and shares immutable pairs for ordinary bytes and simple escapes.
- `machine/lib/key-spell.js` groups records until the key has no pending positions and pools bitsets in 256-record slabs. Each record stores its first edge inline and allocates room for alternatives only when needed.
- `machine/test/key-redact-speed.test.js` uses xorshift32 with fixed seeds and a 3:1 mix of literal backslash and percent escapes in the timed spelling generator. The noise fixtures use both literal backslashes from E1. Fixture (d) inserts spellings into 2 MiB of JSON and shares fixture (c)'s keys.
- `machine/test/key-redact.test.js` adds a 216-byte character spelling at a ring boundary to exercise complete matches and both partial-edge searches.

### `grep -n -i "never print or log a key" protocol/tools.md`

```text
70:Keys printed as-is or with up to three layers of common escapes are replaced with `[key]`. This covers JSON and backslash escapes such as `\u002B`, `\x2B` and `\/`, and percent-encoding such as `%2B`. Base64, hashing, splitting and web-page codes such as `&#43;` are outside this protection, and deeper escaping may leave a key visible. A backslash right before a key is hidden with it. At a cut edge, text that looks like part of an escaped key is dropped, and a cut-off stretch made entirely of key characters, percent signs and backslashes can be dropped whole. Very escape-heavy output can show `[not checked for keys]` in place of stretches of those characters. Never print or log a key in any form. Never write a key into a tool's files: they are committed. Node's child-process debug output (`NODE_DEBUG`) on in the bridge refuses keyed tools. Claude, Antigravity and unrestricted Codex use keyed tools through MCP with no extra step; sandboxed Codex, Kimi and Pi can't use them yet, and their problems and `wc.js tool list` say so (for sandboxed Codex: set Codex to unrestricted in Settings to use it).
exit 0
```
