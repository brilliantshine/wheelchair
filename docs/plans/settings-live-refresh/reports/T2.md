## Choices

Each is a decision the brief and plan did not settle, or a place I departed from their letter. None was put to the lead.

- `settings.js` `readSettingsAfterWrite`: a save's own reread (`reload`, `refreshModels`, legacy "Use") that another write overtook is read again, up to 3 times, rather than only dropped; dropping it could leave a just-saved template missing from `data`.
- `settings.js` `showHarnesses`: a status read the user is waiting on (they just picked a machine) repaints even though the machine picker has focus, which departs from §3.4's focus defer; otherwise "Checking…" would stay until blur.
- `settings.js` `reconcileVisibleBlocks`: when only the reserved provider's name changed, Balancing's words change in place with no banner or repaint, even with a draft.
- `settings.js` `quietDeferred`: a late first project lookup held back by a typed key never turns into "Updated elsewhere.", not on typing or blur either.
- `settings.js` shared keys: the last keys and machine list are cached and drawn at once on a repaint, so focus survives; a refresh that reads identical keys changes nothing.
- `settings.js` shared keys: the user's own save, remove and Load latest read the hub revision first and count it as seen, so their own write raises no banner; save/remove also run inside `withLocalWrite`.
- `settings.js` `sharedMachine`: starts as null (the hub's default machine) rather than `'hub'`.
- `settings.js` `syncBackground`: no stale mark while the page's own background save is in flight; a refused save is checked again afterwards.
- `settings.js` `lessonAction`: also runs inside `withLocalWrite`, treats Templates as its own block on the 409 reread, and clears the banner when the editor ends up clean.
- `settings.js` `saveLessons`: added the `lessonEdit === edit` guard that Accepted Risks describes as present.
- `settings.js` `paint`: Accounts and Harnesses hold no copy of the values, so a clean repaint of either drops its banner.
- `settings.js` "toggleTemplate": the function is `toggleInUse`; I kept the name. An untouched draft takes the fresh template after the toggle.
- `settings.js` focus restore: also requires exactly one match, so a repeated label never moves focus to another row.
- `settings.js` `focusout`: uses `relatedTarget`, and waits for `pointerup` mid-press, so a held-back repaint never takes a button from under a click.
- `settings.js`: the panel's `change` event is handled like `input`, since selects update drafts on `change`.
- `settings.js` `stable()`: slice and draft comparisons ignore object key order; `renderedSlice` is not recorded for blocks that are never compared.
- `settings.js` `paintHarnesses` and the lesson-thread-title repaint now use `repaint`, so they keep focus too.
