## Choices

- `threads.js`: with same-named folders the lead row reads "<path> lead · <machine>", the machine after "lead".
- `threads.js`, `app.css`: path headings are not uppercased, since paths are case-sensitive.
- `threads.js`: a project whose machine the hub cannot resolve gets no lead row.
- `threads.js`: a lead row's dot is grey until it has a reply, blue after, amber with something waiting.
- `thread.js`, `assistant-popup.js`: a project lead's avatar is "L" (mockup), not its name's first letter.
- `thread.js`, `assistant-popup.js`: a never-started project lead shows no "stopped" bar; one with a past session or a start failure does.
- `thread.js`: with no live lead the queued note reads "waiting for the lead to start".
- `assistant-popup.js`: the closed button and its unread dot name and follow the selected conversation (the project lead by default on a project page).
- `assistant-popup.js`: each side of the switch keeps its own draft.
- `thread.js`, `assistant-popup.js`: the old `wc-assistant-seen` value is not carried over, so the assistant's dot may light once after the update.
- `settings.js`: the mockup's hint wording, not the brief's.
