# T1 — Hub project lead lifecycle

Implementation commit `9cde01d6`.

## Changes by file

| File | Change |
|---|---|
| `viewer/app/project-lead.js` | Resolves project identity, finds projects with active groups, serves read-only status, creates one idle lead record per project, guards threads while off, and stops project lead sessions when switched off. |
| `viewer/app/project-lead-actions.js` | Provides the specified 501 stub until T2 implements the dispatcher. |
| `viewer/app/assistant.js` | Defines the shared `special` predicate, keeps the no-special-thread visibility fast path, and extends the read-only thread guard. |
| `viewer/app/settings.js` | Stores and returns `project_leads` and reuses role-layer composition without templates or lessons for project leads. |
| `viewer/app/routes.js` | Exposes status and creation, validates the setting, attaches resolved machine keys to thread summaries, relays machine actions, and excludes special threads from asides and previous-project suggestions. |
| `viewer/app/sessions.js` | Sends project identity on start and account switch, forces sandboxed Codex mode, keeps project leads branchless, refuses machine session commands, and checks the setting before a start or account switch. |
| `viewer/app/threads.js` | Shares fresh restart handling, refuses archive, and excludes project lead threads from merged-PR polling. |
| `viewer/app/hub.js` | Skips the GitHub PR gate for special threads so their completion cards reach the card-kind refusal. |
| `viewer/app/peers.js` | Excludes special threads from peer discovery and rejects inbound reach cards to project leads. |
| `viewer/app/cards.js` | Restricts project lead card kinds and rejects inbound cross-thread messages with the configured user name. |
| `viewer/app/views.js` | Skips feature and slug discovery for special threads while collecting their open Needs you cards. |
| `viewer/app/auto-merge.js` | Skips special threads before auto-merge consults settings or GitHub. |
| `viewer/app/handoff.js` | Refuses project lead handoff and export through the existing conversation check. |
| `connectors/hub-common.js` | Renders the specified fresh-context line for project leads. |
| `viewer/AGENTS.md` | Routes readers to the project lead modules and the shared conversation predicate. |
| `viewer/test/helpers/app-machine.js` | Adds the fake refresh response. |
| `viewer/test/project-lead.test.js` | Covers identity, idempotency, status, visibility, launch and switch payloads, stop and restart behavior, refusals, Needs you, peer discovery, and PR exclusions. |

## Choices

- `project-lead.js` uses the first active ordinary thread in the group as the source of the stored machine name, while identity uses the resolved machine.
- `routes.js` uses the stored machine name as the summary key if its registration cannot be resolved.
- `cards.js` uses the six allowed kinds for project leads while preserving the assistant’s existing card rules.
- `handoff.js`, `routes.js` and `threads.js` use project-lead-specific text for handoff, asides and retracted cards after restart.
