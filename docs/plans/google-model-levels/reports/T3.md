# T3 report

Settings picker, save checks, sub-lead level lines and scout lines for Antigravity (S3, S5, S6). Code commit `1397123f`.

## Changes

- `viewer/app/settings.js`: `options()` passes `efforts` through; new `levelTool`, `modelLevels`, `normalizeLevelModel` (all reading the list through `model.sh levels`) and `levelLines`; `roleLayers` takes `levels` and puts them after the escalation sentences. `escalationSentences` and the length check are unchanged.
- `viewer/app/routes.js`: PUT `/settings/models` normalizes a suffixed Antigravity id, then refuses a level the model is known not to have.
- `viewer/app/sessions.js`: level lines are worked out at sub-lead start; the scout is named by member id only when the saved list has that level.
- `viewer/pages/settings.js`: the effort selector offers the chosen model's levels (disabled for none); changing model keeps or resets the effort; after a save the model cells are redrawn from GET `/settings`.
- `viewer/app/API.md`: the two settings rows say what changed.
- Tests: `viewer/test/model-options.test.js`, `viewer/test/app-settings.test.js`, `viewer/test/app-settings.spec.js` (its existing server now sets `WHEELCHAIR_AGY: ''`).

`viewer/AGENTS.md`: no entry became false.

New tests were each checked against a deliberately broken version of the behaviour (8 node mutations, 6 page mutations); each made its test fail, and the code was restored.

Screenshot (level group with its levels listed in the Light cell; no-level model with a disabled selector in Standard): `docs/plans/google-model-levels/reports/T3-grid.png`. The open native dropdown cannot be drawn headlessly, so the script set the selector's `size` to list its options. There is no mockup.

## Choices

- `viewer/app/settings.js` `levelLines`: `model.sh levels` does not refresh an old list, so it first runs `model.sh agy-launch <first set tier's model>` (refreshes a list over 1 h old, or over 30 s old when that model is unlisted); once per sub-lead start, with no effort, output ignored; confirmed by the sub-lead (option (a)), `codex/` unchanged.
- `viewer/app/settings.js` `levelTool`: Antigravity is found by its manifest's `listedKey` (as `model.sh` does), not by name, because the name guard forbids names here.
- `viewer/app/settings.js` `levelLines`: a no-level tier reads `<model>, takes no effort, set to <effort or CLI default>`, keeping the "set to" part.
- `viewer/app/settings.js` `levelLines`: with no tier cell set, neither lines nor the closing sentence are added.
- `viewer/app/settings.js` `levelLines`: a `model.sh` error other than "not used" or "unknown" fails the sub-lead start, as scout resolution does.
- `viewer/pages/settings.js`: the picker keys on an option carrying `efforts`, not on the provider name.
- `viewer/pages/settings.js` `keptEffort`: a typed `<base>-<level>` of a listed group is sent with no effort, so the id's level wins.
- `viewer/pages/settings.js`: the re-read failure message is a plain hint, not the error style, and only the latest save's re-read is drawn.
- `viewer/test/app-settings.test.js`: the fake `agy` is set inside the server by a `NODE_OPTIONS` hook, because `helpers/app.js` forces `WHEELCHAIR_AGY=''`.
- `viewer/app/API.md`: updated both settings rows.
- Validation: ran the whole `app-settings.spec.js` file beyond the brief's commands.
