## Choices

- `machine/adapters/pi.js`: interpret the last 7 and 30 days as inclusive local calendar days and exclude future timestamps.
- `machine/adapters/pi.js`: `parseLogin` scans the last five non-empty lines for the prompt.
- `machine/adapters/pi.js`: `loginCommand()` takes no argument because its command does not depend on the account directory.
- `machine/service.js`: Pi completion on a saved line takes precedence over an exit marker; exit-marker completion requires both exit zero and an authenticated account.
- `machine/service.js`: Pi's kill target uses `=name:`; `/keys` uses an exact target for every provider, while pane and state remain prefix-based for providers other than Kimi and Pi.
- `machine/service.js`: a failed Pi prompt capture gives the same 409 as a stale prompt.
- `machine/service.js`: account metadata validation for spend matches status enumeration, including folder ID validity and exact metadata ID.
- `machine/test/pi-login.test.js`: use a private tmux socket and wait for the prompt after disabling terminal echo.
- `machine/test/code-submit.test.js`: exercise cleanup on a private real tmux server with failures injected at paste and Enter.
- `machine/test/pi-spend.test.js`: use a fixed local clock and calculate sample contributions independently alongside synthetic boundary rows.
