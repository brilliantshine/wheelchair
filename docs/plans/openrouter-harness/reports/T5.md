# T5 report

Implemented Pi sign-in, exact login submission targets, tmux buffer cleanup, prompt validation and offline spend aggregation. The full suite has not passed: existing login tests assert old behavior; I asked the lead to authorize updating assertions outside the named test files. The first suite also exposed a Kimi kill target regression, which was corrected. The second focused run exposed a fixture that failed to pass stdin to tmux; it was corrected and the focused tests pass.

Files changed:

- `machine/adapters/pi.js`: Pi sign-in and offline spend reader.
- `machine/service.js`: login lifecycle, code submission and spend endpoint.
- `machine/API.md`, `machine/AGENTS.md`: endpoint and ownership documentation.
- `machine/test/pi-login.test.js`, `machine/test/pi-spend.test.js`, `machine/test/code-submit.test.js`: focused coverage.
- `docs/plans/openrouter-harness/reports/T5.md`: this report.

Validation outputs follow. The full-suite failures are in `/tmp/wc-t5-validation/machine.log`: Kimi's old kill target expectation (corrected in implementation), Kimi's failure cleanup assertion, and the Claude login target assertion. The latter two need existing tests changed.
