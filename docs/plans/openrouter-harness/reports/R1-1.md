# R1-1 — Pi startup and event redaction

Changed files:
- `machine/adapters/pi.js`: wait for download completion lines and recursively redact returned event strings and object keys; enable startup Enter retry for Pi.
- `machine/service.js`: start a replaceable, non-blocking Pi Enter retry after successful submit.
- `machine/test/fixtures/fake-pi.js`: simulate an optional startup download and pending input.
- `machine/test/pi.test.js`: cover download completion ordering.
- `machine/test/pi-turns.test.js`: cover normal and forced-early startup lifecycles, and redaction through the real hook path and direct turn events.
- `docs/plans/openrouter-harness/reports/R1-1.md`: this report.

Tests added:
- Pi waits for every startup download to complete
- Pi redacts every returned turn string and offline tool event
- Pi startup download delivers queued first message after readiness
- Pi startup download delivers queued first message with early readiness and Enter retry

No live model calls were made. Nothing remains uncompleted.
