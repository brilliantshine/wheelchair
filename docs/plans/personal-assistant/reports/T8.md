# T8 — intermittent "Enter sends" composer test

## Finding
I could not reproduce the failure: 12 of 12 quiet runs passed before the fix, and 8 of 8 passed with 6 CPU spinners running. The cause below is therefore found by reading the code and proven by a unit test, not by a failing loop.

Cause: the build's guard in `viewer/app/routes.js:47` calls `assistant.guard`, which called `hub.thread(id)` on every `/threads/<id>` GET and POST. `hub.thread` (`viewer/app/hub.js:125`) saves the thread to migrate a missing `provider` when `cli` and sessions are set. That save runs outside the thread lock, so a concurrent chat poll or the test's own `ctx.patch` can be overwritten by a stale copy, and a POST `/messages` can be affected. The guard now uses the read-only `hub.threadSnapshot(id)`.

## Changes
- `viewer/app/assistant.js:12-16`: `guard` reads `hub.threadSnapshot(id)` instead of `hub.thread(id)`.
- `viewer/test/assistant.test.js` (last test): seeds a thread with a `cli` and a session but no `provider`, and asserts `guard` saves nothing. With `hub.thread` restored the test fails ("not ok 14"); with the fix it passes.

## Bisect
No per-change bisect: nothing failed before the fix, so reverts could not be measured. Only the guard fix was exercised.

## Validation
Before fix (12 loop runs, chromium): `6 passed` x12.
After fix (loop): `6 passed` x12 (11 lines in the first batch, the 12th re-run alone: `6 passed (15.0s)`).
`npx playwright test test/app-assistant.spec.js test/app-assistant-popup.spec.js`: `26 passed (48.3s)`.
`node --test test/assistant.test.js`: `# pass 14`, `# fail 0`.

## Choices
- Fixed the guard with `threadSnapshot` rather than changing `hub.thread`; `viewer/app/assistant.js`.
- Because the failure never reproduced, the fix is unconfirmed against the original flake; Collin should re-measure over many runs.
