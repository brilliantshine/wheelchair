# T2 — hub diagrams and uploads

## Changes

- `viewer/app/card.js`, `viewer/app/cards.js`: validate the diagram formats and lead-only image cards, register graphs only for graph diagrams, and store image basenames.
- `viewer/app/machine-client.js`, `viewer/app/routes.js`: stream uploads and files through the machine and expose archived HTML diagrams.
- `viewer/server.js`: serve registered plan form JSON and sandboxed HTML.
- `viewer/app/threads.js`: read archived HTML and leave a thread open with a system needs card when upload cleanup fails.
- `viewer/app/API.md`: document the card and route contracts.
- `viewer/test/app-hub.test.js`, `viewer/test/routes.test.js`, `viewer/test/helpers/app-machine.js`: cover card validation and storage, streaming, admission, archive failures, and diagram reader headers and boundaries.

## Incomplete

The lead clarified that T2's required gate is the Node suite; the browser gate belongs to T3. The browser geometry failure is documented as pre-existing in `docs/known-issues.md` under “Viewer: no drawn arrow's line passes through either box it connects”. The Node gate failed twice: the first run failed the font allowlist (dependencies were missing at the time) and the existing lost-freed-port race; the second run, after dependencies were installed and without the browser suite running, failed the same race. That race is also documented in `docs/known-issues.md`. The two-failure worker rule stops further iterations. The archived HTML route header test stubs the git reader, so it does not independently exercise git show.

## Choices

- `viewer/server.js`: reject malformed form JSON with 422 and oversized form JSON with 413; the contract does not specify these error statuses.
- `viewer/app/threads.js`: use an unknown-error fallback when the machine reports failed removal without an error string.
