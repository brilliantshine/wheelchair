# T1 report

Implemented S1–S4 backend. Verification is blocked by the machine suite failures described below.

## Changes

- `viewer/app/cards.js:164` counts sends, persists pauses and limit records before refusal, and logs accepted sends.
- `viewer/app/hub.js:202` queues on the latest live or ended lead under the target lock and returns held receipts; `viewer/app/card.js:329` prints the held flag.
- `viewer/app/peer-log.js:2` owns limits, capped log appends and held queue cleanup; `viewer/app/sessions.js:537` records received messages only after submit.
- `viewer/app/threads.js:148` includes recent cross-thread messages in restart context and drops held entries on archive; `viewer/app/handoff.js:94` and `viewer/app/handoff-ops.js:104` ignore and remove held entries on export and Advance.
- `viewer/app/API.md:40` documents the receipt; `viewer/AGENTS.md:15` routes the new helper module.
- `viewer/test/app-lead-messages.test.js:96`, `viewer/test/app-handoff-restart.test.js:238`, `viewer/test/app-hub.test.js:2237`, and `viewer/test/card-receipt.test.js:10` cover the requested cases.

The machine service passes the hub body through unchanged (`machine/service.js:2301-2303`). Existing user activity timestamps and restart queue movement were retained.
