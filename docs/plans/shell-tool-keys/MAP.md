```text
session token -> machine returns worktree and pinned shared copy
  -> CLI discovers tools using caller PATH -> list, check, or local script run
  -> shell-only keyed tool: warning, then local run without stored keys
MCP-capable session -> bridge rechecks definition and reads keys -> keyed runner
  -> capture and redact -> MCP result
```

## CLI and discovery

`wc.js` dispatches to `tool-cli` with its HTTP request function (`viewer/app/wc.js:13`, `viewer/app/wc.js:186`). With a token, `roots` posts to `/tools` and parses its worktree, shared copy and unavailable reason; without one it uses the checkout root and no shared copy (`viewer/app/tool-cli.js:9`). `list`, `check` and `run` discover locally with the caller's `PATH` (`viewer/app/tool-cli.js:45`): project definitions shadow same-named shared definitions, slash-containing programs resolve from the tool directory, and bare names are checked for executability along PATH (`machine/lib/folder-tools.js:38`, `machine/lib/folder-tools.js:63`). `list` asks `/tool-keys` for names and statuses, and reports errors as unavailable; `check` validates scripts without keys and handshakes servers under a shared deadline with signal abort handlers (`viewer/app/tool-cli.js:46`, `viewer/app/tool-cli.js:78`).

`run` accepts an object input, selects a visible valid script, warns when it declares keys, and calls `runScript` locally without a keys argument; inherited environment variables still pass through (`viewer/app/tool-cli.js:109`). `toolEnv` removes the session token and sets the project directory (`machine/lib/tool-run.js:7`). Both runner paths spawn detached process groups; exit handlers kill live groups on exit and signals, with SIGTERM followed by a detached SIGKILL reaper; timeouts and lingering pipes also kill groups (`machine/lib/tool-run.js:8`, `machine/lib/tool-run.js:23`, `machine/lib/tool-run.js:33`, `machine/lib/tool-run.js:49`). The shared request function concatenates response chunks as strings and only handles response `end`, not aborted/error response bodies (`viewer/app/wc.js:28`); a machine-run response needs its own complete-body/error handling to meet the old design's interrupted and split-UTF-8 cases.

## Machine and bridge

Agent routes authorize a session token using timing-safe comparison against recorded sessions; recovered sessions have no usable token (`machine/service.js:588`, `machine/service.js:595`). The returned session contains role, connector (`cli`), worktree and token (`machine/service.js:865`); launch records a pinned shared copy or marks the shared project's own worktree (`machine/service.js:976`). `/v1/agent/tools` returns these roots and the connector reason, and `/v1/agent/tool-keys` discovers against those roots using the machine's tmux PATH and returns names/status, not values (`machine/service.js:2413`). Neither route currently performs the launch eligibility check. Launch discovery requires a tool role and excludes assistant and project lead (`machine/service.js:971`); tool roles are lead, sub-lead, worker and verifier, not reviewer or mapper (`machine/lib/project-mcp.js:9`, `machine/test/folder-tools-launch.test.js:216`). A new execution route must enforce its own eligibility using the authenticated record, not caller-supplied paths.

For MCP, discovery selects the project or shared store, validates keys and creates bridge entries with the tool directory, store and key names (`machine/service.js:997`, `machine/lib/folder-tools.js:78`). The bridge rereads the definition and refuses changes, reads the appropriate store on each call, verifies each value, adds values to a token-stripped environment and passes them to `runScript` (`machine/lib/tool-bridge.js:12`). The reusable runner refuses Node child-process debugging, buffers stdout and stderr as bytes, redacts before applying final limits, and returns stdout on success or stderr on failure (`machine/lib/tool-run.js:16`, `machine/lib/tool-bridge.js:23`). Redaction handles overlapping plain matches, cut edges and escaped spellings with a bounded work budget; on exhaustion it marks unchecked escape-like runs (`machine/lib/key-redact.js:8`, `machine/lib/key-redact.js:53`, `machine/lib/key-spell.js:1`). The bridge installs exit handlers and kills children on MCP close (`machine/lib/tool-bridge.js:25`). `runScript` exposes `killAll` but no per-run cancellation handle (`machine/lib/tool-run.js:60`); a connection-close cancellation cannot safely use global `killAll` if other requests are running.

The machine server's close callback clears timers and screen timers (`machine/service.js:2440`); the service does not import the tool runner or install its exit handlers (`machine/service.js:1`, `machine/lib/tool-run.js:11`). Detached machine-run children therefore need explicit service shutdown and request-disconnect lifecycle handling. This is a code-path observation, not a live restart test.

## Connectors and problems

Kimi and Pi return `shellToolsOnly()` true; Codex returns its `sandboxed(session)` decision, including project leads and default sandboxed mode (`connectors/kimi/machine.js:249`, `connectors/pi/machine.js:19`, `connectors/codex/machine.js:123`). These are optional machine-half functions in the contract, not manifest fields (`connectors/contract.js:24`, `connectors/README.md:76`); manifest capabilities have separately validated members (`connectors/contract.js:18`). Registry export and `--check` are documented at `connectors/README.md:294`; connector-specific dispatch belongs inside connectors, or in a documented capability, not provider-name checks outside (`connectors/README.md:44`, `machine/test/name-guard.test.js:1`).

Launch filters other problem lines for visible keyed scripts in shell-only sessions and creates one connector-specific unavailable line per tool; it also adds the shell and unavailable instructions to the starting prompt (`machine/service.js:1003`, `machine/service.js:1120`). Per-session keyed lines feed the hub's Project tools problem card only while the session is live; card logic preserves and prioritizes newly shown lines (`viewer/app/sessions.js:145`, `viewer/app/sessions.js:176`). `list` independently renders `keyed_unavailable` (`viewer/app/tool-cli.js:61`).
