# T2 report

Implemented cross-thread lead messaging. `cards.js` validates the six refusals in order using non-writing state reads and stores accepted cards only in the sender thread. `hub.js` queues and delivers under the target lock after releasing the sender lock; `agents.js` excludes cross-thread asks from outstanding questions. `app-lead-messages.test.js` covers refusals, restarts, linked threads, concurrent legacy sends, worker refusal, Agents and chat visibility, and the sender-thread `passes_on` check.

Locking inspection: `withThread` serializes entire operations per thread and is not re-entrant. `updateThread` uses a separate per-file write queue and reads fresh JSON inside that queue; `hub.thread` can save a provider migration. The target update returns before delivery, so no nested thread lock or update queue is held during delivery.

The first focused run failed because the new test referred to `root.question` instead of the Agents view's `session.question`; correcting the test produced the passing run below.
