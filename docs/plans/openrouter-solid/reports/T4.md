# T4 — Pi version check

- `machine/service.js`: cached Pi version probe, launch gate and persisted launch version, failure notes, and persisted early-exit reasons. The side-conversation runner can call `await machine.checkPiVersion()` followed by `machine.cliStatus('pi').problem` (or check `installed` for missing Pi).
- `machine/test/pi.test.js`: version floor, warnings, launch persistence, early exit and turn-failure coverage.
- `viewer/app/usage.js`, `viewer/pages/settings.js`, `viewer/pages/settings.css`: propagate and display machine problems and non-blocking warnings on OpenRouter accounts. Ready already blocks only `problem` and required no change.
- `viewer/app/sessions.js`: append startup-stuck event notes.
- `viewer/test/app-hub.test.js`, `viewer/test/app-kimi-settings.test.js`: stuck card and warning/Ready coverage.

## Choices

- `machine/service.js`: Treat non-numeric or prerelease version output as unknown, since S4 does not define prerelease ordering.
- `viewer/app/usage.js`: Show the non-blocking Pi warning on signed-out OpenRouter account lines as well as signed-in lines.
- `machine/service.js`: Reconcile missing startup sessions at the HTTP status/list boundary to persist reasons while retaining the existing synchronous status methods.
