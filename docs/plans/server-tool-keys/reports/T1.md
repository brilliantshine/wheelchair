$ grep -n -i "never print or log a key" protocol/tools.md
exit 0
70:Keys printed as-is or with up to three layers of common escapes are replaced with `[key]`. This covers JSON and backslash escapes such as `\u002B`, `\x2B` and `\/`, and percent-encoding such as `%2B`. Base64, hashing, splitting and web-page codes such as `&#43;` are outside this protection, and deeper escaping may leave a key visible. A backslash right before a key is hidden with it. At a cut edge, text that looks like part of an escaped key is dropped, and a cut-off stretch made entirely of key characters, percent signs and backslashes can be dropped whole. Very escape-heavy output can show `[not checked for keys]` in place of stretches of those characters. A server message replaces an echoed key with `[key]` only when it appears as written. If JSON escapes it, for example `/` as `\/`, the message is held back instead. A message is also held back as "could not be checked for keys" if it contains a stretch over 4 KiB of key characters mixed with `%` or `\`, such as a long percent-encoded URL or nested JSON with `\/`, or so many stretches that checking runs out of time. Never print or log a key in any form. Never write a key into a tool's files: they are committed. Node's child-process debug output (`NODE_DEBUG`) on in the bridge or server launcher refuses keyed tools. Claude, Antigravity and unrestricted Codex use keyed tools through MCP with no extra step. Kimi and Pi run keyed script tools through `wc.js tool run`, which asks the machine to run them with their keys and returns redacted output; key values never appear in the result. Sandboxed Codex cannot use keyed tools; set Codex to unrestricted in Settings to use them.
