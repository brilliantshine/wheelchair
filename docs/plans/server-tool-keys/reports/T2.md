# T2 — server line checker

`machine/lib/server-lines.js` implements the pure reader, bounded detector, replacement and holdback replies. `machine/test/server-lines.test.js` exercises normal, escaped, oversized, budget and large-line cases.

The reader returns `{ wellFormed, members }`, where top-level member names map to `[start, end]` source offsets. Its optional `visit` receives `{ start, end, name, text, top }` for each string, with decoded bytes in `text`; `prefix: true` retains only members whose values have ended.

Measurements on this machine: one 1 MiB unchecked run with 20 long keys took 16 ms and grew heap by 81,328 bytes and array buffers by 1,130,496 bytes; 250 qualifying 4 KiB runs took 70 ms and grew heap by 1,666,984 bytes and array buffers by 8,949,393 bytes. The final test log below records the combined large-case timings. These are process memory deltas after warm-up, not peak resident memory.

The tests were also run against a scratch copy with all public operations deliberately made to throw: all 11 tests failed. This is a coarse mutation check, not a separate targeted mutation for every individual behavior. An earlier deliberately broken JSON fixture failed once and was corrected.

## Choices

- `readLine`: Exposed source ranges as half-open byte offsets and string text as a Buffer; the brief left this shape open.
- `detect`: When both a key and an unchecked run occur, unchecked wins, as permitted by the brief.
