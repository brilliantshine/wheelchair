# R2 report

## Changes

- `machine/lib/server-lines.js`: `ensure()` now starts its closing-quote scan at `start + 1`, after the opening quote. This prevents an escaped leading quote from being mistaken for the end of the string and truncating the decoded buffer.
- `machine/test/server-lines.test.js`: added byte-for-byte decode cases for the four specified strings and a checker regression showing a fully percent-encoded key after an escaped quote is held back with the expected S5 reply and note.

Both new regressions failed before the change and passed after it. Before the change, the decoded `a\\"bcdefghijk` case ended at `a"bc` (bytes 97, 34, 98, 99), and the encoded-key reply was passed through unchanged with a null note.
