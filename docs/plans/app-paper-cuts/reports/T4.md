## Could not do / notes

- A `..` path through a raw HTTP client is normalized away by `fetch` before it reaches the server, so the test sends percent-encoded dots (`..%2F`, `%2e%2e/`), which reach `handleAsset` and 404; the literal `../../node_modules/...` form returns 401 from the router and is asserted only as "not 200".

## Choices

- `viewer/test/pages.spec.js`: added `font-src 'self'` to its hard-coded CSP constant (one token, outside the ownership list) because the header change breaks it otherwise.
- `viewer/server.js`: `font-src 'self'` placed right after `img-src`, so the existing CSP strings in tests changed in one predictable spot.
- `viewer/server.js`: font names are matched by regex plus `Object.hasOwn`, so `__proto__`/`constructor` cannot hit the allowlist.
- `viewer/pages/app.css`: `@font-face` rules placed at the top, before `:root`.
- `viewer/test/app-fonts.spec.js`: loads `/app/threads` and injects probe elements for each family and weight, because faces load lazily and the page may not itself render every weight.
- `viewer/package.json`: description reworded to "Its only runtime dependencies are the two self-hosted font packages."
