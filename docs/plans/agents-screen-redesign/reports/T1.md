# T1 — hub data for Agents

## Changes

- `viewer/app/wc.js`: accepts the optional session title.
- `viewer/app/sessions.js`: persists titles and briefs, hides private start data, and records turn and session timestamps.
- `viewer/app/routes.js`: serves briefs, validates and forwards pane history, records terminal turn starts, and sanitizes session lists.
- `viewer/app/agents.js`: constructs persistent agent trees, titles, waiting and other states, counts, stages, asides and project metadata.
- `viewer/app/views.js`: exports the existing status and needs helpers.
- `viewer/app/API.md`: documents the brief and history routes.
- `viewer/test/app-agents.test.js`, `viewer/test/app-session-meta.test.js`: exercise tree derivation, session metadata, access, timing, and pane forwarding.

## Choices

- `agents.js`: represent absent `waiting_on` as null; the specification names the populated shape but does not specify the empty value.
- `agents.js`: for a cyclic parent chain, attach the affected nodes to the lead so they remain visible.
- `routes.js`: treat an empty stored brief as absent for the brief endpoint and `has_brief`.

## Limitations

The required Node suite failed twice, so the worker gate requires stopping rather than retrying it again. The second invocation started before dependency installation finished; its font server test still saw a 404. It also failed the quiet-turn test `6 message clears debt` (expected 0, got 1) while the browser suite ran concurrently. The first full invocation had only the font failure. The final focused run was made after adding the direct history-forwarding assertion; the full run started before that final test addition and before the last legacy timing fallback edit. Several requested edge cases do not yet have dedicated tests, including every Decision 13 branch, failure/stop timing, and all state/count combinations.
