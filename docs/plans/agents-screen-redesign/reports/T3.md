# T3 report

## Changes

- `viewer/pages/term-view.js`: reusable lifecycle, view-only switch, input queue cancellation, mouse filtering, history polling, viewport preservation and sizing. Exposes `_onDataForTest` for mouse and paste tests. Buffer replacement uses a single clear-screen-and-scrollback write and restores scroll position in its callback.
- `viewer/pages/terminal.html`, `terminal.js`: thin standalone host retaining login and lead lookup.
- `viewer/pages/views.css`: terminal module styling, hidden view-only cursor, amber typing state and responsive keys.
- `viewer/test/app-views.spec.js`, `app-accounts.spec.js`: switch on typing before sending and cover standalone view-only, mouse, paste, history and reload.
- `viewer/test/pages-r3.test.js`: read the semicolon key function from its new module; assertions remain unchanged (boundary extended by the lead).

## Choices

- `term-view.js`: retain the same switch element across retargets so a host does not need to replace its header control.
- `term-view.js`: expose `_onDataForTest` on the handle to exercise mouse reports and queued paste without synthesizing browser-specific xterm events.
- `term-view.js`: use a single clear scrollback/screen write and restore the viewport in its completion callback.

## Limitations

Validation did not pass. `viewer/test/pages-r3.test.js` assumed the moved function remained in terminal.js; the lead authorized updating the source path after the failed runs. The updated test has not been rerun because the Node gate failed twice. Browser suite had a test-server port collision in an unrelated account test. The second Node run also had unrelated quiet/upload failures and hung in server.test.js; it was interrupted after several minutes. The first Node run overlapped dependency installation, causing the font failure. Cursor hiding is implemented in CSS but was not independently visually verified.
