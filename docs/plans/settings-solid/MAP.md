# Settings solid: map

Checked against `672764aeaa4a1170c7cd6d15af0cfb9673ced4e2` (origin/main and worktree HEAD). The follow-up is the four deferred items in `docs/plans/settings-rework/PLAN.md:130-137`.

```text
open AI providers or Usage -> read /usage now and every 30 seconds -> newest answer
  -> replace Usage host if present
  -> replace Accounts host if present and not busy
       -> reattach existing sign-in card inside the new Accounts DOM
```

## Repaint and position

- Category hosts are siblings: AI providers has Harnesses then Accounts; Usage and balancing has Usage, Lead order, Balancing (`viewer/pages/settings.js:11-14`). `paint` invokes a renderer and `replaceChildren` on the named host only, and skips hosts outside the open category (`viewer/pages/settings.js:2472-2482`, `viewer/pages/settings.js:2502-2514`). Each accepted usage answer calls `paint('usage')` and, unless busy, `paint('accounts')`; the 30-second timer and immediate read use the same function, with newest-request-only answers (`viewer/pages/settings.js:1422-1455`). Hidden tabs pause timer ticks and trigger a read on return (`viewer/pages/nav.js:6-14`).
- Accounts is busy for an edit, add form, or a focused input/select/textarea within Accounts; an open sign-in card by itself or a pressed button is not included (`viewer/pages/settings.js:1422-1426`). The sign-in section holds the same textarea, password input and Send code button (`viewer/pages/settings.js:1484-1514`); it is placed in `#signin-host` or a provider's `.prov-signin`, both *inside* the Accounts renderer (`viewer/pages/settings.js:1515-1517`, `viewer/pages/settings.js:1722-1734`). Re-rendering moves the existing card into newly created DOM before the Accounts host is replaced, so node identity is retained but attachment/focus and a press are exposed to that move. The card's own two-second status poll updates its contents separately (`viewer/pages/settings.js:1528-1576`).
- Usage's loading placeholder and provider bars are inside its own replaceable host (`viewer/pages/settings.js:1889-1895`); Lead order buttons live in the next host and are not replaced by a usage answer (`viewer/pages/settings.js:1752-1780`, `viewer/pages/settings.js:1923-1930`). Their position can still shift when the bars change height. Reordering itself repaints Lead order, while a balancing save repaints both editors (`viewer/pages/settings.js:1761-1769`, `viewer/pages/settings.js:1783-1798`).
- `holdPlace` scrolls to hold an on-screen sign-in card below a different repainted host, even if that host is partly visible; otherwise it anchors the next sibling only when the repainted host is wholly above the sticky header and the page is scrolled (`viewer/pages/settings.js:2484-2499`). It does not anchor a card inside the host being replaced or generally anchor a visible Lead order button below partly visible Usage. Account focus suppression is the separate busy check above; category navigation resets scroll (`viewer/pages/settings.js:2559-2575`).

## Phone You

- The Technical terms native select is inside a wide control in a padded Basics row (`viewer/pages/settings.js:1289-1294`, `viewer/pages/settings.js:1323-1338`). The You line and Assistant and project leads title come from category data (`viewer/pages/settings.js:12-16`); category headings use 24px/600 (`viewer/pages/settings.css:14`).
