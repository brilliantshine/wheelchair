Question 5 · waiting on you

When a lane is a full session, how does the lead know it's done?

Every lane now opens a real Claude or Codex session in its own tmux window, so you can step into any thread. A headless codex exec run ended on its own and handed the lead a final message and a thread id. A live session just sits at its prompt, so the lead needs another signal that a part is finished, and somewhere to read the result.

Decided so far

  1. Q1 The app grows out of the existing viewer server rather than replacing it.
  2. Q2 Slash commands keep working in a terminal. The app is a second way in, not the only one.
  3. Q3 One hub holds every project; the app lists repos it has cloned.
  4. Q4 Every session, workers included, is a full Claude or Codex session in its own tmux window. Headless exec and -p are retired.
